2. 데이터 칸(⑤ 대조 확정, 계획 §6.2.1)

  • BodySet
  • BodyFitId·Skeleton·Torso(Leader)·AnimClass
  • Pieces 11개 = Head, Arm_L/R, Hand_L/R, Thigh_L/R, Calf_L/R, Foot_L/R. Torso는 따로 있어 합계 12다.
  • ④ 인계 body_parts.json은 Torso를 포함한 몸 11개이고, Head는 parts_manifest에서 온다.
  • Part
  • SlotId(Underwear·Cloak·TorsoOutfit·Legwear·Gloves·Accessories 6개)·BodyFitId
  • Meshes: 항목마다 PieceId(포함 부위)와 외부 3D 생성 도구. 여러 부위를 합친 외부 3D 생성 도구도 된다.
  • MaterialOverrides: 대상은 (PieceId, 재질 슬롯 이름) 쌍이다. 슬롯 이름은 실제 값 그대로다(예 M_FP_BodySet, M_FP_Underwear, M_FP_Scalp, M_B_8K_fs). 접두어·숫자 순서를 강제하지 않는다.
  • HideBodyParts: 몸 11개 id, Torso 포함. Torso Leader는 외부 3D 생성 도구를 끄지 않고 마스크로만 가린다. 기본 속옷은 빈 값이다.
  • MaskBodyParts: FFPBodyMask(PieceId·MaskTexture·UVChannel·Channel·MaterialParameterName). 실제 자료가 없으면 빈 값이다(v001에는 옷별 가림 정보가 없다).
  • 천: bCloth·PhysicsAsset·CopyPoseAnimClass
  • Look: BodySet·Parts(슬롯마다 하나 이하)
  • 후속 조건부 확장(이번 범위 밖): 소켓용 정적 장신구, HairBundle, LOD profile
  • HairBundle을 고를 때만 두피·끈 기준면·Groom/Binding이 필수가 된다. Scalp·끈 기준면·Hair는 Pieces 11과 별개다.

3. 요청과 상태(계약 3.2절)

  • RequestLook
  • 번호를 올린다. Look이 비었으면 상태 None, 아니면 Loading이다.
  • 완료 콜백은 번호가 최신일 때만 처리한다. 완료 순서가 뒤집혀도 마지막 요청만 쓴다.
  • 완료 처리
  • 자산 없음: None, 일반 로그 한 줄
  • Look 형식이 아니거나 검증 실패: Failed, 경고, GetLastError()(검증 이름 포함)
  • 통과: 교체 계획을 한 호출 안에서 실행 → Applied
  • 어느 경우든 OnApplied(Request, bSuccess)를 방송한다.
  • 실패하면 현재 외형(이전 Look 또는 블록아웃 Body)을 그대로 둔다. 부분 적용은 없다.
  • 시작 외형(RequestInitialLook, 캐릭터 BeginPlay, 소유와 무관): 콘솔 변수 Celestiel.Explore.Look(개발 빌드)을 먼저 본다.
  • 빈 값: VisualLook
  • none: 대소문자 무관, 요청 없음
  • 콘텐츠 경로: 그 Look. /Game/A/B는 /Game/A/B.B로 채운다. 마지막에 FPackageName::IsValidObjectPath로 객체 이름까지 본다(공백 등 금지 문자, '.' 뒤 '/', 끝의 '.'·':'는 형식 아님).
  • 형식이 아닌 값: 경고, 요청 없음
  • 걷기 도구·자동 시험은 소환 전에 none이나 가벼운 Look으로 둔다.

4. 여섯 검증(①→⑥ 순서, 첫 실패만 보고)

검증실패 조건
① 로드빈 필수 참조. BodySet, BodySet의 Skeleton·Torso·AnimClass·Pieces 외부 3D 생성 도구, Part와 그 외부 3D 생성 도구, 재질 덮어쓰기의 재질, 마스크 텍스처, 천 부품의 CopyPoseAnimClass가 대상이다
② Skeleton스킨 외부 3D 생성 도구의 Skeleton이 BodySet 공통 Skeleton과 다름
③ BodyFitIdBodySet이나 부품의 BodyFitId가 비어 있음(서로 같아도), 또는 부품의 BodyFitId가 BodySet과 다름. 특정 판 문자열은 고정하지 않는다
④ 슬롯·부품몸 부품 11개 가운데 없는 것이 있음, Underwear 없음, 알 수 없는 슬롯, 고른 슬롯에 외부 3D 생성 도구 없음, 슬롯 겹침. 나머지 5슬롯은 고르지 않아도 된다. 가림·마스크 id 유효성도 여기서 본다: HideBodyParts·MaskBodyParts의 id는 Torso + 몸 10(Arm·Hand·Thigh·Calf·Foot 좌우)만 되고, Head·Scalp·오타는 적용 전에 거부한다(총괄 결정, 검증 수는 여섯 그대로)
⑤ 재질 슬롯재질 덮어쓰기의 (PieceId, 슬롯 이름)이 그 조각 외부 3D 생성 도구에 없음
⑥ 천천 부품의 조각마다: 렌더 섹션에 연결된 유효한 천이 없음, 연결된 섹션이 쓰는 천 LOD에 고정 영역(최대 거리 가중치가 문턱 아래인 정점)이 없음. 그리고 PhysicsAsset 없음. 한 조각의 천이 다른 조각의 빠진 천을 가리지 않는다
  • 검증은 사실 구조체(FFPLookFacts)를 받는 순수 함수라 에셋 없이 시험한다. 사실은 FPAppearanceFacts::FromLook이 읽은 Look에서 만든다(컴포넌트와 시험이 같은 경로).
  • ⑥의 천 연결(ReadCloth)은 엔진이 천 시뮬레이션을 만드는 조건과 같다: 렌더 섹션의 ClothingData(AssetGuid·AssetLodIndex)가 가리키는 천 자산이 UClothingAssetCommon이고 IsValid()여야 연결로 친다(USkeletalMesh::GetClothingAssetsInUse + IsValid). 고정 영역은 그 섹션이 쓰는 LOD의 MaxDistance 가중치로 본다. ClothingSystemRuntimeCommon의 UClothingAssetCommon::LodData를 읽는다(모듈 의존 추가).

5. 원자적 교체(계획 §3.1·§3.3)

  • 한 호출 안에서 아래 순서로 한다(중간에 프레임이 지나지 않는다).
  1. 준비: 몸 부품·의상 조각 컴포넌트를 떨어진 채 모두 만든다.
  2. Leader: 몸통 외부 3D 생성 도구·AnimClass
  3. follower: 붙이고 Leader Pose. 천 부품은 Leader Pose 대신 Copy Pose를 쓴다.
  4. 재질: (PieceId, 슬롯 이름)
  5. 몸 가림
  6. 천: Copy Pose AnimClass·PhysicsAsset·Leader 뒤 틱 선행조건
  7. 이전 묶음 치움
  8. 블록아웃 Body 숨김
  • 몸 가림은 기본 몸 상태에서 이번 부품들의 HideBodyParts 합집합으로 다시 계산한다. 이전 옷의 가림은 남지 않는다.
  • Torso는 숨김에서 마스크로 바꾼다.
  • 숨긴 부품에는 마스크를 두지 않는다.
  • 부분 가림 마스크 MID는 실제 마스크 자료가 생기면 더한다.
  • 1단계에서는 계획(단계 순서·가림 재계산)을 순수 시험으로 본다. 실제 부품 붙이기는 2단계에서 확인한다.

6. 숨김·복귀·순간이동(계약 3.3~3.5절)

  • 숨김(SetPresentationActive(false)): 액터 숨김은 컨트롤러가 한다. 외형은 Leader bPauseAnims(지금 pose 유지)와 천 SuspendClothingSimulation을 한다.
  • 단계는 순수 계획 FPAppearanceCore::PresentationSteps의 순서로만 실행한다. 실제로 실행한 단계를 차례로 기록한다(GetLastPresentationSteps, 시험·도구용).

| 경우 | 단계 |

|---|---|

| 숨김 | Leader 멈춤 → 천 멈춤 |

| 복귀(순간이동 없음) | Leader 재개 → 천 재개 |

| 복귀(숨긴 채 순간이동) | Leader 재개 → Leader pose 갱신 → 천 부품 pose 갱신 → 천 재개 → 천 리셋 요청(ForceClothNextUpdateTeleportAndReset) |

| 보이는 중 순간이동 | Leader pose 갱신 → 천 부품 pose 갱신 → 천 리셋 |

  • pose 갱신은 TickAnimation(0, false) + RefreshBoneTransforms()다. 틱 함수 없이 부르면 게임 스레드에서 평가를 끝낸다(병렬 평가는 틱 함수가 있을 때만). ACharacter 기본 AlwaysTickPose는 최근 렌더가 없으면 뼈 갱신을 건너뛸 수 있으므로, 순간이동 뒤 리셋 전에 새 자리의 뼈를 직접 계산한다(③ 검토 P2-01). 외부 3D 생성 도구가 없으면 하지 않는다. 천 부품은 Leader 다음에 갱신해 새 pose를 복사한다.
  • API 호출 순서와 다음 틱의 의미는 다르다(③ 재검토 P2-04).
  • API 호출 순서: 엔진 ResumeClothingSimulation은 멈춤을 풀면서 다음 천 갱신 방식을 Teleport로 덮는다(ForceClothNextUpdateTeleport). 그래서 재개를 먼저 부르고 리셋 요청(TeleportAndReset)을 마지막에 불러야 리셋이 남는다. pose 갱신은 두 호출보다 앞이다.
  • 다음 틱의 의미: 천 갱신(UpdateClothSimulationContext)이 남은 방식 TeleportAndReset을 읽어, 갱신된 pose에서 천을 리셋하고 이어서 돈다. 대기 중인 물리 순간이동은 더 강한 방식을 낮추지 않는다.
  • 순간이동 없는 복귀는 재개만 하므로 다음 천 갱신 방식이 Teleport다(관성 없이 이어서, 리셋 아님).
  • 순간이동이 없는 전환은 리셋하지 않는다. 같은 값으로 다시 부르면 아무것도 하지 않는다.
  • 순간이동은 엔진 TeleportSucceeded로 받는다(호출부 변경 없음).
  • 그룸 정지·재개는 HAIR-2 연결 때 더한다(방식은 CU3·CU4에서 고른다). 필드 정지 API는 만들지 않는다.
