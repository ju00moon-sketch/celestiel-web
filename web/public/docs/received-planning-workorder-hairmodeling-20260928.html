CELESTIEL 헤어 모델링 개선 작업지시서 (사용자 전달, 기획 도구 작성)

접수: 2026-09-28 07:0x. 사용자가 앞서 보낸 의견(PLANNING_REVIEW_HairGuide_20260928.md)의 정리본을 md 파일에서 복사해 다시 보냈다("아까 글이 좀 잘린 게 있어서 … 아까 작업 방식이랑 다른 부분 있으면 적용시켜줘"). 첫 붙여넣기는 9절 첫 줄에서 끊겼고, 사용자가 잘린 뒷부분(9절 지시문·완료 기준·10절 참고 문서·최종 방향)을 이어서 보내 합쳤다. 총괄이 앞선 전달과의 차이를 ④·⑤에게 추가 전달했다.

---

목표: 현재 파이썬 생성 방식과 승인된 반묶음 디자인을 보존하면서, 가이드 중심의 국소 편집·재현 가능한 비교를 통해 자연스럽고 부드러운 머릿결을 만든다.

문서 상태: 작업 제안. 실제 groom4_core.py와 .blend 내부 구조를 확인한 뒤 적용한다. 스크린샷의 설명만으로 현재 생성 방식의 문제 원인을 확정하지 않는다.

1. 기본 방향

파이썬을 버리거나 헤어를 전부 다시 만드는 작업이 아니다. 권장 흐름은 다음과 같다.

기존 스크립트로 초안 생성 → 부위별 기준 가이드 저장·편집 → 가이드를 따라 최종 모발 생성 → 모발 굵기·끝 테이퍼·다발 묶임 조절 → 제한적인 잔머리 추가 → 같은 조건에서 비교 렌더 → 작은 다발로 Unreal Groom 전달 검증

핵심은 특정 도구를 사용했다는 사실이 아니라 아래 작업이 안정적으로 가능한지다.

  • 앞머리 일부를 고쳐도 승인된 뒷머리가 바뀌지 않는다.
  • 반묶음 구조를 유지하면서 뒷목 구역만 수정할 수 있다.
  • 모양을 고정하고 모발 굵기·밀도·재질을 각각 비교할 수 있다.
  • 재생성해도 승인된 가이드 수정이 사라지지 않는다.

기존 자체 생성기가 이 기능을 이미 제공한다면 재사용한다. Geometry Nodes로 전면 이관하는 것을 목표로 삼지 않는다.

2. 변경 금지·보존 조건

  • 확정 얼굴을 수정하지 않는다. 얼굴 형상, 이목구비, 머리 크기를 헤어에 맞춰 바꾸지 않는다.
  • 현재 승인된 반묶음 디자인과 흑갈색 계열의 머리색을 유지한다.
  • 윗부분만 뒤에서 모이고, 아래 머리는 풀려 내려오는 반묶음으로 통일한다. 풀린 뒷머리를 묶음 지점으로 끌어올려 전체 포니테일로 바꾸지 않는다.
  • 나침반 장식과 리본의 디자인·위치는 승인된 최신 참고 도면을 따른다.
  • 기존 코드·가이드·작업 파일은 백업한다. 전체 재생성이나 덮어쓰기로 승인된 결과를 잃지 않는다.
  • 형태 결함을 흐림·과한 후처리·어두운 조명으로 가리지 않는다.
  • 헤어 문제를 해결하기 위해 얼굴·목 텍스처를 임의로 덧칠하지 않는다. 텍스처 수정이 필요하면 먼저 원인과 수정 범위를 구분한다.

4. 가이드 중심의 국소 편집 구조

4.1 기준 가이드와 최종 모발 분리

  • 가이드는 머리 다발의 시작 위치, 흐르는 방향, 곡률, 길이와 끝점을 정하는 기준 곡선이다.
  • 승인된 가이드는 안정적인 기준본으로 보존한다.
  • 생성된 최종 모발 수를 바꿔도 기준 가이드의 모양은 유지한다.
  • .blend 안에서도 가이드를 확인·편집할 수 있게 남긴다.
  • 외부 가이드 데이터와 .blend 중 무엇이 기준 원본인지 하나로 명확히 정한다. 양쪽을 따로 수정해 서로 덮어쓰지 않는다.
  • 가이드 변경과 최종 모발의 밀도·굵기·재질 변경을 구분해서 기록한다.
  • 담당자가 마우스로 한 올씩 수정해야 한다는 뜻은 아니다. Python으로 Blender 데이터를 편집하더라도 같은 보존·국소 편집 원칙을 지킨다.

5. 부드러운 머릿결을 위한 조절 순서

5.1 큰 흐름과 곡선의 꺾임

  • 모발 수를 늘리기 전에 가이드가 참고 도면의 형태와 맞는지 확인한다.
  • 머리 다발이 중간에 갑자기 꺾이거나 한 점에 몰리지 않게 한다.
  • 반묶음의 의도된 꼬임·웨이브는 유지한다.
  • 전체 곡선을 일괄적으로 펴서 헤어스타일을 바꾸지 않는다.

5.2 다발 묶임과 개별 모발 굵기 분리

  • 머리 다발의 굵기와 머리카락 한 올의 굵기는 별도로 조절한다.
  • 목표: 멀리서는 정돈된 큰 흐름이 보이고, 가까이서는 가는 모발이 구분된다. 다발을 분리한다고 전체를 잔머리로 덮지 않는다. 부스스함을 줄인다고 모든 가닥을 같은 곡선·같은 끝점에 붙이지 않는다.
  • 큰 다발과 작은 다발의 관계를 부위별로 조절한다.
  • 모발 끝은 자연스럽게 가늘어지되, 끝 전체가 같은 높이에서 끊겨 보이지 않게 한다.
  • 같은 재질과 가닥 수에서 굵기·테이퍼부터 비교한다.

5.3 잔머리

  • 잔머리는 큰 형태와 다발 흐름을 확인한 뒤 필요한 구역에 제한적으로 추가한다.
  • 승인된 실루엣을 흐트러뜨리지 않는다.
  • 이마·귀·뒷목을 무작위 잔가닥으로 덮지 않는다.
  • 같은 시드와 설정을 유지하며 잔머리 변화만 비교할 수 있게 한다.

5.4 재질·조명

  • Blender 비교 렌더는 Cycles + Principled Hair BSDF를 우선 검토한다. 설치 버전의 지원 범위를 확인한다.
  • 원하는 표현: 검은 덩어리 위에 굵은 흰 광택띠가 얹힌 느낌이 아니라, 흑갈색 모발 흐름을 따라 은은한 윤기가 나오는 상태.
  • 비교 원칙: 같은 재질에서 가이드·다발·굵기를 비교한다. 같은 형상에서 색·거칠기·가닥별 재질 변화를 비교한다. 조명·노출·카메라까지 한꺼번에 바꾸지 않는다.
  • 확대해도 가닥이 남고, 전체로 봐도 거칠지 않아야 한다.
  • 블러나 강한 후처리로 결함을 숨긴 결과는 채택하지 않는다.

5.5 사용할 수 있는 Blender 기능

다음은 후보 기능이다. 현재 생성기와 설치 버전에 맞춰 필요한 부분만 사용한다.

6. 뒷목의 '부스스한 띠' 진단

화면 설명만으로 잔머리 밀도가 원인이라고 단정하지 않는다. 아래처럼 표시 요소를 분리해서 원인을 찾는다.

원인 후보진단 방법수정 원칙
기존 머리 조각·머리칠 잔여새 헤어를 잠시 숨긴 상태와 비교새 헤어가 원인인지 기존 자산이 원인인지 먼저 구분
같은 높이에서 끝나는 가닥뒷목 그룹만 켜고 가이드·끝점 분포 확인문제 구역의 길이와 끝점 분포만 조정
구역 경계의 갑작스러운 밀도·길이 변화구역을 구분해 경계 비교전체 밀도를 낮추지 말고 경계의 변화부터 정리
피부 관통·떠 있는 가닥측면·후면에서 뿌리와 경로 확인문제 가닥의 연결·경로를 수정
재질·렌더에 따른 표시 문제형상을 고정한 채 재질·표시 조건을 분리원인을 확인하지 않은 상태에서 텍스처를 덧칠하지 않음

확정 얼굴은 그대로 두고, 확인된 원인만 수정한다.

7. 첫 시험과 비교 방법

시험 범위: 전체 헤어를 재생성하지 않는다. 앞머리와 뒷목 두 구역에서 기존 방식과 개선 방식을 비교한다.

비교 조건:

  • 동일한 얼굴·몸·포즈를 사용한다.
  • 카메라 위치·초점거리·해상도·조명·노출을 고정한다.
  • 형상 비교에서는 같은 재질을 사용한다.
  • 생성형 노이즈와 잔머리는 난수 시드와 설정을 기록한다.
  • 정면·45도·측면·후면과 문제 구역 확대를 함께 남긴다.
  • 각 결과가 어느 작업 파일·가이드 버전·설정에서 나왔는지 연결한다.

통과 기준:

  • 반묶음 구조와 확정 얼굴이 유지된다.
  • 앞머리를 수정해도 무관한 뒷머리가 바뀌지 않는다.
  • 뒷목의 띠처럼 보이는 부분이 원인에 맞게 개선된다.
  • 굵은 튜브·판 같은 다발과 과도한 잔머리가 동시에 정리된다.
  • 재생성해도 승인된 가이드가 보존된다.
  • 같은 조건의 비교에서 개선을 확인할 수 있다.

스크립트가 실행됐거나 렌더가 끝났다는 이유만으로 통과 처리하지 않는다. 실제 출력 이미지를 확인하고 남은 문제를 기록한다.

8. 담당 분리와 Unreal 전달

모델링 담당:

  • 가이드·생성 구조·부위별 흐름·형태를 수정한다.
  • 기준 작업 파일과 필요한 설정을 저장한다.
  • 렌더 요청서에 비교 목적, 변경 구역, 고정 조건을 명시한다.

렌더·테크니컬 아트 담당:

  • 전달받은 기준 버전의 복사본에서 비교 렌더와 재질 테스트를 진행한다.
  • 요청하지 않은 얼굴·체형·헤어 형태 변경을 하지 않는다.
  • 출력 파일과 사용 설정을 모델링 담당에게 전달한다.

두 담당자가 같은 원본을 동시에 수정하지 않는다.

Unreal Groom 선행 시험:

  • 전체 헤어를 고밀도로 확장하기 전에 작은 다발로 시험한다.
  • Unreal이 요구하는 Alembic Groom 규격과 필요한 속성을 확인한다.
  • 파일 생성 여부가 아니라 실제 임포트 성공과 가닥 형상을 확인한다.
  • 스케일·모발 굵기·두피 바인딩·움직임을 점검한다.
  • Blender 재질의 표현이 Unreal에 그대로 옮겨졌다고 가정하지 않는다.
  • 근접 카메라와 실제 게임 화면에서 각각 확인한다.

  • 부위별 그룹, 두피 연결, Blender 데이터 타입을 실제 파일에서 확인해줘.
  • 이미 필요한 기능이 있으면 재사용하고, 없는 부분만 보완해줘.
  • Geometry Nodes로 전면 이관하는 것을 목표로 삼지 마.
  1. 기준 원본과 승인된 편집 보존
  • 기존 코드와 작업 파일을 백업해줘.
  • 승인된 가이드와 최종 모발 생성 설정을 분리해줘.
  • 가이드는 .blend 안에서도 확인·편집 가능하게 남겨줘.
  • 외부 데이터와 .blend 중 기준 원본을 명확히 정해줘.
  • 재생성으로 승인된 수정이 사라지거나 무관한 구역이 바뀌면 안 돼.
  1. 반묶음과 부위별 제어
  • 앞머리, 얼굴 옆 가닥, 윗머리, X자 반묶음 연결부, 풀린 뒷머리, 뒷목을 독립적으로 조절해줘.
  • 윗부분만 모이고 아래 머리는 풀려 내려오는 반묶음을 유지해줘.
  • 전체 포니테일로 바꾸지 마.
  • 얼굴·머리 크기·의상·장식 디자인은 임의로 바꾸지 마.
  1. 머릿결 조정 순서
  • 가이드 흐름 → 다발 묶임 → 개별 모발 굵기와 끝 테이퍼 → 제한적인 잔머리 → 재질 순서로 점검해줘.
  • 모발 수와 잔머리부터 늘리지 마.
  • 굵은 다발을 잔머리로 덮거나 블러로 부드러워 보이게 하지 마.
  • 멀리서는 정돈된 흐름, 가까이서는 가는 모발이 보이는 것이 목표야.
  1. 현재 뒷목 문제
  • 새 헤어를 숨긴 비교와 뒷목 그룹만 켠 비교로 원인을 확인해줘.
  • 기존 머리 잔여물, 동일 높이의 가닥 끝, 부위 경계의 밀도·길이 변화, 피부 관통·뜸, 재질 표시 문제를 구분해줘.
  • 확인한 원인만 수정하고, 얼굴·목 텍스처를 임의로 덧칠하지 마.
  1. 첫 시험
  • 전체를 다시 만들지 말고 앞머리와 뒷목 구역부터 시험해줘.
  • 같은 얼굴·카메라·조명·재질·난수 시드에서 전후를 비교해줘.
  • 정면·45도·측면·후면과 문제 구역 확대를 남겨줘.
  • 좋아진 방법만 나머지 헤어에 확대 적용해줘.
  1. 렌더와 전달
  • Blender 비교는 설치 버전을 확인한 뒤 Cycles + Principled Hair BSDF를 우선 검토해줘.
  • 형상 비교와 재질 비교를 분리해줘.
  • 모델링 담당은 가이드·형태·설정을 저장하고, 렌더 담당은 전달받은 버전으로 출력과 검수를 진행해줘.
  • 같은 원본을 동시에 수정하지 마.
  • 전체 고밀도 확장 전에 작은 다발로 Unreal Groom 전달을 검증해줘.

완료 기준: 실행 성공이나 렌더 완료가 아니라, 같은 조건에서 확인되는 시각적 개선, 승인된 형태의 보존, 국소 편집 가능성, 재생성 재현성, 엔진 전달 결과로 판단해줘. 확인하지 않은 항목은 미검증으로 표시하고, 실제 원인과 남은 문제를 보고해줘.
