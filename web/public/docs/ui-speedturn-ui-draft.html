U1. 타임라인 띠·차례 배너·가장자리 색(TURNFEEL-1 초안을 바꾼 안)

  • 타임라인 띠(새 파일 UI/Slate/SBattleTimeline.h/.cpp): 보스 막대 자리(위 가운데)에 다음 10차례의 아이콘을 왼쪽부터 차례 순서로 늘어놓는다.
  • 지금 차례: 맨 왼쪽, 크게(80px), 밝은 테두리
  • 아군: 팀 색 테두리 + 얼굴(대역은 이니셜 A~E)
  • 적: 붉은 테두리 + 적 표식·번호, 보스는 굵은 테두리
  • 같은 인물이 여러 번 나오면 그대로 여러 칸을 둔다.
  • 재정렬: 예측 순서가 바뀌면(경직·둔화·가속·처치) 각 아이콘이 새 칸으로 0.3초 미끄러진다. 새 칸은 나타나고, 빠진 칸은 흐려지며 사라진다.
  • 칸 짝은 (누구, 몇 번째 등장)으로 맞춘다.
  • 차례 배너(새 파일 UI/Slate/SBattleTurnBanner.h/.cpp): 편이 바뀔 때만 가운데에 '아군 차례'·'적 차례'를 0.8초 띄운다.
  • 같은 편이 이어지면 배너 없이 타임라인 강조와 행동 인물 이름표만 바뀐다(자주 떠서 거슬리지 않게).
  • 가장자리 색: 차례 편에 따라 테두리 비네트(적 = 붉은색, 아군 = 푸른색, 알파 0.2, 0.3초 전환)를 둔다. 결과·일시정지 창 동안은 없다.
  • 없어지는 것
  • 라운드 머리글, 계획/실행 턴 순서 열(SBattleFrame MakeOrder, SBattlePlanScreen MakeOrderColumn), 라운드 결과 창의 라운드 단위 표시
  • 최소 HUD의 '실행 비트' 구분(UI/BattleUIController.h IsMinimalHud)은 차례 단계로 다시 정한다.

U2. 아군 차례 즉시 실행 화면(계획 패널 없음)

  • 흐름(한 인물): 차례 시작(카메라 스윙은 ②-A) → ① 이동(선택) → ② 행동 → ③ 대상 → ④ 확인 → 실행
  • ① 이동: 바닥 누르기·끌기, 방향키. 이동 원·경로·가림은 지금 전장 층을 쓴다.
  • ② 행동: 스킬 바 누르기 또는 1~4 키
  • ③ 대상: 적 누르기 또는 Tab 순환. 사거리·시야 안 대상이 먼저 돌고, 밖은 흐리게 두되 고를 수는 있다.
  • ④ 확인: Enter·Space 또는 [실행] 단추
  • 실행 뒤에는 조작을 받지 않고 결과 숫자만 뜬다.
  • Esc·오른쪽 누르기는 한 단계 뒤로 간다. 확인 전까지는 전술 미리보기가 계속 갱신된다: 사거리·시야 선, 구역(정면·측면·배후), 예상 피해·경직 더함, 다음 적 차례의 예고 범위(있으면).
  • 화면 구성
  • 둠: 지금 인물 카드(C7 자리), 스킬 바(C8), 전장 층(한 인물만)
  • 뺌: 명령 대기열(C9), [모두 대기로]·계획 확정 → [실행]·[대기] 두 단추
  • 대기: 이번 차례를 넘긴다. 게이지 처리는 ②-A 규칙을 따른다.
  • 파일
  • UI/BattlePlanScreen.h/.cpp → 한 인물 명령 상태(단계·이동·행동·대상)로 줄인다. 이름은 CommandScreen으로 바꾸는 것을 검토한다.
  • UI/Slate/SBattlePlanScreen.*, UI/BattlePlanDraft.*(한 인물), UI/Slate/SBattleFieldLayer.cpp(적 누르기), UI/BattleFieldElements.cpp(대상 표시·사거리 선 적마다)

U3. 적별 머리 위 막대·대상 선택·결과 줄

  • 머리 위 막대(새 파일 UI/Slate/SBattleEnemyBars.h/.cpp, 숫자 층과 같은 투영)
  • 적마다 이름표(예 '적 1'), 체력 막대(96×8px, 보스 160×10px), 그 밑 경직 칸
  • 기준점은 진행자의 적 머리 위치이고, 위쪽 UI 아래로 눌러 둔다(지금 머리 위 글 제한과 같은 규칙).
  • 화면 밖이면 가장자리 화살표로 보인다.
  • 고른 대상은 괄호 테두리를 두르고 바닥 고리를 둔다. 쓰러진 적은 막대를 흐리게 한 뒤 치운다.
  • 보스 막대(SBattleFrame MakeBossBar, BossRegion)는 없앤다. 보스는 머리 위 큰 막대와 핵 표시로 보이고, 타임라인에서 굵은 테두리로 구분한다.
  • 대상 선택
  • 누르기: 적 몸 반지름(최소 18px) 안
  • Tab·Shift+Tab: 적 번호 순이되 사거리·시야 안이 먼저
  • 고른 대상은 차례가 바뀌어도 살아 있으면 기억한다.
  • 결과 줄: 라운드 결과 창(UI/Slate/SBattleResultScreen.*·UI/BattleUIText SummaryGroups)을 '행동 결과'로 바꾼다.
  • 차례마다 한 묶음: 행동 인물 → 적별 줄(적 2: 피해 24·경직 +1·쓰러짐), 적 차례면 인물별 줄(지금 형식)
  • 화면 왼쪽 아래에 최근 5줄 기록 띠를 두고, 창은 띄우지 않는다.
  • 숫자 기준점(UI/BattleUIRoot.cpp OnAnchor: 인물 아니면 보스)은 적 id를 받는다.

U5. ②-A 계약에서 UI가 받을 조회·알림(제안)

  • 조회
  • PredictTimeline(Count): 다음 Count차례의 (누구: 인물|적 id, 몇 번째 등장, 남은 틱). 속도 변화를 반영하고 결정적이어야 한다.
  • GetGauges(): 게이지 채움 표시용
  • GetEnemyRoster(): id·종류·표시 이름·최대 체력·몸 반지름·보스 여부
  • GetEnemyState(id): 체력·경직·위치·방향·쓰러짐
  • QueryCommand(actor, move, skill, target): 지금 전술 미리보기의 한 인물판(사거리·시야·구역·피해·경직). 계획 전체 미리보기를 대신한다.
  • ValidTargets(actor, skill): 사거리·시야 안 대상
  • SubmitCommand(actor, move, skill, target): 받음 또는 거부와 이유
  • 진행자 GetDisplayAnchor(적 id)
  • 알림·사건
  • TURN_START(who)·TURN_END(who)
  • TIMELINE(바뀐 예측, 속도 변화·처치 때)
  • SPEED_CHANGE(who, 이전, 이후)
  • INTENT·AREA·ATTACK_START…END에 적 id
  • ENEMY_MOVE(id, from, to, 경로): 보스 이동 포함
  • ENEMY_DAMAGE·STAGGER·ENEMY_DOWN(id)
  • VICTORY·DEFEAT·ESCAPE
  • 튜토리얼 알림의 라운드 → 차례 번호
  • 표시 로그 원본 키는 '시도.라운드.순번' → '시도.차례.순번'으로 바뀐다(관찰 도구 ③).
