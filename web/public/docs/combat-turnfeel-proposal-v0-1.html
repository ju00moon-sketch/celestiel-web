전투 '차례 느낌'·카메라·다수 적 일반 전투 — 총괄 기획안 v0.1 (사용자 결정용)

2026-09-28, 총괄 작성. 사용자 지시(원문): "전투할 때 지금 약간 턴 개념이 없는 느낌이야 걍 내 턴 니 턴 이런 느낌. 카메라 무빙도 좀 역동적으로 넣어줬으면 좋겠어. 그리고 보스전 말고 이제 일반적으로는 몬스터들 다수를 상대하는 형식이 일반 전투일 텐데 이런 것도 고려해야 해."

이 문서는 결정이 아니라 선택지다. 사용자가 고르면 구현한다.

0. 지금 전투가 이렇게 느껴지는 이유

  • 지금 라운드 = 계획 제출 → 실행(아군 선행 행동 → 적 공격 → 대응 박자 → 아군 후행 행동). 실행이 한 흐름으로 이어지고, 전술 모드 실행 중에는 최소 HUD가 턴 순서 띠를 숨겨 누구 차례인지 화면에 없다(②-B 조사: UI/BattleUIController.h IsMinimalHud). 행동 이름 배너는 아군 행동에만 뜬다.
  • 카메라는 구도 몇 개(계획 조망·대응·행동)만 있고, 차례가 바뀔 때 움직이지 않는다.
  • 적은 보스 1명(+핵) 전제로 규칙·UI가 짜여 있다(적 id 없이 "boss" 문자열, 대상은 항상 보스, 보스 막대 하나, 예고 범위 하나).

1. 결정 A — '내 턴·네 턴'을 어떻게 만들까

안내용바뀌는 것규모
A1 연출로 차례 표시(추천, 먼저)규칙은 그대로 두고, 실행 중에 '아군 차례'·'적 차례' 배너, 얇은 행동 순서 띠(지금 칸 강조, 적 칸 붉게), 차례별 화면 테두리 색(아군 푸름·적 붉음), 차례 전환 카메라(결정 B)를 넣는다UI(②-B)·카메라(②-A)만. 계약·기록 불변작음(2~3일)
A2 진영 교대 턴아군 전원 행동 → 적 전원 행동으로 라운드를 두 턴으로 나눈다. 적 턴에는 지금의 대응 박자(막기·회피)를 그대로 쓴다. 아군 턴은 한 명씩 고르고 바로 실행(계획 제출은 없앰 또는 선택)규칙·계약·기록·UI·튜토리얼 안내 모두. 반응형 대응은 유지큼(2~3주, 튜토리얼 재검증)
A3 개별 속도 타임라인인물·적마다 속도로 차례가 오는 타임라인(전형적 JRPG). 차례마다 한 명이 행동A2보다 더 큼. 전술(위치·구역) 규칙과 결합 설계 필요매우 큼

총괄 의견: A1을 지금 바로 하면 '차례가 보이는' 효과는 대부분 난다. 그래도 "한꺼번에 흐르는" 느낌이 남으면 A2로 간다. A2를 택하면 CP-T4에서 수용한 계획-실행 구조를 바꾸는 것이므로, A1 결과를 패키지로 보신 뒤 정하는 것을 권한다.

2. 결정 B — 카메라 무빙 (②-A 연출, 규칙 불변)

권장 세트(전부 넣고 강도는 패키지에서 조정):

  1. 차례 전환: 아군 차례 시작 때 아군 쪽에서 적을 보는 낮은 앵글로 스윙, 적 차례 시작 때 적 뒤에서 아군을 보는 앵글로 스윙(0.4~0.6초).
  2. 행동 추적: 행동하는 인물을 어깨 뒤에서 따라가다 타격 순간 살짝 줌인. 돌진은 옆에서 따라감(지금 돌진 캡처 구도 활용).
  3. 적 공격 예고: 대응 박자 직전에 적 클로즈업 → 박자 줄로 전환. 막기 성공 때 짧은 흔들림, 실패 때 카메라 낙하감.
  4. 결정타·경직 파괴: 0.3초 느리게(슬로 모션) + 줌.
  5. 라운드 끝: 조망으로 복귀.

제약: 인물 가림 회피(이미 구현) 유지, 튜토리얼 안내 텍스트가 카메라와 겹치지 않게, 자동 재실행 기록(바이트 일치)은 카메라와 무관하게 유지.

3. 결정 C — 일반 전투(몬스터 다수)를 어떻게 만들까

지금 보스 1명 전제라 '다수 적'은 규칙 계층부터 바뀐다(②-B 조사 요지: UI 18파일 101곳이 Boss 전제이나 비용 대부분은 규칙·계약 쪽).

항목제안
적 모델적 id 체계(적 N명, 각자 체력·경직·구역·예고 범위). 보스전은 '적 1명이 큰 몸집'인 특수 경우로 통일
대상 선택계획 화면에서 적을 고름(누르기·Tab 순환), 사거리 선은 적마다
예고·대응적마다 공격 예고 범위(번호·색 구분). 대응 박자는 적 공격을 순서대로 이어 붙임(적 이름 표시). 범위가 겹칠 때 판독성이 제일 큰 설계 문제 → 한 라운드에 공격하는 적 수 상한(예 2~3)
화면위쪽 보스 막대 → 적 목록 띠 또는 머리 위 체력·경직 막대. 순서 열에 적 칸 여러 개. 결과 요약에 적별 줄(준 피해·쓰러짐)
조우필드 트리거마다 적 구성 데이터(⑥ 배치, ②-B 연결). 탐험에 몬스터 무리가 보이게 하려면 진입 때 숨김·처치 상태 유지(②-A·⑥)
패배·도주지금은 승리만 처리. 일반 전투가 잦아지면 패배(재도전/복귀)와 도주 규칙이 필요 → 사용자 결정
밸런스적 종류별 수치는 사용자 기획(기획 도구)에서 받는다. 개발팀은 시험용 임시 적 2~3종만 둔다

규모: 규칙·계약·UI·조우 연결까지 2~3주(②-A·②-B 병행, ③ 검증 포함). A2를 함께 하면 규칙 변경을 한 번에 묶는 편이 낫다.

4. 순서 제안

  1. 지금: A1 + B(차례 배너·순서 띠·테두리·카메라 세트) → 튜토리얼 포함 패키지로 확인.
  2. 다음: C(다수 적) 규칙·계약 설계서 → 사용자 확인 → 구현. 시험용 적 2~3종은 블록아웃 대역.
  3. 그 뒤: A1 결과가 부족하면 A2(진영 교대)로 규칙 변경. C와 묶어 진행.

5. 사용자 결정 요청

  • A: A1 먼저 / A2 바로 / A3
  • B: 권장 세트 그대로 / 뺄 항목 지정
  • C: 위 제안대로 설계서 진행 / 조우 방식·패배·도주에 대한 의견
