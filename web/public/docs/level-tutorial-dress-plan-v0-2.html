1. 요약

  • 튜토리얼은 그림 그대로 캄포 비에호 마을에서 한다. 플레이어는 남쪽 흙길 입구에서 그림의 시점으로 마을을 보며 시작한다.
  • 흐름(제안 A)
  1. 시작(그림 시점)
  2. 입구 팻말 살펴보기
  3. 광장 우물 살펴보기
  4. 예배당 문 앞 살펴보기
  5. 마을 서쪽 숲 가장자리 공터에서 전투. L_BattleTest 규격 그대로다.
  6. 숲길(사냥터 쪽) 출구. 다음 목적지가 없으므로 임시 처리한다.
  • 걷는 거리는 약 140m, 500cm/s로 약 28초다. v0.1은 158m였다.
  • 맵은 캄포 비에호 맵 하나를 튜토리얼 겸 마을 맵으로 쓰기를 권한다(5장).

2.1 시작 시점

  • 그림 카메라는 입구 길에서 3.0m 높이, 피치 −2.7°, 수평 화각 70°다(LVL-02 KV_Concept).
  • 템플릿 3인칭 카메라는 캡슐 중심(바닥 위 96)에서 뒤로 400이다. 그래서 높이와 피치를 함께 맞출 수 없다.
  • 3.0m 높이가 되려면 피치가 −31°여야 한다. 그러면 광장·예배당이 화면 위로 잘린다(LVL-02 −25° 캡처와 같은 문제).
  • 제안(코드 변경 없음): 구도를 맞추는 쪽을 택한다.
  • Pawn_Tutorial StartPitch를 −6~−10°(카메라 높이 약 1.4~1.7m)로 두고, 첫 캡처에서 그림 기준점 11개와 맞춰 정한다.
  • 지금 튜토리얼 값은 −15°다.
  • 카메라가 그림보다 낮다. 그래서 앞 울타리·텃밭이 더 크게 보이고, 광장 바닥이 덜 보일 수 있다.
  • 대안(②-B 작은 기능): 시작할 때 KV_Concept 고정 카메라로 2~3초 그림 그대로 보여 주고, 플레이 카메라로 넘어간다.

2.2 살펴보기

  • 세 곳 모두 강제하지 않는다(v0.1과 같다). 시작 화면이 광장·예배당을 가운데에 두므로, 대부분 2 → 3 → 4 순서로 걷게 된다.
  • 반경은 모델이 들어온 뒤 캡슐이 대상과 겹치지 않는 값으로 다시 잰다(v0.2 방식, 0.6 × 반경 자리 점검).
  • 문구는 임시 문구다. 창에 '임시 문구'를 함께 보인다. 글자·문양은 쓰지 않는다(Q9).

2.4 출구 임시 처리(선택지)

안내용필요한 것비고
(1) 끝 화면(권장)출구에 들어가면 0.3초 페이드 뒤 '튜토리얼 끝(임시)' 창. 확인하면 시작 자리로 돌아가거나 끝낸다②-B: ExitVolume의 끝 화면 동작(작은 기능)패키지 시험에서 끝이 분명하다
(2) 같은 맵 광장 복귀ExitVolume 목표 = 같은 맵, 도착 태그 = 광장 PlayerStart코드 없음(태그만)맵을 다시 읽으면 전투 볼륨이 다시 켜진다. 상태를 남기려면 ②-B 작업이 필요하다
(3) 표시만출구는 막힘(경계 벽). 이긴 뒤 숲길 끝에서 멈춘다없음끝났다는 신호가 없다

2.5 순서와 대안 B

  • 지켜지는 순서
  • 전투를 거쳐야 출구에 닿는다. 전투 시작 볼륨이 서쪽 구역 전체를 덮기 때문이다.
  • 마을을 먼저 들르는 것은 강제하지 않는다. 숲길이 입구 팻말 옆에서 갈라지기 때문이다(그림의 'To the Forest' 자리).
  • 강제하려면 방법이 두 가지다.
  • ②-B: 전투 시작 볼륨을 EXM_3를 본 뒤에 켜는 작은 기능
  • 배치: 숲길 입구를 가축 우리 뒤로 옮기고, 입구 길 서쪽을 막는다. 걷기 경로를 다시 짜야 한다
  • 대안 B: 밭 가장자리 전투 → 넓은 세상 출구
  • 공터는 북서 'Farmer's Fields' 비탈 아래다. 지금 경사 경계인 곳을 평평하게 바꾸고, 북쪽 경계를 넓힌다.
  • 출구는 EX_NE다. 그림의 문구 'A wider world awaits'와 이어진다.
  • 보스 뒤가 햇빛 받은 밭 비탈이 된다. 판독은 D5에서 확인해야 한다.
  • 넓은 세상 길은 광장에서 바로 이어진다. 그래서 전투 전에 출구에 닿지 않게 하려면 ②-B 기능이 필요하다(출구를 이긴 뒤에 켬).
  • 해 관계 135°를 지키면 보스는 늘 공터의 서남서에 선다. 그래서 마을 동쪽·북동쪽 공터는 보스 뒤가 마을 집들이 되어 맞지 않는다.

6.1 사용자가 할 일(단계별)

  1. 웹 브라우저로 http(내부 경로) 에 들어가 오른쪽 위 '로그인'을 누르고, 에픽게임즈 계정으로 로그인한다.
  2. 위 표의 링크를 하나씩 연다. 오른쪽 가격이 '무료'인지 확인하고 '내 라이브러리에 추가'를 누른다.
  • 라이선스 선택 창이 나오면 Standard를 고르고, 내용을 읽은 뒤 직접 동의한다.
  1. 끝나면 총괄에게 "Fab 추가 끝"이라고 알려 준다. 여기부터는 에디터를 쓰므로, 팀의 무거운 작업이 없는 때를 총괄이 정한다.
  2. Megaplants와 Medieval Game Environment처럼 언리얼 형식인 항목
  • 에픽게임즈 런처 → 언리얼 엔진 → 라이브러리 → Fab 라이브러리에서 항목을 찾는다.
  • '프로젝트에 추가' → Celestiel(5.8)을 고른다.
  • Medieval Game Environment는 완성 프로젝트라 '프로젝트 만들기'만 나온다. 이것은 팀이 따로 처리하므로 추가하지 않고 알려만 준다.
  1. Megascans 표면·풀·바위처럼 언리얼 형식이 아닌 항목
  • 각 페이지의 '다운로드'에서 가장 높은 해상도를 고른다.
  • 받은 zip을 (내부 경로) 폴더에 그대로 둔다.
  • 가져오기·재질·배치는 팀이 한다.
  1. 무엇을 추가했는지 목록을 알려 준다. 받은 폴더를 보여 줘도 된다.

7. 에셋 조건 메모

  • Megaplants(무료, UE 5.7~5.8)
  • Procedural Vegetation Editor 플러그인과 'Nanite Foliage(실험)'가 필요하다.

  • 플러그인 켜기는 프로젝트 설정 변경이므로 총괄 승인 뒤 한다. 켠 뒤 패키지 시험을 먼저 한다.
  • Megascans 무료 항목은 언리얼 패키지가 아니다. 텍스처 세트나 fbx/gltf 원본 zip이다.
  • 그래서 가져오기 스크립트가 필요하다(⑤ 도구 방식: 원본 해상도 유지, Nanite 켬, 재질 인스턴스).
  • 'Megascans Trees … (Early Access)' 묶음은 언리얼 형식이지만 UE 5.1~5.6 전용이다. 5.8 프로젝트에는 바로 넣지 않는다.
  • Medieval Game Environment는 완성 프로젝트(UE 4.26~4.27·5.3)다.
  • 쓰려면 복사본을 5.8로 변환한 뒤 필요한 에셋만 옮긴다(migrate).
  • 그림과 맞는지 먼저 캡처로 본다.
  • 품질: 텍스처 해상도·삼각형 수는 자원 때문에 낮추지 않는다. 메모리가 모자라면 나눠 처리한다.

9. 결정이 필요한 것

  1. 흐름: 제안 A(숲 가장자리 전투 → 숲길 출구, 코드 추가 없음) 또는 대안 B(밭 가장자리 전투 → 넓은 세상 출구, 비탈 평탄화와 ②-B 출구 잠금 필요)
  2. 출구 임시 처리: (1) 끝 화면(권장, ②-B 작은 기능), (2) 같은 맵 광장 복귀, (3) 표시만
  3. 맵: 가 안(캄포 비에호 맵 하나, 권장) 또는 나 안(튜토리얼 맵 다시 만들기)
  4. 시작 시점: 피치만 맞춤(기본, 코드 없음) 또는 시작 연출 카메라(②-B)
  5. 살펴보기 셋째: 예배당 문 앞(제안) 또는 노점
  6. 마을 먼저 들르기 강제: 강제 안 함(제안, v0.1과 같음), ②-B 기능, 또는 숲길 입구 옮기기
  7. Fab 유료·외부 3D 생성 도구로 채울 것: 해바라기·노란 들꽃, 사이프러스, 채소, 건물류
