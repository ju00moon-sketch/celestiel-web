3. 검토 결과 — 모순·누락·구현 위험

#등급내용영향보완 제안
F1높음T01의 대상 선정 규칙이 없다. P09는 AI·확률을 빼고 고정 순서로 반복한다고만 한다. 기본 방어가 자기만 보호하고(P02) 도발·대상 변경도 없으므로, 06장의 대표 작전(A 충격 방어 → B → C → D)은 T01이 A를 칠 때만 성립한다.대상 규칙에 따라 릴레이가 매번 되거나 거의 안 된다. 시험 A/B 결과가 규칙에 좌우된다.R1: "T01은 현재 체력이 가장 높은 생존자를 노린다(동률은 A→E 순)". 의도 공개 때 표시하므로 숨은 규칙이 아니다. A를 회복해 두면 A가 계속 표적이 되는 결정이 생긴다.
F2중간P01 예시와 P02 규칙 충돌. P01 대응 예시의 "피해 직전 가로막기"는 대상 변경인데, P02는 최소 버전에서 대상 변경을 뺀다.구현자가 가로막기를 넣을지 판단해야 한다.R10: 시제품에서 가로막기는 빼고 P01 예시를 "자기 방어"로 고친다.
F3중간방해 수치가 임계치에 못 미칠 때의 처리, 누적의 지속 여부가 없다.방해 스킬의 가치와 UI 표시가 정해지지 않는다.R2: 방해는 선행에서만 누적하고, 선행이 끝났을 때 합계가 임계치 이상이면 예고 행동을 취소한다. 미달이면 효과 없음(비용은 소비). 라운드마다 0으로 초기화. 결정론이라 계획 화면에서 달성 여부를 미리 보여준다.
F4중간연계 효과의 '강화 정도'가 정의되지 않았다. B는 충격 유무에 따라 "강화된 번개/기본 번개"를 만들고, C는 "강화 조건을 만족하면" 전하를 남긴다.효과에 등급이 있는지, C의 조건이 무엇인지 구현자가 추측하게 된다.R3: 연계 효과는 유형과 위력(정수)을 가진다. B의 번개는 충격 소비 시 위력 2, 아니면 1. C는 번개를 소비하면(위력 무관) 전하를 남기고 피해는 위력에 비례한다.
F5중간연결 지정 방식이 두 가지로 읽힌다. "출력 하나는 수신 행동 하나만 예약"(명시적 연결)과 "C에게 번개를 만든다"(대상 지정)가 섞여 있다.편집 UI와 검증 규칙이 달라진다.R4: 모든 연계는 명시적 연결(생산 행동 → 소비 행동)로 지정한다. 아군에게 거는 효과(번개)는 그 아군의 행동만 소비할 수 있다.
F6중간보호막·감소·표식의 지속 시간과 전투불능 회복 여부가 없다.라운드 종료 처리와 치유 대상 검증이 정해지지 않는다.R5: 보호막·피해 감소는 라운드 종료 시 사라진다. 전투불능은 그 전투 동안 회복 불가이고 치유 대상이 될 수 없다.
F7낮음승패 판정 시점과 동시 전멸. 시제품 규칙에서는 보스와 파티가 같은 사건에서 동시에 쓰러질 수 없다.무승부 처리를 따로 만들 필요가 없다.R6: 사건 하나를 처리할 때마다 승리→패배 순으로 판정하고, 결과가 나면 남은 명령을 취소한다. 무승부 규칙은 만들지 않는다.
F8낮음"대기"의 효과, 계산의 반올림 규칙이 없다.결정성(QA01)과 미리보기 일치(QA07)에 영향.R7·R8: 대기는 효과·비용 없음. 모든 수치는 정수, 비율 계산은 내림, 순서는 기본 피해 → 약점 배율 → 감소 → 보호막 → 체력.
F9설계 확인결정론 + 전체 미리보기면 매 라운드가 결과를 정확히 아는 퍼즐이 된다. P10 최소 버전이 이미 "라운드 종료 상태"까지 보여준다.재미의 성격이 정해진다. 조건부 결과 표시(P05)와 긴장이 겹칠 수 있다.R9: 시제품은 전체 미리보기(실제와 같은 계산)로 간다. 미리보기가 사고를 대신해 버리는지는 M4에서 관찰 항목으로 본다.
F10위험명령 편집 UI가 가장 큰 작업이다. 3구간·순서·대상·연결·검증·미리보기를 5인 동시에 다룬다.M2 일정과 품질을 좌우한다.규칙 계산(M1)을 UI 없이 먼저 끝내고, UI는 텍스트·클릭 목록 위주로 시작한다(드래그 없음, P10과 같음). 계획 상태는 위젯이 아니라 전투 모델에 둔다(QA07의 "새로고침해도 계획 유지").
F11위험결정론 구현 위험. 부동소수점, 순서가 보장되지 않는 컨테이너 순회, 엔진 난수·프레임 시간이 결과에 섞이면 QA01이 깨진다.재현 불가 버그.규칙 코어는 정수만 쓰고, 순서가 정해진 배열만 순회하며, 연출·시간과 분리한다. 같은 입력의 로그가 같은지 자동 테스트로 확인한다.
F12위험CELESTIEL 보스 규칙과 일반 규칙의 충돌. 원전의 미카엘은 "예고는 반드시 적중, 무적기 무효, 대상 인계만 가능"이고 가브리엘은 "최근 행동 삭제"다. 시제품의 방해·약점 규칙을 모든 보스의 공통 전제로 굳히면 나중에 막힌다.후속 보스 구현 비용.'방해 가능 여부'를 패턴 데이터의 속성으로 둔다(T01·T02는 가능). 대상은 사건마다 명시적으로 바뀔 수 있는 값으로, 상태는 사건 로그로 되돌릴 수 있게 설계만 해 두고 기능은 만들지 않는다.
F13참고원전 최종전(옴팔로스)은 4인 파티 5개(20인)로 구성된다. 다른 콘텐츠의 파티 인원은 원전 콘텐츠 편에 명시돼 있지 않다.D01 판단 자료.합의(4~5인)와 충돌은 아니다. 시제품 5인은 연계 조합을 넓게 보려는 선택이다.

4. P 규칙별 제안

P처리요지
P01수정 유지흐름·결정론·속도 스탯/확률/실시간 입력 제외는 유지. 대응 예시의 "가로막기" 삭제(F2).
P02유지처리 순서(대상 확정 → 피해 직전 대응 → 피해·보호막·체력 → 전투불능 → 생존자 피해 직후 효과) 그대로.

P07보완 유지임계치 미달·누적 초기화 규칙 추가(F3).
P08보완 유지지속 시간·전투불능·승패 시점 추가(F6·F7).

5. 구현 전 승인할 규칙(총괄 보완안)

  • R1 T01 대상 = 현재 체력이 가장 높은 생존자(동률은 A→E 순). 의도 공개 때 확정·표시.
  • R2 방해는 선행에서만 누적. 선행 종료 시 합계 ≥ 임계치면 예고 행동 취소(그 행동의 대응 발동·약점도 없음). 미달이면 효과 없음. 라운드마다 초기화.
  • R3 연계 효과 = 유형 + 위력(정수). 같은 라운드에서만 유효.
  • R4 연계는 명시적 연결로만 지정. 아군 대상 효과는 그 아군의 행동만 소비.
  • R5 보호막·피해 감소는 라운드 종료 시 소멸. 전투불능은 전투 중 회복 불가.
  • R6 사건마다 승리→패배 판정, 결과가 나면 남은 명령 취소. 무승부 규칙 없음.
  • R7 대기 = 효과·비용 없음.
  • R8 정수 계산, 비율은 내림. 기본 피해 → 약점 배율 → 감소 → 보호막 → 체력.
  • R9 미리보기는 실제 실행과 같은 계산으로 라운드 종료 상태까지 보여준다.
  • R10 가로막기(대상 변경)는 시제품에서 제외.
