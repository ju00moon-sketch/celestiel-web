0. 원칙

  • 새 동작은 튜토리얼 전술 규칙 세트(FCombatRuleSet::MakeTutorialTactics())에서만 켜진다.
  • 기본 전술(MakeTacticsP1)과 '이동 없음' 모드는 흐름·사건 로그·입력 로그가 바이트 단위로 그대로다(10절).
  • 규칙 판정은 지금처럼 결정적이다.
  • 단계 진행(안내, 다음 단계 조건, 다음 패턴 고르기)은 진행자(Battle/)가 한다.
  • 규칙 계층은 '고른 패턴'만 입력으로 받는다.

1. 규칙 세트와 수치 버전[결정 T4]

  • MakeTutorialTactics()의 바탕은 MakeTacticsP1()이다. 규칙 문자열은 RT-v0.3+D8+CT-v0.3 그대로 두고, 판정 규칙은 같다.
  • 수치 버전은 TUT-T-v0.1이다(수치는 BALANCE_LOG 'TUT-T' 절, 총괄 결정 2026-09-27). 이 버전 문자열로 규칙 세트를 가린다. 재실행기의 버전 대조가 튜토리얼 기록과 CT-P1 기록을 섞지 않게 한다.
  • 다른 값
  • 적 패턴 5개(TT_*, 수치는 BALANCE_LOG 'TUT-T' 절)
  • bExternalPatternChoice = true, 순서표(Rotation)는 비움
  • StaggerMax 3[결정 4]
  • BossRadiusCm 50[결정 4]
  • 적 체력 등 나머지는 수치 초안에 따른다
  • 인물 스킬·판정 폭·배율·치명타·엄호·연계 값은 CT-P1 그대로다. 엄호·연계·막기는 한 명이라 일어나지 않는다.
  • 데이터 검증(tactics_rotation)
  • 바깥 선택이면 순서표가 비어 있어야 하고, 패턴은 1개 이상이어야 한다.
  • 순서표 모드는 지금 그대로다.

2. 바깥 패턴 선택[결정 1]

2.1 흐름

  • 바깥 선택 규칙 세트에서는 라운드 사이에 새 상태 ECombatState::WaitingForPattern이 있다(열거 끝에 붙인다, 로그 이름 WaitingForPattern).
  • 전투 시작·재도전
  • 지금: 머리 사건(BATTLE_START·UNIT) 뒤 곧바로 ROUND_START로 간다.
  • 바뀐 뒤: 머리 사건 뒤 Round = 1로 두고 WaitingForPattern에서 멈춘다.
  • 라운드 끝
  • ROUND_END와 효과 소멸 사건 뒤 Round + 1로 두고 WaitingForPattern에서 멈춘다.
  • 승패로 끝났으면 기다리지 않는다(Victory·Defeat).
  • 선택을 받으면 그 자리에서 라운드를 시작한다: ROUND_START → FOCUS → INTENT → WaitingForPlan. 그 뒤 흐름은 CT-P1 그대로다(계획 → 선행 → 보스 공격 → 예약 → 후행 → ROUND_END).
  • 기다리는 동안의 조회
  • GetRound()는 다음 라운드 번호다.
  • GetIntent()는 비운다(바깥 선택에서만).
  • GetResolvedAttack()은 지금처럼 비어 있다.

2.3 순환 번호와 가짜 박

  • 바깥 선택에서 순환 번호는 이번 시도에서 그 패턴을 고른 횟수다(이번 라운드 포함, 1부터).
  • FakeFromCycle과 INTENT의 cycle이 이 값을 쓴다.
  • 순서표 모드의 (r − 1) ÷ 길이 + 1은 그대로다.

2.4 회피 불가 연속 금지[사양, 결정 T1]

  • 사양은 "회피 불가는 연속으로 두 번 쓰지 않는다"이고, 레이드 3단계에서만 허용한다(사용자 확정).
  • 순서표 모드에서는 데이터 검증이 이것을 막는다. 바깥 선택에서는 선택 때 막는다: 직전 라운드 패턴이 회피 불가면 회피 불가 패턴을 UnavoidableRepeat로 거절한다.
  • 경직으로 공격이 취소된 라운드도 그 라운드에 고른 패턴으로 센다. 재도전하면 처음부터 센다.
  • 튜토리얼 영향: 회피 불가 단계(2 리듬 패링, 4 피할 수 없는 공격)를 바로 다시 할 수 없다.
  • 2단계를 다시 할 때는 사이에 채움 라운드(TT_SWEEP, 새 안내 없음) 하나를 넣는다.
  • 4단계는 보여 주기 단계라 다시 하지 않는다(5절 표).
  • 튜토리얼 예외는 두지 않는다. 사용자 확정 규칙과 맞다.

2.5 경직 취소와 선택

  • 경직으로 다음 공격 취소가 정해진 뒤 고른 패턴은 INTENT canceled=true로 공개되고, 그 라운드에는 보스 공격이 없다(CT-P1 규칙 그대로).
  • STAGGER_BREAK의 attack 값 — CT-P1 계약 6.6절의 예외[결정 T3]
  • 순서표 모드는 지금처럼 R{라운드}.{패턴 id}다.
  • 예외: 튜토리얼 규칙 세트(바깥 선택)에서 다음 라운드 공격을 취소할 때는 패턴을 아직 모르므로 R{라운드}만 쓴다. 예: STAGGER_BREAK attack=R4 gauge=3>0
  • 이 예외는 튜토리얼 규칙 세트에서만 나온다. 이번 라운드 공격을 취소할 때는 지금과 같다.
  • CT-P1 계약 6.6절 STAGGER_BREAK 행에 "바깥 선택의 예외는 TUT-T 계약 2.5절"을 더했다(수정본 7).
  • 진행자는 STAGGER_BREAK를 보고, 취소될 라운드를 단계 보여 주기에 쓰지 않는다(5절).

2.6 사건·미리보기·UI 영향

  • 새 사건은 없다. 고른 패턴은 그 라운드 INTENT의 pattern·cycle로 보인다.
  • 미리보기(CombatPreview::Build)는 전투를 복사해 라운드 끝까지 돌리므로, 바깥 선택에서는 EndState가 WaitingForPattern이다.
  • ②-B 확인: 카드의 '라운드를 마침'은 WaitingForPlan 또는 WaitingForPattern으로 본다(BattleUIText는 Victory·Defeat만 보므로 지금 코드는 영향이 없을 것으로 본다).
  • 진행자는 WaitingForPattern에서 새 비트(가칭 Step)를 연다(5절). 계획 화면 조건(WaitingForPlan)은 그대로다.

3. 한 명 전술[결정 2]

  • 시작 상태: 참가 인물(Participants)을 전술 시작 정보와 함께 쓴다.
  • 새 FCombatStartState::MakeTacticsTutorial(Rules, Arena, Seed) = MakeTactics + 참가 {A}
  • 시작 체력·집중력 칸은 지금처럼 5명 모두 두고, 참가하지 않은 인물의 값은 쓰지 않는다.
  • 자리
  • 전투 공간 파일의 party와 전술 시작 정보의 Party는 지금처럼 A~E 5자리다.
  • 참가하지 않은 자리는 형식과 정수 범위만 본다(arena_range, start_tactics_body의 반지름·방향).
  • 배치 검증(경계 안, 서로·장애물·보스 몸과 겹치지 않음)은 참가자만 본다.
  • CombatArena::ValidatePlacement(Arena, BodyRadiusCm, BossRadiusCm, Participants)를 더했다. 5명이면 기존 3인자 함수와 같은 결과다.
  • 규칙: 참가하지 않은 인물의 몸은 모든 전술 판정에서 없는 것으로 본다.
  • 대상: 이동 막기·빈 자리·조준(가장 가까운·먼 인물)·범위 대상·엄호·연계·가림
  • 전투불능(결정 D1)과 같게 자리는 남기되 쓰지 않는다.
  • 지금 코드는 IsLiveParticipant로 대부분 거른다. 구현 때 전수 확인하고, 한 명 시나리오 시험으로 고정한다.
  • 사건: 인물 줄(UNIT·MOVE·COVER 등)은 지금처럼 참가자만 나온다.
  • 진행자
  • PrepareRules의 '전술 모드는 기본 5인 시작 상태만' 제한을 푼다.
  • StartStateKind = Tutorial + ArenaId이면 MakeTutorialTactics()와 MakeTacticsTutorial로 시작한다.
  • 인물 연출은 참가자만 보인다(TUT-PLAY-1 규칙 그대로).
  • 가까운 연출 구도(결정 D2)는 이미 참가자만 담는다.

4. 튜토리얼 돌진 조준[결정 3]

  • TT_THRUST는 직선 + NearestAtPlan이다. 데이터 검증은 이미 이 조합을 받는다.
  • 방향이 계획 때 고정되므로, 계획 때 비켜 서거나 저스트 회피로 피한다. 둘 다 3단계가 가르치는 것이다.

5. 단계 진행(진행자)과 안내 UI 경계[결정 T2·T5·T6]

  • 단계표는 진행자 데이터다(②-A, 사용자 문구 없음).
  • 진행자는 WaitingForPattern마다 다음을 한다.
  1. 직전 라운드 사건으로 단계 통과를 판정한다.
  2. 다음 단계의 패턴을 ChoosePattern으로 낸다.
  3. 단계 정보를 알린다.
  • 자동 진행(기록 재생)은 기록의 pattern을 그대로 내고 단계 판정은 하지 않는다.

  • 안내 UI 경계(②-B)
  • 진행자 조회: GetTutorialStep() → FBattleTutorialStepView { FName StepId; int32 Try; bool bFiller; bool bPassedPrev; }
  • 진행자 알림: OnTutorialStep(단계가 바뀌거나 다시 할 때)
  • ②-B는 StepId로 안내 한 줄과 강조 대상(이동 핸들, 박자 줄, 준비 방어 버튼, 보스 뒤쪽 등)을 정한다.
  • 안내 문구의 글은 UI 쪽 표에 두고 총괄이 확정한다(총괄 확인).
  • 미리보기 EndState = WaitingForPattern의 UI 영향은 총괄이 ②-B에게 확인시킨다(2.6절).

  • 전투 → 탐험 쪽과 필드 흐름 시험은 ②-B가 맡는다.
  • 전투 문맥 안의 입력 시험(진행자 시험)은 ②-A가 맡는다.

7. 사람형 적 연출[결정 6]

  • ②-A가 새 연출 클래스 ABattleHumanoidEnemy(가칭)를 만든다. 지금 ABattleBoss(블록)는 CT-P1용으로 남는다.

  • 박마다 예비 동작 시작·타격: 가짜 박은 헛손질이다.
  • 공격 시계로 자세 갱신
  • 자세 초기화
  • 핵 위치 GetCoreLocation(): 근접 행동이 바라보고 발사체가 향하는 점
  • 맞음·쓰러짐
  • 돌기(FACE)·돌진 이동(BOSS_MOVE): 액터 변환은 진행자가 하고, 적 클래스는 걷기·달리기 애니메이션만 속도에 맞춘다.

  • 핵은 가슴 소켓(CoreSocket)이다. 반지름 값은 적 클래스가 가진다.

13. TUT-T2: 진행자 단계 진행과 안내 UI 경계(②-A 제안, 2026-09-27)

  • 5절 단계표와 기획안 6장(안내 문구 임시 표)을 진행자 데이터와 UI 계약으로 구체화한다.
  • 진행자(②-A)는 단계를 정하고 알린다. 안내 글과 강조 표시는 UI(②-B)가 이 절의 키로 그린다.

13.1 단계 진행(진행자)

  • 진행자는 WaitingForPattern마다 새 비트 Step(EBattleBeat::Step, 열거 끝, 길이 Timings.TutorialStep 0.3초)을 연다. 비트를 시작할 때 차례대로 한다.
  1. 직전 라운드가 단계 라운드였으면 그 라운드 사건으로 결과를 정하고 result를 알린다.
  2. 다음 라운드의 단계와 패턴을 정한다. 그 패턴이 UnavoidableRepeat이면 채움 라운드(TT_SWEEP)를 먼저 넣는다.
  3. ChoosePattern을 부르고 step을 알린다. 그 뒤(ROUND_START·INTENT 머리 → 계획)는 지금 그대로다.
  • 결과 판정: 그 라운드(같은 시도)의 사건만 본다.

| 단계(StepId) | 패턴 | 결과 |

|---|---|---|

| Move | TT_SWEEP | 보스 공격 AREA의 targets에 A가 없으면 passed |

| Parry | TT_COMBO | A의 JUDGE result가 perfect·success인 것이 1개 이상이면 passed |

| Dodge | TT_THRUST | BOSS_MOVE가 있으면(빗나감) passed |

| Unavoidable | TT_OVERHEAD | 보스 공격이 있었으면 shown |

| Flank | TT_SWEEP | A의 BOSS_DAMAGE zone이 flank·back인 것이 1개 이상이면 passed |

| Feint | TT_FEINT | 보스 공격이 있었으면 shown |

  • 위 조건이 아니면 failed다.
  • 그 라운드 공격이 경직으로 취소됐으면 canceled다. 횟수에 넣지 않고 같은 단계·같은 시도를 다시 고른다.
  • 앞 라운드에서 찬 경직: 그 라운드 INTENT canceled=true
  • 그 라운드 선행에서 찬 경직: 그 라운드 STAGGER_BREAK attack이 그 라운드 공격 id다(의도는 canceled=false로 이미 나갔다).
  • 다시 하기
  • Move·Parry·Dodge·Flank는 두 번째 시도(Try 2)까지 한다.
  • 두 번째도 failed면 그 단계는 넘어감(통과 아님)이다. 사용자가 막히지 않게 다음 단계로 간다[총괄 확인].
  • Result 알림: Result = Failed, bRetryNext = false
  • 다음 Step의 bPassedPrev는 false다.
  • 넘어간 단계는 통과로 기억하지 않는다. 그래서 재도전하면 다시 한다.
  • 첫 시도의 failed는 Result = Failed, bRetryNext = true이고, 다음 Step이 같은 단계 Try 2(Tut.Retry)다.
  • Unavoidable·Feint는 보여 주기라 한 번이다.
  • 자유 전투(Free): 여섯 단계를 다 지나면 TT_SWEEP → TT_COMBO → TT_THRUST → TT_OVERHEAD를 되풀이한다. 승패로 끝날 때까지다.
  • 재도전(여주인공이 쓰러짐, 결정 T6)
  • 진행자는 세션 동안 통과·보여 준 단계를 기억한다.
  • 새 시도는 1라운드부터 아직 통과하지 못한 단계를 순서대로 다시 한다(시도 횟수는 새로 센다). 모두 지났으면 자유 전투부터다.
  • 적이 먼저 쓰러지면(결정 T5) 보통 승리로 끝나고 남은 단계는 건너뛴다.
  • 자동 진행(기록 재생)은 기록의 pattern만 내고 단계 판정·알림은 하지 않는다.

13.2 조회와 알림(진행자 → UI)


enum class EBattleTutorialNotice : uint8 { Step, Result, Finish };
enum class EBattleTutorialResult : uint8 { None, Passed, Failed, Shown, Canceled };

struct FBattleTutorialStepView
{
	EBattleTutorialNotice Notice = EBattleTutorialNotice::Step; // Step: 라운드를 시작함, Result: 직전 라운드 판정, Finish: 튜토리얼 승리
	FName StepId;              // Move·Parry·Dodge·Unavoidable·Flank·Feint·Free. Finish는 Victory
	int32 Try = 0;             // 1 첫 시도, 2 다시 하기. Free·Finish는 0
	bool bFiller = false;      // 채움 라운드(새 안내 없음). StepId·Try는 채움 뒤에 할 단계
	bool bPassedPrev = false;  // Step만: 직전 단계를 통과했거나 보여 줬다
	EBattleTutorialResult Result = EBattleTutorialResult::None; // Result만
	bool bRetryNext = false;    // Result만: 같은 단계를 다시 한다(Failed 시도 1, Canceled). Failed인데 false면 넘어감(통과 아님)
	FName HintKey;             // 안내 문구 키(13.3절). 없으면 NAME_None(채움·Result)
	TArray<FName> Highlights;  // 강조 대상 id(13.3절). 없으면 빈 배열
	FString PatternId;         // Step: 이번 라운드 패턴, Result: 판정한 라운드 패턴
	int32 Attempt = 0;
	int32 Round = 0;           // Step: 시작할 라운드, Result: 판정한 라운드, Finish: 끝난 라운드
};

DECLARE_MULTICAST_DELEGATE_OneParam(FOnBattleTutorialStep, const FBattleTutorialStepView&);
FOnBattleTutorialStep ABattleDirector::OnTutorialStep;
const FBattleTutorialStepView* ABattleDirector::GetTutorialStep() const; // 지금 보일 안내(마지막 Step·Finish). 튜토리얼 전술 일반 진행이 아니면 nullptr
  • 알림 순서
  • 라운드 끝 → (단계 라운드였으면) Result → 다음 라운드 Step
  • 승리 표시(Finish 비트) 시작 → Finish
  • 재도전·새 전투: 표현 초기화(GetPresentationSerial 증가) 뒤 1라운드 Step
  • 알림은 진행자 틱 안에서 보낸다(OnPlanInput과 같다). 패배에는 알림이 없다(지금처럼 결과 창의 재도전).

13.3 안내 문구 키와 강조 대상 id

  • 글은 UI 쪽 표에 둔다. 지금 글은 기획안 6장 임시 문구이고, 확정은 총괄이 한다.

| HintKey | 쓰는 때 | 강조 대상(Highlights) |

|---|---|---|

| Tut.Move | Move 시도 1 | AttackArea, MoveRange |

| Tut.Parry | Parry 시도 1 | BeatBar, JudgeLine |

| Tut.Dodge | Dodge 시도 1 | ChargeBand, DodgeKey |

| Tut.Unavoidable | Unavoidable | UnavoidableBadge, ReadyDefense |

| Tut.Flank | Flank 시도 1 | FlankZones, StaggerGauge |

| Tut.Feint | Feint | FakeFlash |

| Tut.Retry | 모든 단계의 시도 2 | 그 단계의 강조 그대로 |

| Tut.Free | 자유 전투 라운드 | 없음 |

| Tut.Victory | Finish | 없음 |

  • 강조 대상 id의 뜻
  • AttackArea 예고 범위, MoveRange 이동 원
  • BeatBar 박자 줄, JudgeLine 판정선
  • ChargeBand 돌진 띠, DodgeKey Space 안내
  • UnavoidableBadge '회피 불가' 표시, ReadyDefense 준비 방어 칸
  • FlankZones 측면·배후 부채, StaggerGauge 경직 칸
  • FakeFlash 표식 없는 예고 반짝
  • 채움 라운드는 HintKey가 없고 강조도 없다. 안내 줄을 비울지 앞 안내를 둘지는 ②-B가 정한다.

13.4 표시 로그(자동 확인용)

  • tutorial_step attempt=1 round=2 step=Parry try=1 filler=false pattern=TT_COMBO hint=Tut.Parry highlight=BeatBar,JudgeLine
  • tutorial_result attempt=1 round=1 step=Move try=1 result=passed retry_next=false pattern=TT_SWEEP
  • tutorial_finish attempt=1 round=8 hint=Tut.Victory

  • 없는 값은 -다(예: hint=-, highlight=-).

13.5 ②-B 인계(UI)

  1. WaitingForPattern: 계획 화면은 지금처럼 Plan 비트 + WaitingForPlan에서만 연다. Step 비트(라운드 사이)에는 조작이 없다. 디버그 표시에 새 규칙 상태·비트 이름이 나온다.
  2. 미리보기 EndState: 바깥 선택에서는 라운드를 마치면 WaitingForPattern이다. 카드의 '라운드를 마침'은 WaitingForPlan·WaitingForPattern 둘 다로 본다.
  3. 계획 자동 채움(FBattlePlanDraft::FindFill): 입력 로그의 계획 없는 마지막 기록(bPlanned = false)은 계획이 비어 있으니 건너뛴다. 튜토리얼은 라운드마다 패턴이 달라 앞 시도의 같은 라운드 계획이 맞지 않을 수 있다. 채울지는 ②-B가 정한다.
  4. 문구 표(HintKey → 글)와 강조 표시는 ②-B가 만든다. 문구 글은 총괄이 확정한다.
  5. Step 비트의 Enter는 진행자 NotifyConfirm → UI 확인 알림(OnConfirm)으로만 간다. 계획 확정과 같은 알림이므로 안내 줄은 Enter를 쓰지 않는다.

13.6 진행자 시작과 적 연출(3·7절 구체화)

  • StartStateKind = Tutorial + ArenaId면 MakeTutorialTactics() + FCombatStartState::MakeTacticsTutorial로 시작한다. Default + ArenaId는 지금처럼 MakeTacticsP1이다.
  • 7절 공통 기반 ABattleEnemy를 둔다.
  • 구현: ABattleBoss(블록, CT-P1)와 ABattleHumanoidEnemy(튜토리얼)
  • 공통 호출: StartSwing(HitIndex, Timing, bFake), UpdateArms(ClockMs), ResetArms(), GetCoreLocation(), GetCoreRadius()
  • 사람형 적은 아트가 오기 전까지 대역이다.
  • 모습: 인물 블록아웃 외부 3D 생성 도구(SM_TestPartyMember) + 보스 재질 + 목검 팔(보스 팔 외부 3D 생성 도구를 줄인 것)
  • 동작: 가짜 박은 들다가 멈추는 헛손질이다.
  • 새 에셋은 만들지 않는다.
  • 구도: 대응·행동 구도는 카메라 → 적 핵 시선 구간이 담은 인물 몸 영역(발 둘레 TacticsPeopleClearCm 60, 발에서 인물 높이 + 60까지의 원기둥) 안을 한 곳이라도 지나면 장애물 가림처럼 방향을 ±20°씩 돌린다(camera 줄 hidden=). 1인 튜토리얼에서 A가 사람 크기 적을 가리지 않게 하는 것이다. 핵이 높은 CT-P1 보스는 시선이 인물 위로 지나 걸리지 않는다.
  • 진행자 조회: GetBoss()는 지금처럼 ABattleBoss*를 돌려준다(사람형이면 nullptr). 새 GetEnemy()는 둘 다 돌려준다.
