현재 모델링 개선 방향은 유지한다. 헤어 전면 재작성, 다른 프로그램으로 전환, 얼굴 재생성, v3f 둔부 재조형을 새로 시작하라는 뜻은 아니다.

1. 최신 기준 동기화

  • HAIR-2·CHAR-UE-0·현황판 인계표를 최신 결정과 맞춰줘.
  • ④ 얼굴·헤어 / ⑤ 체형·렌더·엔진 조립으로 담당을 정리하고, v3f 기반 다리 조정 채택본과 최신 채택 헤어를 인계 기준으로 명시해줘.
  • h1~h3·v3c 등 이전 기준을 현재 인계본처럼 표시하지 마.

2. 헤어 그룹 대응

  • 최신 여섯 편집 구역과 실제 가닥·가이드 ID, 내보내는 Groom 그룹, 뿌리 기준면, 물리 적용 여부의 대응표를 만들어줘.
  • 편집 구역 수와 Groom 그룹 수를 무조건 같게 만들 필요는 없다.
  • 예전 끈 분할 계약을 새 X자 반묶음에 그대로 적용해도 되는지 확인해줘.

3. 가이드 편집 왕복 시험

  • NPZ 기준 원본은 유지한다.
  • Blender에서 앞머리 가이드 하나 수정 → 새 NPZ 저장 → 재생성 후 수정 내용과 비수정 구역이 보존되는지 시험해줘.
  • 이미 구현됐다면 새로 만들지 말고 결과만 제출해줘.

4. 뒷목과 긴 머리

  • 후드 접촉 때문에 가닥을 잘라내거나 같은 높이에서 종료하는 처리가 있는지 확인해줘.
  • 원인이라면 길이 삭제보다 가이드 경로와 충돌 여유를 조정해줘.
  • 확정 반묶음과 긴 뒷머리 목표는 유지한다.

5. 다리 비율과 측정

  • v3f 기준 +1.0/+1.5cm 두 안에서 표면 전이 변화와 고관절·무릎·발목의 골격 변화를 구분해서 보고해줘.
  • 키·머리 크기·발바닥 기준과 v3f의 체형 인상은 유지한다.
  • 3.2cm 고랑 깊이는 기존 z88 단면과 보호 부위의 대응을 확인하고, 측정 기준을 바꿔서 조건 통과로 처리하지 마.

6. 내보내기 기준

  • 편집용 셰이프 키·래티스는 작업 원본에 보존한다.
  • 채택한 정적 체형은 별도 출력 사본에 반영하고, 그 체형에 맞는 리그·가중치·모듈을 하나의 인계 묶음으로 만든다.
  • 동작 보정용 Morph Target을 쓰면 Unreal에서의 적용까지 따로 검증해줘.

7. 선행 엔진 시험

  • 최종 자산 연결 대기와 작은 Dev 전달 시험을 구분해줘.
  • 기존에 통과한 작은 Groom 시험은 재사용하고, 새 구조의 변경 부분과 체형 수정본의 움직임을 먼저 확인해줘.
  • 시험 결과를 최종 외형 승인으로 기록하지 마.

8. 공개 문서 오류

  • build_docs.py에서 일반 기술용어 '메시'를 '외부 3D 생성 도구'로 일괄 치환하는 규칙을 수정해줘.
  • 서비스 이름·개인정보 익명화는 유지하되 기술적 의미는 보존해줘.
