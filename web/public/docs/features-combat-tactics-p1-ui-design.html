전장 전술 전투 CT-4·CT-5 UI 설계 초안(②-B)

  • 기준: combat-tactics-v0.3.md(승인본) 「화면·카메라」·「리듬 패링」·「회피와 막기」, combat-tactics-p1-design.md(총괄) 3~5절
  • 참고 그림: D:\GameDevelop\Unreal\ArtSource\Concepts\CombatUI\(9/25 세 장, CUI_battle_concept_v03_board2.png). 그림 속 글자·인물·수치는 예시이고 사양이 기준이다.
  • 상태: 1절 원칙과 7·8절 결정은 총괄이 승인했다. 공유 계약은 수정본 2로 승인됐고(CP-T0, 2026-09-27), 4절 요구가 모두 반영됐다. CT-4는 계약 필드를 따른 UI 쪽 입력 모델로 먼저 만들고(CT-4a 커밋 fef1d9b), CP-T3에서 규칙 미리보기와 잇는다.

1. 원칙

  • UI는 규칙 계층이 낸 값(미리보기 K-T4, 예고·박자 K-T5, 진행자가 보인 사건)만 그린다. 거리·각도·범위·사거리·가림·측면·배후·엄호·연계 판정을 UI에서 계산하지 않는다.
  • UI가 직접 하는 계산은 둘이다: 월드 점을 화면에 투영하기, 끌기에서 화면 점을 전투 공간 바닥 평면에 역투영하기(목표 자리는 cm 정수로 반올림해 규칙에 넘긴다).
  • 월드 위 표시(원·부채·선·범위)는 에셋 없이 Slate 층에서 투영해 그린다. 지금 숫자 층(SBattleFloatLayer)과 같은 방식이다. 데칼·외부 3D 생성 도구·재질이 필요 없어 ⑤ 작업과 겹치지 않는다.
  • '이동 없음' 모드(S1~S4 회귀)에서는 새 표시가 모두 숨고 지금 화면 그대로다. 지금 UI 자동 시험은 모두 유지한다.
  • 파일 범위: Source/Celestiel/UI/, UI/Slate/, Tests/UI/. 입력 통로처럼 Battle/을 바꿔야 하는 것은 7절에 적고 총괄을 거친다.

2.2 전장 표시 층이 그리는 것

표시모양값의 출처
이동 원선택 인물은 실선 원(반지름 = 이동 거리), 다른 인물은 흐린 원. 도달 판정은 경로 길이라 원은 윤곽일 뿐이다K-T1 이동 거리
경로지금 자리 → 목표 자리 점선 화살표(경로 점을 잇는다). 겹침 해소로 밀렸으면 목표 ×와 실제 자리 ●를 함께K-T2 경로·최종 자리
도달 불가목표 자리 빨간 ×와 사유 한 줄K-T2 사유
예고 범위피할 수 있음 = 빨강 반투명 채움·테두리, 반회피 = 주황 채움 + '피하면: 대가' 글, 회피 불가 = 보라. 전장 전체는 전장 가장자리 보라 테두리, 대상 고정은 대상 발밑 보라 고리 + '회피 불가' 글, 저스트 회피 불가는 '저스트 회피 불가'를 더 붙인다. 낙인 창처럼 원이 여럿이면 원마다 타격 순서 번호를 붙인다. 돌진은 빗나가면 보스가 옮길 자리에 보스 윤곽 점선 원을 그린다미리보기 확정 공격(Attack.Area·Beats·BossEndIfMissed), 의도의 종류·대상 규칙 글
취소된 공격경직으로 취소되면 범위를 그리지 않고 보스 머리 위에 '경직: 공격 취소'의도 bCanceled
몇 타인물 머리 위 'N타'(0타 흰 글, 1타 이상 빨간 바탕). 회피 불가 타격이 있으면 보라 테두리. 규칙이 계획을 받았을 때만 보인다(거부된 계획은 피격·엄호·연계 값이 없다, 총괄 결정 2026-09-27)K-T4 피격 수·공격 목록
사거리·가림 선선택 인물 → 행동 대상. 사거리 안·시야 트임 = 흰 실선, 사거리 밖 = 회색 점선 + '사거리 밖', 가림 = 막힌 지점까지 실선 + × + '가림'K-T4 사거리·시야·막힌 지점
측면·배후 부채보스 둘레에 측면(양쪽 60~150°)·배후(150~180°) 부채를 옅게. 기준 방향은 고른 인물의 행동 시점 보스 방향이고, 보스 대상 행동이 아니면 돌기 전 방향이다. 인물이 측면·배후면 'N타' 옆에 '측면'·'배후'경계 FlankFromDeg·BackFromDeg, 방향 Action.BossFacingAtAction·Attack.BossFacingBefore, 인물별 여부 Action.Zone
엄호 선준비 방어 인물 → 지킬 아군, 방패 표식 + 파란 점선K-T4 엄호 대상
연계 선주는 쪽 → 받는 쪽. 이어짐 = 금색 점선, 8m 밖 = 회색 점선 + '연계 끊김'K-T4 연계 가능 여부
  • 색: 측면 청록, 배후 파랑으로 시작한다. 빨강·주황·보라는 예고 범위에만 쓴다(보드 2는 배후를 파랑·빨강 두 가지로 그렸다, README). 사용자 답에 따라 바꿀 수 있게 이 층의 색은 모두 스타일(BattleUIStyle) 한곳에서 정한다.
  • 매 페인트마다 다시 투영하므로 조망 카메라(A/D·Q/E·Z/X)를 움직여도 표시가 바닥에 붙어 있다.
  • 머리 위 글은 무리로 다룬다: 적 하나(공격 이름·저스트 회피 불가·경직 취소), 인물마다 하나('N타'·측면/배후·대상 고정 '회피 불가'). 무리의 가장 위 글 상자 위 끝이 y 140(보스 막대 아래 8px)보다 위면 그 무리를 함께 내린다. 공간의 먼 가장자리에 서도 보스 막대를 덮지 않는다(총괄 결정 2026-09-27).
  • 인물 무리는 가장 아래 글(상자면 상자) 아래 끝이 머리 투영(발 위 180cm, 그리기용 어림값)보다 4px 넘게 위면 그만큼 함께 내린다. 조망을 멀리 두면 인물이 작아져 발 위 고정 px 자리가 머리보다 훨씬 높이 뜨고, 인물 앞에 선 적의 몸을 덮는다(총괄 지시 2026-09-27). 올리지는 않으므로 가까운 조망 자리는 그대로다. 적 무리는 적마다 키가 달라 쓰지 않는다.

2.3 조작

조작동작
인물 끌기(왼쪽 버튼)발밑 원 안을 잡아 끌면 목표 자리가 따라온다. 끄는 동안은 경로·도달만 다시 구하고(K-T2 가벼운 조회), 놓으면 미리보기 전체(K-T4)를 다시 구한다
인물 클릭그 인물을 고른다(지금 목록 클릭과 같은 Select)
빈 바닥 클릭고른 인물의 목표 자리를 그곳으로
[제자리]선택 인물 패널의 버튼. 고른 인물의 이동을 취소한다(지금 자리)
Tab / Shift+Tab생존 인물을 순서대로·거꾸로 고른다. Tab 건너뛰기(R9)는 파티 행동 비트에서만 받으므로 계획 비트와 겹치지 않는다
방향키고른 인물의 목표 자리를 화면 기준 방향(조망 카메라 요 기준)으로 50cm씩 옮긴다
  • Tab·Shift+Tab·방향키는 진행자·플레이어 컨트롤러(Battle/)가 받아 계획 단계의 탐색 키 알림으로 UI에 넘긴다(②-A가 K-T6에 넣어 만든다, 7절 3). Enter는 지금처럼 진행자 확인 알림(OnConfirm) 한 경로로 받는다(7절 7). 마우스 끌기·클릭은 전장 표시 층이 직접 받는다.

| Enter | [계획 확정] 그대로 |

  • 편집 하나(놓기·클릭·방향키 한 번)가 계획 편집 한 번이다. 관찰 기록에 편집 종류 '이동'을 더하고 'ui edit' 줄도 같게 남긴다.
  • 계획 편집 상태(FBattlePlanDraft)에 인물별 목표 자리를 더하고, 낼 계획에 이동 명령(K-T2 형식)으로 넣는다. 자동 채움(직전 라운드·이전 시도)도 목표 자리를 함께 채운다.

2.4 명령

  • 사양: 라운드마다 이동 한 번 + 행동 하나(공격·준비 방어·예약·대기). 지금 스킬 바(스킬·대기·예약)를 네 묶음 머리 아래에 스킬을 두는 모양으로 바꾼다. 묶음은 규칙 데이터의 스킬 종류로 나눈다.
  • 구현(CP-T3, 총괄 결정 2026-09-27): 묶음 머리와 사양 순서(공격·준비 방어·예약·대기)는 전술 모드에만 쓴다. 지원 스킬(B2)도 스킬 행동이라 '공격' 묶음이다. '이동 없음' 모드·튜토리얼은 무변경 원칙에 따라 머리 없이 지금 칸과 순서(스킬·대기·예약) 그대로다. 준비 방어 칸 이름은 Plan.<인물>.Ready다.
  • 준비 방어: 전술 모드에서는 다섯 명 모두의 공통 명령(ready, 대응 자리, 계약 6.3절)이라 인물마다 '준비 방어' 칸을 둔다. 턴 순서 열의 대응 칸에는 준비 방어 인물을 모두 보인다. '이동 없음' 모드는 지금처럼 A2 스킬 칸이다.
  • 예약 인물을 고르면 후보(회복·공격 지원)마다 사거리 선을 하나씩 보인다(ReserveActions).
  • 구간·순서·대상·연결·예약 대상 편집 줄은 그대로다. 이동은 명령과 따로라 어떤 명령을 골라도 목표 자리는 남는다.

2.5 박자 악보(Plan.Score)

  • 다음 보스 공격(보인 의도)의 패턴 이름, 종류 색 띠('회피 불가'·'저스트 회피 불가'), 타수, BPM.
  • 박자 줄: 가로 시간축에 타격 시각을 점으로 찍는다(첫 타격 기준, 쉼은 빈 칸). 강타는 큰 점, 가짜 박은 속 빈 점(8절). 음표 기호는 쓰지 않는다(사양은 모양을 정하지 않았다).
  • 점 아래에 그 타격을 맞을 인물 머리글(K-T4 공격 목록)을 붙인다. 여러 대상을 잇는 연타는 대상 순서대로 한 줄에 잇는다.
  • 머리글은 제 점 가운데에 두되, 줄 밖으로 나가면 줄 안으로 밀고 옆 머리글과 4px 이상 띄운다(첫·마지막 타격의 'A·B·C·D·E'도 칸 안). 글 폭 합이 줄보다 길면 줄 안에 두는 것을 먼저 지킨다.
  • 패링 키는 계획 화면 악보에 보이지 않는다(사양: 박자 줄·타수·빠르기). 키는 실행 화면 박자 줄에서만 보인다.

3. 실행 화면(CT-5)

3.1 배치

  • 카메라: 진행자의 연출 카메라 그대로. 실행 비트에서는 계획 화면 패널과 전장 표시 층을 숨긴다.
  • 최소 HUD: 위 띠(보스 체력·경직 게이지 5칸·행동 이름), 5인 띠(체력), 상태 칸의 일시정지 버튼, Tab 건너뛰기 안내를 남긴다. 지금 기본 틀(SBattleFrame)의 나머지 칸(제목 줄 R1·턴 순서 R6)은 실행 비트에 숨긴다.
  • 일시정지 버튼과 Tab 안내를 남기는 까닭: 실행 중에도 P 정지와 건너뛰기를 알 수 있어야 한다(총괄 판단, 2026-09-27).
  • 구현(CT-5): 전술 모드의 실행 비트(계획 화면이 닫혀 있을 때)에 적용한다. 보스 막대·5인 작은 목록·행동 이름 배너·상태 칸·Tab 안내는 그대로 보인다.
  • 박자 줄(새 Exec.Beat, 지금 SBattleResponseScreen 자리를 바꾼다): 화면 아래 가운데 가로 약 1200×120.
  • 구현(CT-5): 가운데±600 × 900~1020. 전술 모드에서 박자 줄 값이 있을 때(보스 공격 동안)만 대응 화면 자리를 대신한다. '이동 없음' 모드와 튜토리얼은 지금 대응 화면 그대로다.
  • 가운데 판정선(원). 타격 표식이 오른쪽에서 흘러와 타격 시각에 판정선에 닿는다. 표식은 약 1.5초 앞에서 나타난다.
  • 표식 안에 그 타격의 패링 키 글자(Q·W·E·R·A·S·D·F). 엄호로 대신 받는 타격은 방패 표시 + '엄호'(회피 불가).
  • 예비 동작: 박마다 예고 시작(TelegraphMs)에 판정선이 한 번 반짝이고 소리가 난다. 가짜 예비 동작도 같은 신호이고, 가짜에는 흘러오는 표식이 없다(8절).
  • 판정 표시: 판정선 위에 '완벽'·'성공'·'실패'(이른 입력은 '이름'을 작게 더함). 지금 모양 규칙을 이어 쓴다: 완벽 = 채운 원(금색), 성공 = 채운 원(초록), 실패 = X(빨강), 이른 입력 = 사각 테두리(주황).
  • JUDGE 결과 → 글(계약 6.2절): parry perfect 완벽 · success 성공 · early 실패(이름) · fail 실패, dodge success 회피 성공 · early·fail 회피 실패, block blocked 막기 · side 막기 불가: 옆·뒤 · fail 막기 실패(뗌), none no_input 실패(무입력).
  • 광역: 한 입력이 인물마다 다르게 판정되면 판정 글 아래에 인물별 결과를 작게('A 완벽 · C 성공').
  • 구현(CP-T3): 판정 글은 가장 좋은 결과(완벽 > 성공·막기 > 이른 입력 > 그 밖) 한 단어이고, 인물별 결과는 그 아래 작은 줄이다(한 명이거나 모두 같으면 없음). 판정선 모양도 판정 글의 결과를 따른다.
  • 판정 글 표시 시간: JudgeShowMs = 700ms(UI/BattleBeatBar.h). 판정 글·판정선 모양·인물별 줄은 가장 최근에 보인 판정의 처리 시각(JUDGE의 atMs)부터 박자 줄 시계로 700ms 동안 보인다. 시계가 처리 시각보다 앞이거나 700ms가 지나면 지운다.
  • 공격 뒤 표시(UI 정책, CP-T3 검토 P2-01): 공격이 끝나 박자 줄 시계가 없어져도 그 공격의 ATTACK_END가 보였으면 마지막 판정 글·소리를 잃지 않는다. 끝 틱에 남은 타격·판정 신호를 내고, 판정 글 표시 시간(0.7초)이 다 될 때까지 박자 줄을 남긴다(시계는 끝 값에서 실시간으로 이어 센다). 마지막 판정이 공격 끝보다 0.7초 넘게 앞서면(끝 틱에 판정 글 시간이 이미 지났으면) 끝 틱에 박자 줄을 바로 닫는다. 정지 중에는 표시 시계도 멈춘다(정지 구간과 재개 프레임의 경과를 빼고 센다, 결과 창 무장 지연과 같은 기준, CP-T3 검토 P2-04). 공격이 끝나지 않고 시계가 없어지면(재도전 등) 바로 닫는다. 박자 줄은 그 틱의 표시 사건을 모두 읽은 뒤 갱신한다.
  • 그 공격의 판정만(CP-T3 검토 P2-02): 박자 줄에는 확정 공격 id가 같은 공격의 판정만 보이고, 시계가 판정 처리 시각보다 앞이면 보이지 않는다(다음 라운드 대응 준비에 지난 공격 판정이 나오지 않는다). 막기 칸은 공격과 따로 보인 REACT block_down·block_up으로 켜고 끈다.
  • 회피: 'Space 회피 성공'·'회피 실패'. 막기: 'Shift 막기'(옆·뒤라 못 막으면 '막기 불가: 옆·뒤').
  • 입력 안내: 박자 줄 아래 한 줄 '[키] 패링 · [Space] 회피 · [Shift] 막기(방패)'. 막기 키를 누르고 있으면 막기 칸이 켜진다. K3 안내(누르고 있던 키는 받지 않음)는 그대로 둔다(구현: 박자 줄이 대응 화면을 대신하므로 박자 줄 안 왼쪽 아래 Exec.Beat.K3에 보인다).

7. 정한 것(총괄, 2026-09-26)

  1. 측면·배후 색: 측면 청록, 배후 파랑으로 시작한다. 빨강·주황·보라는 예고 범위에만 쓴다. 사용자에게 측면 초록·배후 파랑 통일을 추천해 답을 기다리는 중이라, 색은 스타일 한곳에서 바꿀 수 있게 한다.
  2. 조작 편의 두 가지를 넣는다: 빈 바닥 클릭으로 목표 지정, 선택 인물 패널의 제자리. 규칙을 바꾸지 않는 조작이고 사양의 '마우스 위주(클릭·끌기)' 안이다.
  3. Tab·방향키 통로: Battle/은 ②-A 범위라 ②-A가 계약(K-T6)에 계획 단계의 탐색 키 알림으로 넣어 만든다.
  4. 조건부 미리보기 카드는 유지한다(기존 승인 기능). ②-A가 K-T4에 위치를 반영한 시나리오 결과를 계속 내고, 치명타(확률)를 미리보기에 어떻게 나타낼지 정한다.
  5. 박자 줄·소리의 시각 기준: 악보는 계획 때 공개된 정보라 실행 중 표식·소리는 전투 시계와 악보 시각으로 미리 그리고, 판정 결과는 판정 사건이 보인 뒤에만 그린다. 타격별 키는 표식이 나타나기 전(약 1.5초 앞)에 알 수 있게 ②-A가 계약에 넣는다. 계획 화면 악보에는 키를 보이지 않는다.
  6. 경직 게이지: 보스 체력 막대 옆에 5칸으로 보인다. 계획 화면과 실행 최소 HUD 둘 다다. 사양이 경직을 측면·배후를 노리는 이유로 적었고, 값은 계약에 있어 규칙 변경이 없다.
  7. 계획 문맥의 Enter: 지금처럼 진행자 OnConfirm → UI 한 경로로 둔다. 새 계획 탐색 알림은 Tab·Shift+Tab·방향키만 다룬다(정지·재도전 선후 판정을 한곳에서 하고, 지금 시험·표시 로그를 그대로 둔다).
  • UI 필수 요구(좌표 변환·바닥 높이, 가벼운 경로 조회, 행동 시점 보스 방향 기준 측면·배후, 막힌 지점, 키 공개 시점, 전투 시계)는 총괄이 ②-A에게 넘겨 계약 초안에 넣게 했다. 계약 수정본 2(2026-09-27)에서 모두 반영된 것을 확인했다.

8. 가짜 예비 동작 표시(총괄 결정, 2026-09-27)

계약 5.4절이 UI 설계에 맡긴 것이다. ②-A도 계약 의도와 맞다고 확인했다.

  • 계획 악보: 가짜 박을 속 빈 점으로 보인다. 박자를 계획 때 공개하는 예고형 원칙과 '같은 패턴은 같은 박자라 외운다'에 맞춘다.
  • 실행 박자 줄: 흘러오는 표식은 키가 있는 진짜 타격만 그린다. 가짜는 예비 동작 신호(판정선 반짝·소리)만 진짜와 같게 낸다(규칙의 bFake·TELEGRAPH fake=true로 구분한다). 가짜에는 키가 없어 표식을 그리면 진짜와 구별되고, UI가 없는 키를 만들어 넣을 수는 없다.
  • 이유: 사양의 가짜 예비 동작은 보스 몸짓 속임수이고, 가짜 예고 시작부터 다음 타격이 입력을 받으므로(계약 5.1절) 가짜에 누르면 그 타격이 '너무 이른 입력'으로 실패한다. 박자 줄과 악보를 읽는 사람은 피하고, 몸짓·소리만 보고 누르는 사람은 걸린다. 계약 초안 대조 뒤 추가 요청(사건 필드 키 표, 회피·막기 결과 값, 막기 누름 상태, 타격별 예고 ms, 구조체 필드, 행동 사거리 값, 구역 경계 각, ReachableCells 형식·비용)도 ②-A가 반영한다.

9.5 실제 연결(2026-09-27, 규칙·진행자 병합 bb96d03 위)

  1. 변환: BattleTutorialGuide::FromDirector가 FBattleTutorialStepView를 FBattleTutorialGuideView로 같은 칸 그대로 옮긴다. 컨트롤러는 공급자가 없으면 진행자 조회를 이 변환으로 쓰고, Bind에서 OnTutorialStep을 HandleTutorialNotice에 묶는다(Unbind에서 푼다).
  2. 계약 13.5절 인계
  • 1번 계획 화면 조건: 코드 변경 없이 맞다(Plan 비트 + 대기 + WaitingForPlan, UpdatePlanScreen). Step 비트에는 계획 화면이 닫혀 있고 Enter는 무시된다. 진행자가 비트를 시작할 때 ChoosePattern을 불러(계약 13.1절) 그 비트 동안 규칙은 이미 다음 라운드 WaitingForPlan이지만, 계획 화면은 Plan 비트로 막는다(시험 StepBeat).
  • 2번 미리보기 EndState: 코드 변경 없이 맞다(카드 글은 승리·패배만 따로 적는다). 튜토리얼 카드의 끝 상태는 WaitingForPattern이고 승패 줄이 없다(시험 PreviewEndState).
  • 3번 FindFill: 계획 없는 기록(bPlanned = false)은 건너뛴다. 바깥 패턴 선택(튜토리얼)에서는 이전 시도 채움을 하지 않고 지금 시도의 직전 라운드만 채운다(재도전하면 라운드와 단계 짝이 바뀐다, 총괄 확인). 찾기는 입력 로그만 받는 FBattlePlanDraft::FindFillInLogs로 나눠 시험한다(Celestiel.UI.PlanDraft.FillPlanned).
  • 5번 Step 비트의 Enter: 진행자 확인 알림으로만 오고 안내 줄은 Enter를 쓰지 않는다. 계획 화면이 없으니 컨트롤러는 무시한다(시험 StepBeat).
  1. 실제 진행자 흐름(시험 DirectorFlow): 흉내 공급자 없이 공터 튜토리얼 전투에서 1라운드 이동 안내 → 모두 대기로 두 번 실패 → 2라운드 다시 하기 → 3라운드 넘어감 글 + 리듬 패링.
