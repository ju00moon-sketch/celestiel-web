4. 성능 예산과 측정 계약

4.1 기준과 예산

  • 기준 PC: 현재 로컬 기록의 Ryzen 7 7800X3D, RTX 5070 Ti, 시스템 RAM 약31GiB. 드라이버·실제 VRAM·클럭/전원·디스플레이 모드를 실행 때 기록한다. 다른 PC 최소 사양까지 합격을 확대하지 않는다.
  • 총괄이 받은 준완성 조건: 패키지·이 PC·1080p·기본 품질, 흐름 A 평균 프레임 16.7ms 이하. 합격 경계는 16.7ms 그대로 쓰고, 1000/60=16.666…ms는 P95·초과 프레임 조정 목표로 구분한다. 평균 FPS들의 평균 대신 1000 / 평균 프레임 ms를 보고한다.
  • 조정 목표(제안): 환경 baseline GPU 평균 ≤12ms, Game Thread ≤6ms, Render Thread ≤6ms. 최종 GPU 목표 ≤14ms, 남은 2ms는 이후 주인공/그룸/천/VFX 통합 여유로 관리하고 프레임 한계 16.67ms까지 약2.67ms 여유를 둔다. CPU/Render/GPU는 겹치므로 서로 더하지 않는다.
  • 환경 GPU 내부의 초기 배분: geometry/base/Nanite 3.5ms, GI+반사 3.5ms, VSM 2ms, 대기/반투명 1ms, TSR+post 2ms = 12ms. 예산이지 실측값이 아니다. 실제 GPU 트리는 포함 관계·async overlap이 있어 상위/하위 패스나 Wait를 중복 합산하지 않는다.
  • 평균 외에 중앙값/P95/P99/최대, 16.67ms 초과 프레임 비율, 33.33ms 초과 횟수, VRAM·스트리밍·사용 가능 RAM 최저를 반드시 함께 낸다. P95≤16.67ms를 추가 조정 목표로 제안하되 기존 평균 기준을 몰래 바꾸지 않는다. 평균 통과여도 끊김이 많으면 문제를 따로 보고한다.
  • HAIR-1 H3의 작은 시험 GPU 값을 완성 긴 머리에 대입하지 않는다. HAIR-2·여주인공·새 전술 전투가 연결되면 최종 합산 장면을 다시 측정한다.

4.2 실행·재현 절차

2026-09-28 R3 준비의 구체적인 시간표·패키지 명령·판정·② 연결 계약은 R3 측정 준비를 따른다. V01~V09 카메라 진단을 실제 전술 흐름 A 합격으로 대신하지 않는다.

  1. ⑥ B 인계본 맵/자산/경로 SHA, 빌드 커밋, 품질·드라이버를 동결한다. 셰이더/PSO 준비 상태와 DDC 재사용 여부를 기록한다. 에디터 측정은 진단 참고값, 합격 근거는 별도 실행 또는 Development 패키지다. 최종은 패키지로 확인한다.
  2. 1080p 창/전체 화면을 고정한다. -ResX=1920 -ResY=1080, VSync off·프레임 제한 해제, TSR100%·DynamicRes off로 성능을 측정한다. 실제 ViewRect/내부 렌더 크기·표시 해상도·ScreenPercentage·AA값을 로그/Insights/캡처 근거에 남긴다. HighResShot 1920x1080만으로 1080p 실행을 입증하지 않는다. 카메라 종횡비 제한/레터박스도 확인한다.
  3. 첫 30초 이상 대기하고 Lumen/VSM/스트리밍이 안정된 뒤 동일 경로를 한 번 예열한다. 이후 고정 구간 60초 이상 ×3회. 별도의 최초 진입 1회도 기록하여 첫 실행 hitch를 숨기지 않는다. 60fps 제한/VSync는 별도 플레이 확인에서 다시 켜고 결과를 분리한다.
  4. 고정 카메라 경로는 시간 기반 transform/FOV/cut 배열로 만들고 매 실행 같은 위치·속도·컷 시각을 쓴다. B 후 (내부 경로)에 world cm·Pitch/Yaw/Roll·FOV·시간·SHA를 저장한다. 30/60/120fps에서도 절대 경과 시간으로 같은 경로를 계산한다. -UseFixedTimeStep 같은 게임 시간 고정으로 실제 성능을 좋게 보이게 하지 않는다.
  5. 캡처/카메라 구간과 실제 흐름 A 걷기/전투 구간을 분리한다. 단순 BugItGo는 Pawn 위치이지 카메라 위치가 아니므로 PCM의 실제 카메라를 기록한다. 고정 경로 재생기/카메라 시험 자산은 다음 배정에서 ⑤가 별도 Dev 장면에 만들고, 게임 코드 연결이 필요하면 ②에게 계약을 넘긴다. CV-RENDER-0에는 재생기 구현/실행이 포함되지 않는다.
  6. CSV로 Frame/Game/Render/GPU를 함께 수집한다. 표준 내장 csvprofile START/STOP·-csvGpuStats를 우선 사용한다. 로컬 UE CsvProfiler.cpp:1051,3136,5098에서 명령·끝 요약 헤더·GPU 플래그를 확인했다. -csvCaptureFrames는 boot capture라 초기 로딩을 정상 구간과 섞지 않도록 주의한다. 실제 CSV 열 이름은 첫 실행의 --list-columns로 확인해 분석기에 명시한다. CPU 열이 없는 경우 Insights를 확보해 부족을 보고하며 값을 추정하지 않는다.
  7. 병목 장면만 Unreal Insights CPU/GPU trace 및 GPU 패스 캡처로 추가 조사한다. 상세 프로파일/디버그 뷰 오버헤드가 있는 런은 합격용 CSV와 분리한다. stat unit, stat gpu, stat virtualshadowmap은 편의 진단이며 존재/지원 여부를 실행 때 확인한다.
  8. 경로 종료는 로그의 완료 사건으로 기다린다. 한 번에 여러 이동/전투 명령을 ExecCmds로 연달아 보내 시간이 흘렀다고 가정하지 않는다. 기존 패키지 진단의 exec 파일 검색 규칙을 따라 실행기 staging의 Binaries 경로를 쓰고 실제 명령 실행 로그를 확인한다. Python은 패키지 런타임에서 실행하지 않는다.

6. 작업 순서·메모리·시간·비용

RAM은 Windows 사용 가능 메모리 감소량의 추정이다. Private Bytes나 파일 크기를 그대로 시작 기준에 넣지 않는다. 모든 수치는 B 후 첫 실행에서 보정한다. ⑥ 준비 실행기의 capture/walk 추정8.5GiB를 보수적으로 참고했다.

무거운 실행은 한 번에 하나다. 실행 전 총괄에게 예상 시간·RAM을 알리고 배정받는다. 0.5~1초 간격으로 available 최소·시작 대비 감소·프로세스 트리 Working Set/Private Bytes 최고·시간을 기록한다. 사용 가능 RAM이 2GiB 미만이면 작업을 중단하고 정상 종료 요청한다. 저장 중 강제 종료로 손상시키지 않도록 저장 진입 전에도 확인하며, 여유가 부족하면 추가 단계를 시작하지 않고 총괄에게 앱 정리를 요청한다. 다른 앱 종료는 ⑤가 하지 않는다. 자식 ShaderCompileWorker를 포함한 시스템 감소량을 본다.

기본 배치 실행에는 -DisablePlugins=ModelContextProtocol,ToolsetRegistry,EditorToolset,UMGToolSet,AutomationTestToolset. -NoEOS는 HAIR 시험에서 Fab 초기화 오류가 있었으므로 기본값으로 추가하지 않는다. 네트워크 조회/설치/로그인/유료 기능을 요청하지 않고 환경 변경이 필요하면 먼저 보고한다.

  • 추가 금전/크레딧 비용: 0원, 외부 생성 0크레딧, Fab 구매 0, 다운로드/새 플러그인 설치 없음. 현재 설치된 UE와 기존 자산만 사용한다.
  • 실행 단계의 총 순차 자리 추정은 약2.5~4시간(⑥·③ 단계 포함, 큐 대기·첫 셰이더 제외). 아트 2단계·주인공·새 전투 통합은 별도 재측정과 일정이다. 실제 문제에 따라 재승인할 추가 작업을 구분한다.
  • 출력 예상 공간: CSV/로그/trace 1~5GiB, PNG 0.2~1GiB, 선택 영상 1~3GiB. 패키지·DDC는 기존 용량에서 증분을 먼저 확인하며 총 패키지 크기를 여기서 단정하지 않는다. 영상 인코더가 없으면 설치하지 않고 PNG 시퀀스로 인계한다.

오프라인 도구(지금 사용 가능)

Scripts/TechArt/prepare_campo_render_probe.py는 GLB JSON 삼각형/PNG 헤더 치수/원본 해시, 현재 V01~V09 경로와 원본 JSON, 맵·Source·Config·Scripts/Level 해시를 묶는다. 원본 GLB 폴더는 필수 --model-source 인자로 받으며 도구별 폴더 이름을 기본값으로 넣지 않는다. 실제 경로는 저장소 밖 인계 기록을 사용하고 폴더를 옮기거나 이름을 바꾸지 않는다. Config 내용·토큰은 출력하지 않는다. 입력을 변경하거나 다른 프로세스를 띄우지 않는다.


py -B Scripts/TechArt/prepare_campo_render_probe.py --model-source '<인계받은 GLB 폴더>' --output (내부 경로)

Scripts/TechArt/summarize_campo_render_csv.py는 UE CSV의 마지막 EVENTS 헤더/metadata를 처리하고 열을 명시하여 시간 구간·평균·P95/P99·초과 횟수를 낸다. FPS 평균, 잘못된 열 추측, 결측/NaN/0 GPU의 자동 합격을 피한다. GPU/CPU가 기록되지 않았으면 오류로 멈춘다. 통계 출력은 품질·해상도·전체 완료 판정이 아니다.

예열 종료 전 시작한 프레임은 경계를 걸쳐도 통째로 제외한다. 그다음 온전한 프레임부터 sampled_seconds가 요청 측정 시간을 채울 때까지 수집하며, 예열에서 초과한 시간을 측정 시간으로 세지 않는다. 마지막 채택 프레임은 잘라 짧게 만들지 않는다. 실제 measurement_start_seconds/measurement_end_seconds와 warmup_boundary_frame_ms를 기록한다. 비교 실행마다 실제 채택 시각과 경로 구간도 대조한다. 예열 경계가 길어 경로를 벗어나면 해당 결과를 성능 합격에 쓰지 않고 재촬영한다. 1ns 수치 오차 허용 외에 측정 꼬리가 부족하면 오류이며 결과 JSON을 쓰지 않는다.


# 캡처가 생긴 뒤 실제 열을 먼저 확인(지금은 엔진 캡처를 만들지 않음).
py -B Scripts/TechArt/summarize_campo_render_csv.py (내부 경로) --list-columns
# 아래 열 이름은 예시. --list-columns 결과의 실제 열로 지정.
py -B Scripts/TechArt/summarize_campo_render_csv.py (내부 경로) --frame-column FrameTime --game-column GameThreadTime --render-column RenderThreadTime --gpu-column GPUFrameTime --warmup-seconds 30 --duration-seconds 60 --output (내부 경로)
py -B -m unittest discover -s Scripts/TechArt/tests -p test_campo_render_probe.py -v
