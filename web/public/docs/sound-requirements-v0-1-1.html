1.2 항목 표기

  • ID: AMB-(환경음) SFX-CBT-(전투 효과음) SFX-UI-(UI 효과음) MUS-(음악) VO-(음성). 파일·에셋 이름에도 이 ID를 쓰되 생성 도구·서비스 이름은 넣지 않는다.
  • 재생 방식: 원샷(한 번 재생), 루프(끊김 없는 반복), 랜덤 원샷(변형 여러 개 중 무작위, 간격 무작위), MetaSound 후보(음높이·층·순번처럼 실행 중 값으로 소리가 달라져야 하는 것). 임포트·조립은 ⑤가 한다(7절, 총괄 결정 2026-09-28).
  • 근거 표시: [확정] = 사용자 확정에서 바로 나오는 필요, [지시] = 총괄 배정 문구에 든 항목, [승인] = 총괄이 답으로 정한 것(2026-09-28), [제안] = ⑦의 안이며 확인 대기. 확정·승인된 것은 다시 묻지 않는다.
  • 길이: 원샷은 소리 전체 길이(꼬리 포함), 루프는 한 바퀴 길이. 전투 박자 소리는 다음 박(800ms)이 오기 전에 끝나야 하므로 판정 소리도 500ms를 넘기지 않는다.

1.3 시간대와 장소 전제

  • 마을과 튜토리얼 들판의 확정 조명은 해 뜰 녘이다(마을 계획 v0.2 4.1 Q3, 튜토리얼 계획 6장). 환경음 기본 층은 새벽~아침(첫 새소리, 닭, 이슬 진 풀, 낮은 바람)으로 잡았다.
  • 총괄 답(Q1): 첫 안내문의 '해질녘'은 총괄 문구 오류였고, 별개 저녁 장면은 계획에 없다. 해질녘 층(AMB-17)은 '저녁 장면 없음, 필요 시 기획에서 추가'로 정리해 P2에 남긴다. 다시 묻지 않는다.
  • 시제품 전투 공간은 두 곳이다: 튜토리얼 숲 가장자리 공터(1인, 자경단원 목검)와 시험용 전투 공간 TacticsArena_P2(적 3종 + 시제품 보스, 블록아웃). 전투 효과음은 두 곳에서 같은 세트를 쓰고 무기 소재 변형만 바꾼다.

5. 배경음악(MUS)

5.1 방향 전제 [제안, 사용자 결정 대기 Q2]

  • 세계관은 창세력 1347년의 시골 마을에서 시작한다. 마을 컨셉은 초가·슬레이트 지붕, 예배당 종루, 우물, 텃밭·가축, 사이프러스로 온화한 남유럽 시골에 가깝다. 마을·들판 곡은 어쿠스틱 소편성(발현 현악 1~2, 목관 1, 손 타악, 낮은 현 패드)을 제안한다. 확정 장르·악기는 사용자 결정이다.
  • 전투 음악과 박자 줄의 충돌 방지: 규칙 시계는 타격 간격 800ms(= 75BPM 4분 박), 첫 예고 900ms, 후속 예고 600ms다. 음악에 강한 규칙적 4분 박이 있으면 박자 신호(3.1)와 헷갈릴 수 있다. 두 가지 안 중 하나를 고른다.
  • (가) 대응 구간(RESPONSE_START~LAST_RESPONSE_INPUT) 동안 타악·강박 층을 내리는 수직 층 구조(MetaSound·Quartz 후보). 판정 사건은 음악에 영향을 주지 않는다.
  • (나) 전투 곡 템포를 75BPM과 정수배가 아닌 값으로 두고 리듬 강조를 낮춘다(한 파일 루프, 구현 단순).
  • ⑦ 권고는 (가)다. 대응 구간이 규칙상 뚜렷한 사건 경계를 가지므로 층 전환 신호가 이미 있다. 시제품 첫 판에서는 (나)로 시작해 (가)로 올릴 수도 있다.
  • 슬로모션은 연출 시간만 느려지고 규칙 시계는 그대로다(8절). 음악은 슬로에 따라 늘어지지 않는다.

7. Unreal 재생 방식·연결 계획 초안

경계 [승인 Q4, 총괄 결정 2026-09-28]

  • ⑦ 사운드: 원본(48kHz WAV)과 설정 값(루프 지점·감쇠 곡선 제안·Sound Class 제안·볼륨 기준)을 인계 묶음으로 넘긴다(8.2절).
  • ⑤ 테크니컬 아트: Unreal 임포트·Sound Class·감쇠·MetaSound 조립.
  • ②-B: BattleBeatSound 코드 교체. 방식은 7.4절 두 갈래 중 (B) 데이터 에셋 매핑을 기본 제안으로 하되 ②-B가 최종 판단한다.
  • 인계 형식은 ⑤와 한 번 맞춘 뒤 8.2절에 고정한다. 아래 7.2~7.5는 그 인계에 실을 설정 값의 초안이다.

7.1 엔진 상태(2026-09-28 확인)

  • 프로젝트 Config/DefaultEngine.ini: AudioSampleRate=48000, 콜백 버퍼 1024, 소스 워커 4. 원본은 48kHz WAV로 맞춘다.
  • 엔진 5.8 동봉 플러그인 확인(Engine/Plugins/Runtime의 .uplugin EnabledByDefault): MetaSound 1.0 기본 켜짐, Synthesis 1.1 기본 켜짐, AudioModulation 2.0 기본 꺼짐, WaveTable 기본 꺼짐. MetaSound는 .uproject 변경 없이 쓸 수 있다. AudioModulation 등 기본 꺼진 플러그인을 켜는 것은 프로젝트 설정 변경이라 총괄·사용자 승인 대상이다.
  • Content/에 오디오 폴더는 아직 없다(Art·Collections·Data·Dev·Developers·Input·Maps).

7.2 원본 형식과 폴더 [승인 Q7, 총괄 2026-09-28]

  • 원본: WAV 48kHz, 24bit(효과음·음성 모노, 환경음 층·음악 스테레오). 루프는 끊김 없는 경계로 잘라 낸다.
  • 파일 이름: <분류>_<번호>_<이름>[_<소재>][_<변형>]_v<판>.wav. 예 SFX_CBT_02_Hit_v01.wav, SFX_CBT_07_Impact_Wood_a_v01.wav. 소재 접미사(_Wood·_Metal·_Body·_Stone·_BossTemp)는 임시 소재라 정식 결정 뒤 교체 가능하게 둔 것이다(Q5). 변형은 _a·_b·_c.
  • 파일명·에셋명·메타데이터(WAV 태그·에셋 설명 포함)에 생성 도구·서비스 이름을 넣지 않는다. 원본 출처는 저장소 밖 로컬 기록에만 둔다.
  • 제작 원본 보관: D:\GameDevelop\Unreal\ArtSource\Audio\<분류>\(기존 ArtSource 폴더 아래, 저장소 밖). 저장소에는 임포트된 에셋만.
  • Unreal 에셋 폴더: Content/Audio/{Ambience,Combat,UI,Music,Voice}/, 공통 설정 Content/Audio/_Setup/(Sound Class·Submix·Attenuation·Concurrency·데이터 에셋).
  • 에셋 접두(제안, 프로젝트가 SM_·T_·MI_·M_ 표준 접두를 쓰는 것에 맞춤): SW_(Sound Wave) MS_(MetaSound Source) MSP_(MetaSound Patch) SC_(Sound Class) SMX_(Submix) ATT_(Attenuation) SCC_(Concurrency) DA_(데이터 에셋). ⑤가 관행에 맞춰 바꿀 수 있다.

7.4 기존 코드 교체 지점

  • Source/Celestiel/UI/BattleBeatSound.h/.cpp: 헤더 주석대로 "사운드 에셋으로 바꿀 자리는 여기 한 곳". BattleBeatSound::Play(WorldContext, Cue, Index)가 UBattleBeatSoundWave(절차 생성 파형, 끝을 알리는 생성기)를 만들어 PlaySound2D로 튼다.
  • 교체 방향 두 가지(②-B 소유 코드이므로 ⑦은 제안만, 수정은 ②-B):
  • (A) Play가 큐·순번에 맞는 USoundBase 에셋(또는 MetaSound Source에 순번 파라미터)을 찾아 PlaySound2D. 에셋 없으면 지금 사인파로 되돌아가는 대비책 유지 → 화면 없는 시험은 지금처럼 아무것도 하지 않음.
  • (B) 기본 제안(총괄, ②-B 최종 판단): 데이터 에셋 하나(Content/Audio/_Setup/DA_BattleBeatCues)에 5신호를 매핑해 코드가 경로 문자열을 갖지 않게 한다. 시험 Tests/UI/BattleBeatBarTests.cpp는 파형 생성 함수(MakeSamples·MakePcm)를 시험하므로 에셋 경로가 바뀌어도 영향이 적을 것으로 보이나, 실제 영향은 ②-B 확인.
  • CT-5 검토에서 나온 '절차 생성 소스 해제 경로' 결함(P2-01, IsFinished 생성기로 수정)은 에셋 재생으로 바꾸면 사라지는 종류의 문제다. 다만 에셋 교체가 그 수정을 대신한다고 보지 않고, 교체 뒤 같은 프로브(2초 뒤 활성 소스 0)를 다시 돈다.

8. 생성 계획과 인계(승인 전 생성 없음)

8.1 생성 계획

  • 외부 생성 서비스 MCP는 현재 미인증 상태다(이 세션에 인증 시작 도구만 노출). 인증은 사용자가 /mcp로 직접 한다. 인증 뒤 도구 목록·크레딧 잔액·단가를 확인해 총괄에게 보고하고, P0 박자 신호 5종의 생성 계획(후보 수·예상 크레딧)을 이 절에 적어 승인(Q8)을 기다린다. 크레딧 단가를 아직 몰라 이 판에는 건수·비용 추정을 적지 않는다.
  • 생성 묶음 순서 제안: ① P0 박자 신호 5종(SFX-CBT-01~05, 후보 2~3개씩 만들어 비교) → ② P0 물리 타격·예고·보스(SFX-CBT-07·08·12·14·17·18·20·21·23·24) → ③ P0 UI 6종·전투·보스 루프·승리 스팅어 → ④ P1 환경음 층·점 음원 → ⑤ P1 나머지. 음악(MUS)은 Q2 답 뒤, 발성(VO)은 Q3 답 뒤에만 넣는다.
  • 비교 확인 규칙: 생성 결과는 실행·다운로드만으로 '통과'라 부르지 않는다. 같은 신호를 기존 사인파와 같은 시각에 놓고 들어 보고(②-B 프로브 또는 화면 있는 PIE), 대응 구간에서 신호가 묻히지 않는지 확인한 뒤에만 채택한다. 확인하지 않은 항목은 '미검증'으로 적는다.
