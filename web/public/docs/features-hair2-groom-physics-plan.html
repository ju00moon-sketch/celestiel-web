승인된 묶음 고정 방식: 형태 확정 뒤 ④가 내보내기 사본에서 기존 ID3을 끈 위치에서 나눈다. 끈 앞 ID3과 끈 뒤 ID4의 접점·접선·굵기를 보존하고, ⑤가 원본을 임의로 나누지 않는다. 상세 계약은 2.1절이다. 연속 가닥의 근위부 강성만 높이는 방식은 분할 인계가 불가능할 때 총괄과 다시 비교할 대안이며, 끈 고정을 보장하지 않는다.

현재 코드의 Ornament에는 11개 링크+끝 십자가가 한 메시에 포함되어 있다. 그대로 한 강체로 흔들면 실제 사슬 운동이 아니다. 최종 장식 제작 배정 전에는 참고 자료로만 쓰고, 시뮬레이션은 Dev 대체물로 검증한다. 공유 SK_Mannequin 본을 덮어쓰거나 장식 본을 억지로 추가하지 않는다. 별도 장식 리그를 캐릭터 소켓에 붙이는 안을 기본으로 한다.

2.1 ④ → ⑤ 최종 내보내기 계약

형태 승인 뒤의 출력 계약이다. 기존 원본·합쳐진 장식을 덮어쓰거나 승인 없이 채택·분리하지 않는다. 실제 수량은 승인 파일 측정값으로 채우며 생성기의 guide 기본420을 완료 수량으로 쓰지 않는다.

  • 각 원본 ID3 렌더 가닥과 가이드를 모두 한 번씩 나눈다. 출력 합계는 렌더 R0+R1+R2+2R3, guide G0+G1+G2+2G3다. 수 증가가 머리 밀도 증가를 뜻하지 않는다. 끈에 도달하지 않거나 두 번 교차하거나 길이0인 가닥은 자동 추정으로 넘기지 않고 ID 목록으로 거부/확인한다. 각 렌더 그룹에 유효 guide가 있어야 하며 수·분포·최대 길이를 별도 기록한다.
  • POLY 곡선, root→tip 순서, 비순환. HGR 입력은 curve-domain INT groom_group_id, groom_guide(0/1), groom_id, FLOAT2 groom_root_uv, point-domain FLOAT radius(cm). ABC에서는 H3 규격의 groom_group_id·groom_guide·groom_root_uv와 widths 등을 대조한다. ABC width는 지름=2×radius다. 그룹 이름은 manifest에서 관리한다.
  • 분할 후 ID는 전체에서 고유하게 주고, manifest에 source_curve_id, 앞/뒤 새 ID, guide 여부, source 길이 구간, 절단점·접선·radius를 남긴다. 곡선 중간에 절단점을 삽입하면 그 위치/보간도 기록한다. 두 구간을 합친 중심선·굵기가 승인 원본과 같은지 수치와 확대 렌더로 검사한다. 가이드 감축·새 모양 생성은 하지 않는다.
  • 인계 manifest에는 그룹별 R/G/점 수, GroupID→각 Groom의 GroupIndex, root의 대상 메시 SHA·LOD·삼각형/삼각형 내 좌표·UV0, 본/pose 판, 좌표 변환, 끈 기준 transform을 넣는다. 두피 UV seam은 vertex UV 평균이 아닌 해당 root의 삼각형 UV로 정한다.
  • 바인딩 구현 제안: Main(ID0~3)은 Quinn 스킨 두피에, Ponytail(ID4)은 같은 pose의 작은 스킨 끈 기준면에 각각 Groom+Binding으로 연결한다. 끈 기준면은 실제 끈 위치에서 head를 추종하며 렌더에는 보이지 않는다. 포니테일 root를 가까운 실제 두피로 재투영하지 않는다. 별도 Groom 안에서는 ID4의 GroupIndex가0일 수 있어 원본 ID와 혼동하지 않는다. 두 컴포넌트 비용도 1.2ms 목표에 포함한다.
  • 위 끈 기준면은 ④에게 추가로 필요한 인계 항목이다. 제안 이름 SK_FP_HairTieAnchor, 완전한 공통 뼈대·같은 reference pose·UV0·필요 LOD와 root 대응을 받는다. 실제 기준면/스킨 방식은 첫 인계 때 확인한다. 최종 머리·두피가 나오기 전에는 어느 바인딩도 실행하지 않는다. 기준면 없이 임의 두피 바인딩으로 대체하지 않는다.
  • groom_root_uv가 끈 기준면을 뜻하는 ID4는 색 조회 좌표와 구분한다. 원래 색 조회 좌표·끈 위치에서의 실제 색/폭을 manifest에 보존하고 승인 색 manifest에 맞춰 재질을 검증한다. 분할 때문에 root darkening이 다시 시작하거나 매듭에 색 띠가 생기면 해결 전 인계 통과로 보지 않는다.
  • 카드도 Main/포니테일 분리와 GroupIndex/LODIndex를 따라야 한다. 카드 메시·atlas 및 나침반·사슬·십자가·찢어진 리본은 ④ 원본, UE 연결·Chaos 설정은 ⑤ 담당이다. 장식 원본 제작 시점은 총괄의 후속 배정을 따른다.

  • H3 주의점 유지: 에셋/컴포넌트 물리 구조체를 통째로 복사하지 않음, simulation_settings.override_settings=True 후 공통 필드만 복사. 에셋 물리 setter 후 DDC/보간 재빌드·틱 완료를 확인하고 저장한다. H3의 enable_global_interpolation=True 재빌드 경로는 완성 머리의 RBF 비용까지 측정한다.

리본·사슬의 첫 시험

  • 리본: 상단 고정부 MaxDistance0, 0~2cm 영역으로 부드럽게 자유 영역으로 전이. 질량 면밀도 .1~.25kg/m², 감쇠 .2~.5, 충돌 두께 .2~.5cm를 초기 후보로 둔다. 나머지 max distance는 실제 꼬리 길이/가동 범위로 정한다. Chaos Cloth 자산의 실제 단위·속성명이 맞는지 실행 준비에서 확인하며 Groom 감쇠 숫자와 같은 물성으로 보지 않는다. 찢어진 실루엣을 유지하고 단순 simulation mesh→고해상도 render mesh 매핑을 검사한다. 자가 충돌은 먼저 꺼서 몸 충돌을 검증하고, 접힘에서 뒤집힘이 남으면 켜서 비용을 비교한다.
  • 사슬: 11개 보이는 링크와 물리 body 수는 별개다. 최초 4~6개 proxy body, 각 body .002~.01kg, 회전 damping1~3s⁻¹, Swing20~35°·Twist10~20° 제한 후보. 옆 body 충돌은 끄고 머리/목 proxy와 충돌, 첫 body는 kinematic 고정. 완성 체인 길이가 짧으므로 마지막 펜던트 질량을 별도 기록한다. 링크를 삭제하거나 장식 모양을 바꾸지 않는다.
  • RigidBody AnimGraph는 별도 장식 SkeletalMesh의 Copy Pose/앵커 추종 뒤 적용한다. Leader Pose만으로 follower의 독립 물리가 실행된다고 가정하지 않는다. Gameplay ragdoll·Damage/Overlap에는 참여시키지 않는다. 실제 캐릭터 BP/AnimBP 연결은 ②와 계약 후 진행한다.
  • Groom ↔ Cloth ↔ 사슬의 상호 충돌이 자동으로 연결된다고 가정하지 않는다. 1차는 공통 몸 proxy·고정부 위치·안전 간격으로 분리, 상호 관통이 남으면 선택적인 충돌 연결을 추가 검토한다. 서로 다른 솔버 사이 양방향 결합은 기본 범위 밖이다.

4. Quinn 바인딩·임포트·충돌

4.1 인계에 필요한 것

  1. 사용자 승인 .blend 버전/해시, 실제 생성 인자·seed·색 명세. ④가 승인본 실제 색/인자를 manifest에 쓰고 HAIR_COLOR_SPEC.json을 맞춘다. ⑤는 그 manifest만 사용한다. 수량·분할 대응·root 계약은 2.1절을 따른다.
  2. CHAR-MOD-1의 Quinn 호환 스킨된 머리와 같은 pose·UV0·LOD의 두피 FBX, Skeleton/본 계층·rest matrices·weights·두피 UV0와 LOD 목록. FP_H2_Scalp의 UVScalp를 출력 UV0에 매핑한다. 이 인계 전에는 바인딩을 실행하지 않는다. 기존 정적 groom_ref_export.py 결과만으로 Skinning Binding을 통과시키지 않는다. 포니테일에는 2.1절 끈 기준면도 필요하다.
  3. 같은 pose/원점의 ABC(또는 POLY Hair Curves→HGR→ABC), root UV·group·guide·width·ID. HGR/manifest 둘 중 하나라도 기존 파일이면 거부하는 35d0293 exporter를 사용한다. HGR1은 group name/카드 필터 문자열을 출력하지 않으므로 별도 표를 인계한다.
  4. 카드 제작 단계에서만 카드 FBX·atlas/채널표·GroupIndex/LODIndex·가이드 대응. 가죽/장식/리본은 최종 원본 제작 배정 후 고정부/피벗/chain 순서/cloth 고정 영역을 별도로 받는다.

Quinn FBX는 약1.802m 기준이고 여주인공 체형을 임의로 Quinn 키로 늘리지 않는다. ④가 맞춘 실제 캐릭터 rest pose가 바인딩 기준이다. 목/머리 본 이름·계층을 보존하고 head와 neck_01/02를 확인한다. root가 Blender armature 객체로 표시되는 것을 추가 본 생성으로 오해하지 않는다.

현재 원본 좌표는 cm·+X정면·+Y인물 왼쪽, 예전 참조 exporter는 UE 변환 X,-Y,Z를 제안한다. H3의 작은 시험 X,Y,Z를 그대로 쓰지 않는다. 축 맵은 CU1에서 확정한 공통 Skeleton/두피의 로컬 축·비대칭 기준점과 대조해 한 번만 적용한다. 배우 정면+X와 스킨 메시 로컬 정면(+X 또는 엔진 마네킹의+Y)은 구분하고, CHAR-UE의 생성자 yaw 보정을 그룸에 중복 적용하지 않는다. 출력이 target mesh 로컬 좌표/UE cm라면 Groom Rotation0/Scale1로 시작하고 실제 길이·지름을 검증한다. 음수/비균일 객체 배율을 남기지 않는다.

4.2 UE 조립과 검증 순서

  • 최초 자산은 /Game/Dev/HAIR2/: GR_FP_Hair_Main_Test·GR_FP_Hair_Ponytail_Test, 각각의 GB_ Binding, SK_FP_Scalp_Test·SK_FP_HairTieAnchor_Test, PA_FP_HairCollision_Test, M_FP_HairStrands_Test, 카드/장식 시험 자산. 최종 외형 승인 뒤 /Game/Art/Characters/FemaleProtagonist/Hair/로 인계한다. 지금 어느 자산도 생성하지 않는다.
  • Main은 최종 두피, Ponytail은 끈 기준면을 TargetSkeletalMesh로 GroomBindingType=SkeletalMesh 생성한다. 같은 면 위에 만든 Groom이면 SourceSkeletalMesh는 불필요; 다른 면→목표 면 변환 때만 source와 MatchingSection을 명시한다. NumInterpolationPoints는 설치본 기본값을 기록하고 시작한다. 원래 root 대상 삼각형인지 확인한다.
  • 다중 LOD마다 binding의 projection/root mapping을 검사한다. UV seam 부근 root UV는 삼각형/loop 기준으로 대조한다. 현재 생성기는 vertex별 loop UV 평균을 만들므로 seam을 가로지른 평균이 유효 UV인지를 실제 인계본에서 확인해야 한다.
  • GroomComponent는 변형되는 두피 SkeletalMeshComponent에 붙여 BindingAsset을 지정한다. 단순 head socket 부착만 확인하고 Skinning Binding 성공이라고 하지 않는다. 두피가 몸 Leader Pose를 따르면 숨김 상태에서도 본 갱신과 Skin Cache가 유지되는지 검사한다. head에만100% 스킨된 두피라도 몸통 회전·목 동작 시 같은 transform 체인을 따라야 한다.
  • 기존 skeleton/physics를 변경하지 않고 캐릭터 뼈대와 맞는 전용 hair collision PhysicsAsset을 쓴다. Head 구/타원체 후보·neck capsule·양 어깨/상완·윗가슴/등 8~12개 단순 충돌체부터. 긴 머리 길이에 따라 spine 하단을 추가한다. target 두피에 필요한 spine/clavicle 본이 없으면 full-body component의 PhysicsAsset 공급 경로를 검증하거나 완전한 공통 뼈대 두피 인계를 받는다.
  • Collision Query/Gameplay는 비활성, 헤어/천/장식 전용. 메시 삼각형 전체 복잡 충돌로 대체하지 않는다. 망토가 생기면 몸 proxy와 망토 외형 사이의 실제 간격을 다시 확인한다.
  • 모발 재질: Hair/Main Strands 사용 표시, 모발 방향/roughness·색을 정면/역광에서 비교. Blender absorption 수치를 UE BaseColor에 직접 복사하지 않는다. Nanite 표시는 Groom에 필요하지 않다. Nanite를 쓰는 고정 장식 메시가 있으면 해당 부모 재질의 set_blockout_nanite_usage.py --check 포함 여부를 확인한다.
  • 슬롯: Groom Editor Materials+그룹 Rendering 연결→저장·재로드를 검증한다. Python에서 보호된 MaterialSlotName을 강제로 쓰지 않는다. 동일 Hair_Main을 공유하는 그룹도 GroupID/GroupIndex/SlotIndex 표를 남긴다. 카드 material slot은 별도로 확인한다.

5. 카드 LOD·거리 전환

HairCardGenerator 비활성 유지. 기존 조사 추정 다운로드2.7~3.2GB·임시/설치 여유10~12GB는 사용자 승인 전 실행하지 않는다. 이번 추가 비용0원이다. 가닥 LOD 감축으로 카드 요구사항을 대신하지 않는다.

승인 경로는 ④가 승인 곡선으로 카드 메시·텍스처를 제작하고 ⑤가 Imported LOD로 연결·검증하는 것이다. UE ImportedMesh + 그룹/LOD 매핑을 사용하며 ⑤는 채널 규격·임포트/변형·측정 도구를 제공한다. hair_guides.py·hair_cards.py에는 이전 시트A/낮은 묶음의 원본이 있으므로 새 도면 확정본으로 혼동하거나 그대로 재사용하지 않는다.

설치본 GroomAssetCards.h의 ImportedMesh, GuideType(GuideBased/Generated), GroupIndex, LODIndex와 GroomAssetInterpolation.h의 GeometryType, ScreenSize, BindingType, Simulation을 사용한다. LOD별 Imported 카드가 실제 가이드를 따라 변형되는지 검증해야 한다. UI/API 노출·다중 그룹 저장은 H3에서 미검증이다.

  • 첫 atlas 계약은 UE Card Default(Layout0)와 맞춘다: Depth(R8), Coverage(R8), Tangent(RGB8), Attributes(RootUV/CoordU/Seed), Material(Color/Roughness), Auxiliary. 채널 packing·방향 부호는 설치본/재질과 대조해 작은 카드 한 장으로 먼저 시험한다. 옛 투명 PNG 한 장을 넣고 완성 카드로 처리하지 않는다.
  • 승인 곡선·밀도·굵기·실루엣·색을 보존한다. LOD0 CurveDecimation/VertexDecimation1부터 시작, 실제 UE의 점 재샘플링 결과는 원본 점 수와 따로 기록한다. 원본 감면/텍스처 축소는 하지 않는다. 카드 atlas도 낮은 해상도부터 강제로 품질을 맞추지 않고 앞머리/실루엣의 픽셀 밀도로 정한다.

6. 성능 예산 — CV의 2ms 여유 안에서

HAIR-2 합GPU1.2ms 이하는 총괄 승인된 조정 목표이며 합격 실측값이 아니다. 세부 배분은 실측 뒤 보정한다. 남는 .8ms는 heroine-ue-assembly-plan.md와 연결한다. 최종 합격은 CV 승인 조건(패키지·이 PC·1080p·기본 품질·평균16.7ms 이하)을 따른다. TSR100%부터, 하향은 사용자 확인 뒤다.

실제 긴 머리가 예산을 넘으면 우선 group/guide·solver·bounds·overdraw·그림자 갱신 원인을 보고하고 카드를 비교한다. 자동 원본 감면·가닥 굵기/색 변경·그림자 끄기·모델 품질 저하는 하지 않는다. 배경12ms+최종14ms 여유를 머리만으로 모두 소비하지 않는다. 향후 여러 캐릭터가 같은 머리를 쓰면 동시 개체 수에 따라 별도 재측정한다.

측정은 고정 pose/움직임·동일 실제1080p·조명·카메라에서 머리 없음 → 바인딩만/물리OFF → Groom 물리ON → 리본/사슬ON → Cards 순으로 각60초×3회, warmup30초 이상. Hair 상위/하위 GPU 패스를 중복 합산하지 않고 전체 GPU 차이·프레임 분포도 보고한다. Shadow/Lumen/Skincache/Niagara·CPU Physics를 함께 본다. 30fps 제한 비교는 동작 검증용, 성능 여유 측정은 제한 없이 분리한다. 가까운 얼굴과 실제 탐험/전투 카메라를 각각 기록한다.
