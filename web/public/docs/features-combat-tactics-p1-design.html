전장 전술 전투 첫 시제품(CT-P1) 작업 설계

  • 기준 사양: docs/features/combat-tactics-v0.3.md (승인본, 2026-09-26)
  • 이어서 쓰는 기존 기준: 규칙 docs/features/combat-reactive-prototype.md(RT-v0.3+D8), M1~M3 설계 문서, 수치 docs/BALANCE_LOG.md
  • 작성: ① 총괄. 세부 구현은 각 담당이 판단하고, 공유 계약·구조를 바꿔야 하면 총괄과 먼저 조율한다.

목표와 범위

임시 5인(A~E), 이름 없는 보스 1종(패턴 4개), 지름 30m 전투 공간 1개로 아래가 재미있는지 플레이해서 확인한다.

  • 칸 없는 이동: 라운드마다 이동 한 번 + 행동 하나
  • 위치 효과 네 가지: 예고 범위, 거리·사거리(가림 포함), 측면·배후, 아군 거리(엄호·연계)
  • 리듬 패링, 회피, 막기, 치명타

범위 밖: 천족 레이드·스쿨드 전용 패턴·레이드 3단계, 직업·포지션 확정, 정식 캐릭터 모델, 브레이크·그로기, 헤어 작업(HAIR-1).

1. 구조 원칙

  • 규칙은 지금처럼 결정적이다.
  • 위치는 cm 정수로 두고, 거리·각도 판정은 정해진 순서로 계산한다.
  • 치명타와 무작위 키는 시드 고정 난수를 쓴다(전투 시드·라운드·타격 순번에서 유도).
  • 같은 시드·계획·입력이면 결과가 바이트 단위로 같아야 한다.
  • 전투 공간의 장애물(기둥·바위)은 규칙이 읽는 데이터(2D 원·상자, cm 정수)로 정의한다. 레벨 메시는 그 데이터에 맞춰 놓는다. 물리 충돌 판정에 기대지 않는다.
  • 기존 기록 S1~S4는 '이동 없음' 모드에서 지금 기록과 바이트 단위로 같아야 한다(회귀 시험).
  • UI는 규칙 계층이 낸 미리보기 결과만 그린다. UI가 판정을 따로 계산하지 않는다.

2. 공유 계약(CT-0)

②-A가 초안을 쓰고, 총괄이 검토하며, ②-B·⑥이 쓰는 쪽에서 확인한다. 계약이 승인되기 전에는 계약에 걸린 코드를 쓰지 않는다. 문서는 docs/features/combat-tactics-p1-contract.md에 둔다.

번호내용

K-T2 이동 명령과 결과목표 자리, 경로 길이, 겹침 해소(계획 순서 우선) 결과, 도달 불가 사유

5. CT-P1 완료 조건

  • 계획 단계
  • 5인을 이동 원 안에 끌어 놓으면 미리보기가 바로 바뀐다(경로 겹침 결과 포함).
  • 예고 범위 세 색과 '회피 불가' 표시, 몇 타 미리보기, 사거리·가림, 측면·배후, 엄호·연계 선, 박자 악보가 보인다.
  • 실행 단계
  • 5인이 동시에 움직이고, 보스 패턴 4개가 예고대로 나온다.
  • 무작위 키 패링, 회피, 막기, 엄호 강제 이동, 치명타, 경직 게이지가 사양대로 적용된다.
  • 재현
  • 같은 시드·계획·입력이면 결과가 바이트 단위로 같다. 새 시나리오는 패턴마다 하나 이상, 최소 4개다.
  • S1~S4는 '이동 없음' 모드에서 기존 기록과 바이트 단위로 같다.
  • 검증: 빌드 경고 0, 자동 테스트 전부 통과, PIE 30·60fps에서 판정 동일, 패키지 실행 확인(docs/VERIFICATION.md 기준).
  • 사용자가 플레이하고 피드백을 준다. 수치 조정은 docs/BALANCE_LOG.md에 남긴다(D2).

6. 작업 경로와 잠금

  • 브랜치·worktree는 ③이 이 문서와 승인 사양을 커밋한 뒤의 feature/reactive-combat-m1 HEAD에서 만든다(②-A 규칙, ②-B UI). 이름과 통합 방식은 docs/VERIFICATION.md 5절에 따라 ③이 정한다.
  • worktree 안의 UBT 빌드와 화면 없는 자동 테스트는 docs/AGENT_WORKFLOW.md 4절의 예외대로 한다(-DisablePlugins=…, -WaitMutex).
  • 메모리 규칙: 시작은 여유가 '예상 최고 + 3GB' 이상일 때, 여유가 2GB 밑이면 멈춘다. 무거운 작업의 순서는 총괄이 배정한다.
  • 에셋(.uasset·.umap) 작업과 PIE 검증은 주 작업 폴더에서 Unreal 실행 잠금을 받아 한다.

7. 금지·주의

  • 승인 사양 밖의 규칙을 넣지 않는다. 사양에 없는 판단이 필요하면 총괄에게 묻는다.
  • 천족 레이드·스쿨드 전용 패턴·최종전 맵은 만들지 않는다(본편 범위 결정, 2026-09-25).
  • 확정 전 직업·포지션을 코드에 넣지 않는다. 방패는 시제품 한정 표시다.
  • ⑤의 HAIR-1 작업물(/Game/Dev/HAIR1/, Celestiel.uproject의 헤어 플러그인 변경, Scripts/TechArt/ 헤어 도구, docs/HAIR1_GROOM_HANDOFF.md)은 건드리지 않는다.
