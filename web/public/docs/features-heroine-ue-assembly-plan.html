2.1.1 채택 체형의 정적 출력 사본

  • 편집용 셰이프 키·래티스는 작업 원본에 보존한다. 현재 다리 비교 사본은 Basis_v3f·LegLength_10mm·LegLength_15mm 키를 가진다. 래티스를 새로 추가한 것은 아니다. 원형/후보별 rest 리그가 다르므로 키만 전환해서 다른 리그와 섞지 않는다.
  • 사용자가 길이안을 고르면 별도 내보내기 사본에서 그 정적 형태만 bake한다. 키 값을 본 rest 변경 대신 사용하거나, 이미 bake한 형태에 같은 Morph를 다시 적용하지 않는다. 최신 몸 메시·대응 리그·정규화된 가중치·이음 대응을 하나의 버전으로 고정한다.
  • v002는 기존 계약의 FBX 14개(몸11 + 머리1 + 두피1 + 속옷1)와 Textures, parts/skeleton/body_parts/sockets/capture manifest를 한 출력 묶음으로 검사한다. 추가 끈 기준면·그룸은 승인된 별도 HairBundle로 명시하며 14개 목록에 숨겨 끼워 넣지 않는다. 기존 v001을 덮어쓰지 않는다.
  • 얼굴·헤어 원본은 변경하지 않는다. 얼굴 출력 사본은 파일 전체 SHA만이 아니라 승인 기하·UV·텍스처의 불변을 대조한다. 같은 공통 rest pose에 연결할 수 없으면 별도 차이를 보고하며 얼굴을 몰래 재조형하지 않는다.
  • 표면 다리 시작과 고관절·무릎·발목 및 허벅지/종아리 길이를 구분한다. 키·머리·발바닥·v3f 보호 부위, 기존 Z88 단면의 3.2cm 고랑 정의와 같은 정점 대응을 유지한다. 수치/정지 외형/움직임/이음/Unreal을 다섯 판정으로 남긴다.
  • 동작 보정용 Morph Target을 채택하면 형태 bake와 별도 목록·구동 조건을 manifest에 남긴다. Unreal 임포트·동작 시 실제 활성 값·골반/허벅지/모듈 경계·저장/재로드를 따로 검증한다. 현재 비교에서 corrective Morph를 구현하거나 Unreal 검증한 것은 아니다.

현재 상태: 키·후보별 리그 사본과 Blender 비교/81자세 검사는 완료, 길이안 최종 선택·v002 bake/FBX 출력·Unreal 임포트는 미실행이다. 기존 고관절 압축 주름과 목 겹침/재질 경계는 남아 있어 원본 불변과 자연스러운 최종 조립 합격을 구분한다.

2.2 기본 애니메이션 재사용

설치 템플릿의 Anims/Unarmed/에 ABP_Unarmed, BS_Idle_Walk_Run, MM_Idle, Walk/Jog 방향 클립, Jump/MM_Jump가 있다. 최초는 Idle·Walk/Jog·Jump 클립 재사용을 검토한다. 템플릿 AnimBP가 이 프로젝트 폰·IK·입력에 곧바로 맞는다고 가정하지 않는다.

⑤는 클립/스켈레톤·발 접촉을 검증하고 외형 시험용 AnimBP를 준비한다. ②가 실제 Pawn의 속도·지상/공중 상태를 연결한다. Root Motion으로 기존 이동을 중복 구동하지 않으며 이동·피격 사건을 새 AnimNotify에 맡기지 않는다. 500cm/s에서 발 미끄러짐은 클립/재생률·리타깃 문제로 측정하고 이동 속도를 임의로 바꾸지 않는다. 머리·얼굴은 첫 조립에서 승인된 정적 표정이며 새로운 얼굴 애니메이션은 범위 밖이다.

3. 모듈 조립·Look 데이터·몸 가림

3.1 한 번의 몸 포즈 계산과 의상 6슬롯

실제 Pawn에서는 기존 ACharacter::GetMesh()를 BodyTorso Leader로 쓰는 계약을 총괄이 승인했다. 구현은 필드 플레이어 담당 ②-B가 맡는다. Head·나머지 몸10개·일반 의상은 같은 canonical Skeleton의 Leader Pose follower다. 독립 물리가 없는 follower는 포즈를 다시 평가하지 않는다. 정적 장신구/무기는 승인 소켓에 붙인다. 별도의 두 번째 CharacterMovement·캡슐·플레이어 Pawn은 만들지 않는다.

Copy Pose는 Leader의 본 갱신 뒤에 실행하도록 tick prerequisite를 둔다. Leader Pose follower에는 독립 천 시뮬레이션을 기대하지 않는다. BindClothToLeaderPoseComponent()는 동일 메시 전제이므로 몸통과 망토 연결에 쓰지 않는다. Mesh Merge는 첫 판에서 하지 않는다. 교체·천·이음·재질 유지가 검증된 뒤 실제 draw call/CPU 병목이 있을 때만 비교한다. Leader Pose는 본 계산을 줄일 뿐 각 부품의 draw call을 합치지 않는다.

머리 포함 몸12개에 의상 조각을 더하면 모든 부위를 보일 때 대략20개 이상의 스킨 컴포넌트가 가능하다. 완전히 덮인 부품의 가시성에 따라 실제 활성 수는 줄어든다. 정확한 컴포넌트·활성 섹션·draw call 수를 Look별로 기록하고 임의의 6슬롯 제한과 혼동하지 않는다.

3.2 데이터와 실패 보존

기존 계획의 PDA_FP_VisualPart, PDA_FP_BodySet, PDA_FP_VisualLook 구조를 따른다. 자산 후보는 DA_FP_Part_<Slot>_<Variant>, DA_FP_Look_Default, DA_FP_Look_SwapTest다. 여기서 PDA는 제안된 Data Asset 클래스이며 현재 구현됐다는 뜻이 아니다. 클래스/실행 로직 구현은 ②-B, 데이터 클래스 위치는 Source/Celestiel/Character/다. ⑤는 명세·에셋 값·시험 조립을 맡는다. 초기 Look은 클래스 기본값이고, 걷기 시험용 소환 캐릭터는 가벼운 외형으로 덮어쓴다.

  • BodySet: BodyFitId·SkeletonContractId, 11몸부품/Head·경계표·LOD 대응·기본 재질·기준 pose. 두피와 끈 기준면은 HAIR-2 인계 참조.
  • Part: SlotId/PieceId·Meshes[]·본/체형 판·소켓·MaterialOverrides(슬롯명)·HideBodyParts·부분 마스크·ClothProfile·LODProfile·호환 조건. 실제 파일 해시/원본 판은 인계 메타데이터로 보관한다.
  • Look: BodySet + 6슬롯 선택 + HairBundle + 무기 외형 참조. HairBundle은 HAIR-2의 최신 대응표로 확정한 Groom/Binding 목록·카드 LOD를 참조하고, Accessories의 머리 장식과 동일 물체를 중복 생성하지 않는다. 소유 ID를 공유해 컴포넌트는 하나만 둔다. 예전 두 Groom 구성의 수를 최신 인계에 강제하지 않는다.
  • 요청 번호로 최신 요청만 적용한다. 로드, Skeleton, BodyFitId, 필수 슬롯, 재질 슬롯 이름, 망토 천 설정 여섯 가지를 모두 검증하고 가림/연결 상태를 준비한 뒤 한 프레임에 원자적으로 교체한다. 비동기 완료 순서가 뒤집힌 이전 요청은 적용하지 않는다. 실패 시 현재 외형을 유지한다. 초기 실패 때 기존 블록아웃 Body를 지우지 않는다.
  • 6슬롯 A→B→A 시험은 같은 승인 부품의 착용/해제 조합으로 가능하다. 비교 시험을 위해 새 옷 디자인을 만들지 않는다. 인벤토리·스탯·장비 저장 기능은 넣지 않는다.

3.3 몸 가림과 이음

④의 HideBodyParts와 T_FP_BodyHide_<Look> 커버리지에 따라, 옷이 완전히 덮는 몸 부품은 가시성을 끄고 반만 덮는 곳은 마스크를 쓴다. BodyTorso Leader는 계속 켜 두고 마스크만 적용한다(단일 경계표 §8). 전체 Pawn이 숨겨지는 상태와 옷 밑 몸 가림은 별개다. 숨긴 손/팔의 상태가 다른 follower에 전파되지 않게 한다.

현재 Look의 모든 가림 합집합을 기본 몸 상태에서 다시 계산한다. 이전 옷의 마스크가 남지 않게 하며 속옷의 기본 가림은 빈 집합이다. 옷이 속옷을 완전히 덮는 경우에도 승인 커버리지로만 해당 부분을 가린다. 영구 면 삭제·몸 부위 메시 교체로 구멍을 메우는 방식은 쓰지 않는다. 섹션 추가/숨김은 실제 필요한 경우 후속 대안이다.

부분 가림 마스크는 linear 데이터, 채널 의미/UV 판/커버리지 이름을 manifest에 명시한다. 몸의 공유 텍스처는 복제하지 않고 필요한 부위에만 마스크 MID를 쓴다. Opaque 피부와 Masked 피부 변형은 같은 색/노멀·피부 반응을 유지하도록 비교한다. 목·손목·무릎·발목 경계는 근접/게임 거리·기준/굽힘 자세에서 검사한다.

5. 피직스 에셋·옷 천

5.1 충돌과 첫 천 대상

제안 PA_FP_ClothCollision은 공통 Skeleton의 머리·목·가슴/등·골반·상완/전완·허벅지/종아리를 따라가는 약12~18개 단순 capsule/sphere에서 시작한다. 겹침이 심한 관절·옷 안 여유를 근접 확인한 뒤 수/크기를 조정한다. 원본 전체 삼각형 충돌이나 몸 크기 확대만으로 관통을 감추지 않는다. 캐릭터 이동은 기존 캡슐이 담당하고, 외형용 충돌체는 gameplay Hit/Overlap·래그돌·전투 판정에 참여하지 않는다.

컨셉 부위첫 판고정/주의

5.2 시험 순서와 설정 범위

  1. 물리 OFF로 Idle·달리기·회전·점프의 스킨 변형/옷 맞춤을 확인한다. 원본 관통을 물리 파라미터로 숨기지 않는다.
  2. 망토만 ON, 무풍·지상 기준에서 고정점·몸 충돌·자락 길이를 확인한다. 질량 면밀도 .1~.25kg/m², damping .2~.5, collision thickness .2~.5cm는 초기 탐색 범위다. 사용하는 ClothConfig에서 질량 모드·단위·지원 속성을 확인한 뒤 환산한다. Groom 설정 수치를 복사하지 않는다.
  3. 처음엔 self collision OFF로 몸 충돌을 분리 시험한다. 접힘/팔 관통이 남으면 self collision ON과 범위를 비교하고 비용을 기록한다. iterations/substeps는 설치 기본값 기록 → 관통/안정성 문제별 한 단계씩 변경한다.
  4. 급정지·회전·점프 착지·카메라 밖 복귀·외형 교체를 시험한다. Chaos cloth CPU 비용과 추가 skin/render GPU 비용은 따로 측정한다.

SuspendClothingSimulation()은 마지막 시뮬 상태를 유지하고 ResumeClothingSimulation()은 재개 시 teleport 처리를 한다. SetPresentationActive(false)에서 애니메이션/천/그룸을 함께 중지하고 복귀 시 재개한다. 필드 정지 API는 별도로 만들지 않는다. 복귀 때 갱신된 pose를 기준으로 ForceClothNextUpdateTeleportAndReset()과 그룸 ResetSimulation()을 수행한다. 매 프레임 reset하지 않는다. 실제 그룸 정지 구현은 CU3·CU4 실행에서 선택하며 장식 체인도 같은 표시 상태에 맞춰 검증한다.

6.1 HAIR-2 선행 조건

v3f 기반 다리 조정 채택본 + 최신 채택 헤어의 BodyFit·Head/reference pose 확정 → 같은 pose·UV0·LOD의 스킨 두피 인계 → ④의 여섯 편집 구역/렌더·가이드 ID/Groom 그룹/root 면/물리 대응표 대조 → 확정 구성으로 Groom·Binding 생성·재로드 → 가닥 재질·물리 → ④ Imported Cards → 장식/리본 순이다. 예전 Main(ID0~3)/Ponytail(ID4)·두 Binding 계약은 새 X자 반묶음 대조 전 자동 적용하지 않는다. 자세한 검토 조건은 HAIR-2 §2.2를 따른다.

최종 머리·두피 인계 전에는 최종 자산 바인딩을 하지 않는다. §8.1의 작은 Dev 전달 시험은 별도 입력으로 먼저 검증할 수 있으며 최종 외형 승인으로 쓰지 않는다. 얼굴/몸이 바뀌어 target geometry/UV/pose가 달라지면 이전 Binding을 재사용하지 않고 영향 목록부터 낸다.

두피/끈 기준면은 같은 공통 Skeleton을 따르고 렌더에는 드러나지 않아야 한다. 숨김 방식이 본 갱신·Skin Cache·Groom binding을 끊지 않는지 실제 확인한다. 헤어, 머리 mesh, 두피/끈 기준면, 망토의 LOD를 공통 품질 단계로 매핑하되 각 asset의 LOD index가 같다고 가정하지 않는다. 장식 소켓은 S_Accessory_Hair, 귀걸이는 S_Accessory_Ear_L/R 등 §8 경계표를 사용한다. 공유 엔진 Skeleton은 변경하지 않는다.

6.2 승인된 실제 플레이어 연결 계약(구현은 ②-B)

다음은 승인된 연결 동작의 의미이며 새 함수가 이미 구현됐다는 뜻은 아니다. 게임 코드/기능 BP 구현은 ②-B가 CP-T3·튜토리얼 전술 작업 다음, 여주인공 UE 가져오기 전에 맡는다. ⑤는 외형 에셋·시험 조립·물리 profile을 넘긴다. §1의 native Pawn과 배치된 Pawn_Tutorial 양쪽에 적용돼야 한다.

②-B의 필드 코드 대조와 총괄 승인에 따라, 몸통 Leader GetMesh()의 발끝 Z=-96cm와 앞 방향 yaw는 생성자 상수로 둔다.
