2. 시간·입력·정지

2.1 보스 공격 중 입력 (M1 4절 계약의 실제 연결)

  • 보스 공격 시작 호출은 대응 준비(카메라 CAM_Default → CAM_React 0.6초, 표적 G0 이동)가 끝난 뒤에 한다. 전환 시간은 공격 시계에 들어가지 않는다.
  • 프레임마다 순서: (1) 그 프레임에 들어온 정밀 방어 누름을 현재 공격 시계 시각(clockMs = atMs)으로 누름 하나당 한 번 제출 → (2) 프레임 시간(ms, 소수 나머지는 다음 프레임으로 넘겨 누적 오차 없이)만큼 시계 진행 → (3) 새 규칙 사건을 표시에 넘김. 50ms 상한은 규칙 핵심이 처리한다.
  • Enhanced Input 콜백에서는 누름을 대기열에 쌓기만 하고 규칙을 직접 부르지 않는다. 진행자 틱이 위 순서로 소비한다. 입력 처리와 진행자 틱의 순서(같은 프레임 안에서 누름이 먼저 소비되는지)는 M2-4에서 표시 로그로 확인한다.
  • 누름은 Enhanced Input의 누른 순간 사건만 쓴다. 누르고 있기는 새 입력이 아니다.
  • 입력 문맥: 보스 공격이 진행 중이고 정지가 아닐 때만 정밀 방어 문맥을 켠다. 계획·예약 선택·결과 화면은 UI 문맥(마우스 클릭, Enter)이며 Space를 확인 키로 쓰지 않는다. Enhanced Input의 문맥 변경은 프레임 끝에 적용되고 '눌린 키 무시'는 불 값 액션에만 적용되므로, 진행자가 문맥 전환 시각을 기록하고 전환 뒤 첫 새 누름만 받는 조건을 직접 확인한다(K3).
  • 보스 공격 밖의 누름은 규칙에 보내지 않고 관찰 기록에만 남긴다.
  • 입력 시각의 해상도는 프레임 간격이다(K1). 같은 물리 입력이 모든 fps에서 같은 시각으로 양자화된다고 요구하지 않는다.

2.2 M2 전체 정지·포커스 (③ P1-01)

  • 규칙의 일시정지는 보스 공격 중에만 받는다. 그래서 진행자가 별도의 정지 상태를 가진다. 정지 중에는 비트, 카메라 전환, 인물 이동, 팔 동작, 규칙 호출(공격 시작·시계 진행·예약 선택·계획 제출), UI 선택 입력이 모두 멈춘다.
  • 정지 원인: 정지 키·화면 버튼, 앱 포커스 상실. 보스 공격이 실제로 진행 중일 때만 규칙 Pause/Resume를 불러 입력 로그에 남긴다. 다른 구간의 정지는 규칙 로그에 남지 않는다.
  • 재개는 사용자의 명시적 조작(화면의 계속 버튼 또는 Enter)으로만 한다. 포커스를 되찾아도 자동으로 재개하지 않는다. 재개할 때 정지 동안의 경과 시간과 밀린 프레임 시간을 따라잡지 않는다(재개 첫 프레임의 시간은 버린다). 재개 뒤 정밀 방어는 새 누름부터 받는다.
  • 정지 키: Esc는 에디터의 PIE 종료 기본 키라 쓰지 않는다. PIE·패키지 공통으로 P 키와 화면의 일시정지 버튼을 쓴다. 사용자 에디터 단축키는 바꾸지 않는다.

3.2 보스 팔과 공격 중 표시 순서 (③ P2-01)

  • 팔 배치·각도(M2-1 임포트에서 확인, (내부 경로)): 몸통 원점 기준 어깨 피벗 ArmL (10, −155, 435)·ArmR (10, +155, 435), 배치 Yaw ArmL +15°·ArmR −15°. 팔 회전은 FQuat(FVector::YAxisVector, 라디안(각도))에 각도를 대기 0° → 예비 끝 −160° → 타격 끝 −60° → 0°로 넣는다(README의 '+160·+60 피치 표기'를 양수로 넣으면 주먹이 뒤로 간다). 방향 = 어깨 Yaw 쿼터니언 × 팔 회전. 오일러 표시값이 아니라 이 스칼라 각도를 보간한다. 타격 끝 주먹 중심은 월드 (357.5, ±92.7, 301.8). H1 = ArmL, H2 = ArmR.
  • 팔과 몸통·골반·다리의 관통이 M2-1 계산에서 발견되어 ④가 몸통 쪽 형태를 고치는 중이다(피벗·Yaw·각도는 유지). 고친 메시는 같은 경로로 다시 임포트한다.
  • 타격 동작은 그 타격의 TELEGRAPH 사건에서 시작하고, 사건의 예고 시작 시각을 기준으로 공격 시계에 맞춰 진행한다(들어 올림 → 멈춤 → 성공창 시작부터 내려침 → 타격 시각에 타격 끝 자세). TELEGRAPH가 없는 타격(연타 중 표적 사망으로 HIT_VOID)은 팔을 움직이지 않는다.
  • 팔 각도 곡선(M2-4b, ART-03 동작 비율): 구간 안 비율 t로 들어 올림은 2차 감속 1−(1−t)², 내려침은 2차 가속 t², 복귀는 smoothstep t²(3−2t)으로 보간한다. 구간 끝 각도·시각(예고 시작 0°, 성공창 시작 −160°, 타격 −60°, 타격 뒤 400ms에 0°)은 그대로다.
  • 공격 시계는 공격 종료(H2 타격 1700ms, H1에서 표적이 쓰러지면 900ms)에 멈춘다. 그 뒤의 팔 복귀(400ms)는 규칙 시계가 아닌 표현 전용 시간으로 진행하며 정지 중에는 멈춘다. 규칙 시계를 늘리지 않는다.
  • 타격 시각 경계: 진행은 [현재, 새) 구간이라 시계가 정확히 900이 된 프레임에는 900의 HIT가 아직 처리되지 않았을 수 있다. 팔 자세는 시계 값으로 그리고, 판정 글자·피해 숫자·체력 변화·받아내기 반동은 해당 JUDGE·HIT 사건이 처리된 프레임에 표시한다(차이는 한 프레임 이하).
  • 판정 표시는 색과 글자·형태를 함께 쓴다(성공·이른 입력·무입력). 예비 동작 시작부터 판정까지 큰 효과를 쓰지 않는다.

3.3 표시 로그 (화면 근거, ③ P2-03)

  • 진행자는 화면에 무엇을 언제 보였는지 표시 로그에 남긴다: 프레임 번호, 공격 시계, 비트 이름, 카메라 전환 시작·끝, 메뉴 열림·닫힘, 입력 문맥 전환, 입력 어댑터가 받은 누름·떼기(프레임, 제출 여부, clockMs = atMs).
  • 규칙 사건에서 나온 표시(팔 동작 시작, 판정, 보스 피해, 아군 피해·체력, 회복, 효과 생성·소비·불발, 예약 후보, 승패)는 원본 사건 키 = 시도 번호·라운드·사건 순번(사건 로그의 R{라운드} {순번})과 사건 종류, 화면에 보인 값과 대상을 함께 적는다.
  • 검증은 표시 로그를 규칙 사건 로그와 대조한다(표시 값 = 사건 값, 표시 순서가 사건 순서를 넘지 않음). 표시 로그는 결과를 바꾸지 않는 관찰 기록이다.

UI가 AddDisplayLog로 남기는 ui 줄이다. UI는 진행자 표시 로그를 기록된 순서대로 읽어 show src= 줄 하나마다 그 사건을 화면 값(표시 모델)과 관찰 기록에 넣고(R2), 그 틱에 남길 ui 줄은 읽은 줄 뒤에 붙인다. 형식 규칙은 10절과 같다(첫 낱말·키 이름·키 순서·값 표기는 조율 없이 바꾸지 않고, 값에는 공백을 넣지 않으며, 정보를 더할 때는 줄 끝에 새 키를 덧붙이거나 새 첫 낱말의 줄을 만든다). 이 절은 ②-B가 고치고, 위 10절의 줄은 ②-A가 고친다.
