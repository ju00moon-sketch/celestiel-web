0. 임시 가정(사용자 확인 전, 총괄 추천안 적용)

사용자가 답하지 않은 세 질문은 총괄 추천안으로 진행하고, 사용자가 다르게 정하면 고친다.

  • 자동 진행에서도 같은 카메라 규칙을 쓴다(사건 로그 바이트 일치 유지).

2.2 전략 조망 조작(계획 화면이 열린 동안만)

키동작한계·속도(⑥ 확정, LVL-01 v0.3 5장)
A / D카메라 오른쪽(화면) 축으로 좌우 이동전장 중심에서 반지름 650cm 원 안, 500cm/s × 확대 배율
Q / E전장 중심 둘레 회전기본 방향에서 ±60°, 45°/s
Z / X확대 / 축소거리 0.7배~1.4배, 0.5/s
  • 기본 조망(LVL-01 v0.3 4장): 중심 (200, 0, 200), Yaw 0, Pitch −40°, 거리 4540, h16 45°, 회전 보정 Pitch −1.48°·Yaw +4.64°(이동·회전·확대와 무관하게 일정). 조망 진입 0.5초, 기본 복귀 0.4초(smoothstep).
  • FOV 값은 모두 16:9 기준 수평 FOV(h16)로 적는다. 16:9 이상 넓은 화면은 세로 FOV를 유지하고(Hor+), 16:9보다 좁은 화면은 수평 FOV를 유지한다(LVL-01 v0.3 2장). UE 5.8의 기본값(ULocalPlayer AspectRatio_MaintainYFOV)은 이미 16:9 기준 Hor+이므로 계산한 FOV를 그대로 넣으면 넓은 화면에서 두 번 넓어진다. 그래서 표시 카메라는 수평 FOV 유지(MaintainXFOV)를 명시하고, 진행자가 화면비별 수평 FOV를 계산해 넣는다(M3-1a의 이중 적용 결함을 M3-1b에서 수정).
  • 계획 화면이 닫히면(실행 시작) 기본 조망으로 되돌린다. 다음 계획 비트에서 다시 기본값부터 시작한다.
  • 전투 키(Space·P·Enter·Tab)와 겹치지 않는다. 입력 문맥은 M2의 UI 문맥에 카메라 조작을 더하는 방식으로 하고, 정밀 방어 문맥에서는 카메라 조작을 받지 않는다.

3.2 실행 단계(그림 CUI_resolution_phase 기준)

  • HUD 최소화: 보스 막대와 턴 순서 열(지금 행동 강조)은 남기고, 5인 목록은 작은 모양으로 줄인다. 선택 패널·대기열은 숨긴다.
  • 행동 이름 배너: 왼쪽 위에 "A의 행동 — A1"(스킬 이름)을 ACTION_START 표시 때 띄운다.
  • 숫자: 피해(흰색/빨강)·회복(초록)·보호막(파랑)을 대상 위치에 띄워 약 0.8초 동안 올라가며 흐려지게 한다. 보스 연타는 타격마다 숫자, 끝에 합계 한 줄.
  • 정밀 대응 표시(M2 UI-3a)와 예약 창·결과 창·일시정지 화면은 기능 그대로 두고, 새 배치와 겹치지 않게 영역만 맞춘다.
  • 모든 표시는 M2 원칙대로 보인 사건에서만 값을 가져온다. 규칙 상태를 먼저 보여 주지 않는다.

4. 연출 건너뛰기(M3-3, ②-A 진행자 + ②-B 안내)

  • Tab: 지금 진행 중인 파티 행동 비트(선행·후행)의 남은 연출을 끝 상태로 건너뛴다. 남은 사건은 즉시 보이고, 인물은 자리로 돌아간 상태가 된다. 연달아 누르면 다음 행동도 건너뛴다.
  • 보스 공격(대응 준비·대응·복귀), 결정, 결과 창, 일시정지 중에는 받지 않는다. 자동 진행 중에는 받는다(8.1절 C5).
  • 규칙·사건 순서·관찰 기록 값은 바뀌지 않는다. 표시 로그에 skip 줄을 남긴다(형식은 10절 표에 ②-A가 추가).
  • 실행 중 화면 아래에 "Tab 건너뛰기" 안내를 작게 둔다.

6. 검증

  • 규칙·사건: S1~S4 자동 진행 사건 로그가 규칙 전용 로그와 바이트 일치(카메라·UI·건너뛰기 추가 뒤에도). 표시 로그의 show 줄 순서가 M2와 같음(건너뛰기는 표시 시점만 당김).
  • 입력: 30·60·120fps에서 정밀 대응 판정이 M2와 같음. 카메라 조작 키가 정밀 방어 문맥에서 먹지 않음. Tab이 보스 공격 중 무시됨.
  • 정지: 카메라 섞기·조작·숫자 애니메이션이 정지 중 멈춤.
  • 화면: 새 배치가 CAM_React 금지 영역(팔·표적)과 겹치지 않음. 표시가 앞서지 않음(sync_error 0).
  • 사람 확인: 카메라 멀미·어지러움, 조망 조작감, 연출 카메라가 행동을 잘 보여 주는지, 숫자·배너 가독성.

8.1 카메라·입력(M3-1, ②-A)

#결정
C1CAM_Overview·CAM_Action은 맵에 카메라를 두지 않는다. 진행자가 무대 표식(자리·M·F·G0·보스 자리)과 설정 구조체 값으로 구도를 계산한다. CAM_Default·CAM_React는 지금처럼 맵의 카메라를 쓴다
C2카메라는 '구도'(위치·회전·FOV·이름) 하나로 다룬다. 비트 시작과 ACTION_START 표시 때만 새 구도로 섞기를 시작하고, 섞기는 표현 시간으로만 흐른다. 행동이 겹치면 다음 행동의 ACTION_START에서 지금 위치부터 새 구도로 섞는다
C3조작(A/D·Q/E·Z/X)과 Tab 입력은 코드로 만든 Enhanced Input을 쓴다. .uasset이 없어 주 폴더 잠금·쿠킹 설정이 필요 없다. 기존 IMC_UI·IMC_PreciseDefense 에셋은 바꾸지 않는다. 키 설정 화면이 생기면 에셋화를 검토한다
C4CAM_Action은 행동마다 고정된 어깨 너머 구도(행동 위치와 대상을 함께 담음)로 시작하고, ACTION_START 때 한 번 계산해 행동 동안 고정한다. 금지 영역 때문에 구도가 서지 않으면 CAM_Default로 둔다
C5자동 진행 중에도 Tab을 받는다. 표시 시점만 당기므로 사건 로그는 그대로이며, 테스트로 고정한다
  • 표시 로그(M2 설계 10절에 ②-A가 추가): 기존 camera_start to=… seconds=…·camera_end to=…를 그대로 쓰고, CAM_Action이면 줄 끝에 actor={인물}를 붙인다. 조망 초기화는 camera_overview … reset=true, 구도 대체는 camera_start to=CAM_Default seconds={초} fallback=action.
  • 건너뛰기 줄: 받음 skip source=key beat=Action actor={인물|none} shown={수} settled={수}, 거절 skip source=key accepted=false reason={halted|not_action}.
  • 구도 값은 ⑥의 LVL-01 v0.3(Planning\TurnBasedRPG\LEVEL_BattleSpace_Plan_v0.3.md) 9장 표를 설정 구조체 기본값으로 쓴다. v0.3이 초안을 바꾼 점:
  • 아군 대상 행동의 방향은 대상이 아니라 보스 핵 쪽으로 잡는다(180° 규칙).
  • 자기 자신이 대상이면 원거리 값을 쓴다.
  • 행동 → 행동은 이동 800cm 이하이면서 회전 30° 이하일 때만 0.3초 섞기, 아니면 컷이다.
  • 기본 ↔ 행동은 컷이다.
  • 행동에서 대응 준비로 갈 때는 대응 준비 비트 첫 프레임에 컷한다(H1 예고 전이므로 공격 중 컷 금지와 부딪치지 않음). 기본에서 갈 때는 기존 0.6초 섞기를 유지한다.
  • 금지 영역은 보스 몸통 +80, 팔 부채꼴 +60, 인물 +40, 높이 60 미만·배경·바닥 밖이다. 대체 순서는 기본 → Side 반대 → Side 반대 + Back 1.5배 → CAM_Default다.
  • 행동에서 나가는 전환(행동 → 행동, 행동 → 대응 준비, 행동 → 라운드 끝, 행동 → 결과)은 지금 행동의 마지막 결과 표시(타격 섬광 등)가 끝날 때까지 최대 0.2초 늦게 시작한다. 늦춘 섞기는 원래 끝 시각에 맞춰 줄이고, 줄인 시간에서 섞기 최고 속도(smoothstep이라 평균의 1.5배)가 150°/s 또는 40m/s를 넘으면 컷한다. 대응 준비 컷은 H1 예고 0.3초 전을 넘지 않는다. 카메라만 늦추며 행동 시간·사건·규칙 시계는 그대로다(M3-5 P3 판독 중 원거리 섬광이 자기 구도에서 0프레임이던 문제, ⑥ 제안 채택). 컷 프레임은 렌더러에 컷으로 알린다(SetGameCameraCutThisFrame).
  • 구현 단위: M3-1a(먼저 검토·통합: 8.3절 계약 API, 건너뛰기 진행자 쪽 전부, CAM_Overview와 조작, 구도 통일 정리) → M3-1b(CAM_Action, 비트별 전환, camera 줄의 actor 키, 캡처·사람 확인 목록). UI는 M3-1a 통합 뒤 실제로 동작하는 API에 붙는다.

8.4 효과(M3-5, ⑤ 에셋 + ②-A 연결)

⑤ 계획 v0.1((내부 경로))에 대한 결정이다.

  • 방식: Niagara 없이 Static Mesh + 동적 재질 인스턴스(MID)를 진행자가 표현 시간으로 직접 갱신한다. 정지 중 고정, 재개 첫 경과 버림, Tab 묶음 끝에서 종료 상태로 정리, 재도전·세션 교체 때 모두 비움.
  • 범위: 기본 3효과(원거리 발사체, 아군 대상 표시, 파티 → 보스 타격 섬광 0.15초), 에셋 7개(/Game/Art/VFX/Blockout/). 보호막·회복 모양 2종은 숫자(8.2절)와 뜻이 겹치므로 사용자 플레이 뒤 후보로 둔다.
  • 보스 공격 대응(CAM_React) 중에는 새 효과를 띄우지 않는다. 파티가 맞는 HIT 섬광은 보류한다.
  • 사건 연결: 보인 ACTION_START에서 발사 예약, 보인 BOSS_DAMAGE(dmg>0)에서 섬광, 아군 대상 표시는 HEAL·EFFECT_ADD effect=shield|support의 실제 필드로 켠다. 기존 행동 시간(0.20·0.25·0.30초)은 바꾸지 않는다.
  • 아군 대상 표시는 K3 왼쪽 24px 상당(최대 20px)에 둔다. 숫자와 겹치지 않도록 숫자 쪽을 옮긴다(②-B). 숫자는 가로 가운데를 기준점에 맞추고 아래 변을 기준점 투영보다 20px 위에 두어 위로만 떠오른다. 위에 자리가 없으면 위 변을 기준점보다 20px 아래에 두고 제자리에서 흐려진다. 이렇게 하면 기준점 ±10px 안의 효과와 늘 10px 이상 떨어진다. 성능 예산(동시 8슬롯, GPU 0.2ms·게임 스레드 0.1ms 이내 등)은 초기 제안이며 실측 뒤 확정한다.
  • 순서: ⑤ 스크립트 준비(잠금 없음) → ⑤ 에셋 생성·재로드(주 폴더 잠금 15~25분) → ②-A 연결·테스트(M3-1b 뒤) → 통합 캡처·판독·성능 → ③ 검토·Cook·패키지.
