01. 게임을 한 문장으로

플레이어가 4~5명의 파티원을 지휘해 보스의 다음 행동을 읽고, 행동 시점과 동료 간 효과 전달을 설계하여 하나의 합동 작전으로 보스를 공략하는 턴제 RPG.

핵심 플레이 경험

합동 작전은 “누가, 언제, 무엇을 하는가”를 정한다. 파티 릴레이는 “그 행동이 다음 동료에게 무엇을 남기는가”를 정한다. 별도 미니게임 두 개가 아니라, 하나의 명령 화면에서 행동 배치와 연결을 함께 편집한다.

목표 감정은 “강한 기술 다섯 개를 눌렀다”가 아니라 “보스의 의도를 읽고 우리 파티가 한 작전을 완성했다”이다. 참신성이나 상업적 성공을 검증한 상태는 아니며, 재미는 실제 플레이로 확인한다.

문서의 결정 상태

표기의미총괄의 처리
합의현재 대화에서 사용자가 선택·수용한 방향임의 변경하지 않는다.
기본안앞선 제안을 바탕으로 유지하는 개발 방향충돌을 보고하고 정식 제작 전 확인한다.
제안 P이번 문서에서 구체화한 임시 전투 규칙검토·승인 전 확정 규칙으로 취급하지 않는다.
미정 D추가 의사결정이 필요한 항목선택지·영향을 정리하되 임의로 결정하지 않는다.

이번 전달의 범위

이 문서는 전체 게임의 최종 제작 명세가 아니라 첫 전투 시제품의 기획·검토 기준이다. 문서 수신 자체는 신규 구현, 유료 에셋 구매, 역할 변경, 외부 배포에 대한 승인이 아니다. 먼저 검토와 작업 분해를 진행하고, 임시 규칙 승인 후 해당 범위만 구현한다.

출시 분량·판매 가격·일정·개발비는 아직 정하지 않는다. 현재 Unreal 프로젝트·엔진 버전·저장소·실행 도구도 이 문서 작성 과정에서 확인하지 않았다.

02. 범위와 추가 결정

확정된 재미는 유지하고, 미정 사항을 구현자의 추측으로 채우지 않는다.

상태항목내용
합의장르·파티턴제 RPG. 파티는 4~5명이며 플레이어가 직접 지휘한다. 최종 정원은 미정이다.
합의전투의 중심보스 패턴 공략 + 합동 작전 + 파티 릴레이. 공격 역이용은 개별 보스 기믹이다.
기본안전투 공간격자 이동 없이 고정된 전투 구도. 중요한 행동만 별도 카메라·효과로 강조한다.
기본안플랫폼·제품Unreal 기반 3D, Steam/Windows 우선, 싱글플레이 유료 완결형을 검토한다. 정식 출시 사양은 별도 확정한다.
범위 밖첫 시제품 제외온라인·모바일 빌드·가챠·상점·오픈월드·제작·호감도·영구 성장·절차 생성은 만들지 않는다.

03. 합동 작전: 라운드 규칙

이 장 전체는 P 제안 규칙이다. 한 라운드는 파티 전체의 작전 한 번을 뜻한다.

P01. 기본 진행

보스 의도 공개 → 파티 명령 편집 → 유효성·예상 결과 확인 → 실행 확정 → 선행 행동 → 보스 행동과 예약 대응 → 후행 행동 → 종료 처리 → 다음 의도 공개.

명령 편집 중 시간은 흐르지 않는다. 각 생존 캐릭터는 행동 또는 대기 하나를 고른다. 속도 스탯, 확률 명중·치명타, 실시간 패링 입력은 첫 시제품에 넣지 않는다. 같은 시작 상태와 명령은 같은 결과를 내야 한다.

구간작동 방식예시
선행보스가 행동하기 전에 실행한다. 플레이어가 구간 안의 순서를 지정한다.준비 방해, 선제 공격, 보호 효과 부여
대응보스의 이벤트에 맞춰 미리 예약한 행동을 실행한다. 클릭 반응속도를 요구하지 않는다.피해 직전 가로막기, 방어 후 충격 생성
후행보스 행동과 대응이 끝난 뒤 지정 순서대로 실행한다.회복, 약점 공격, 릴레이 마무리

P02. 행동 도중의 정확한 의미

예약 대응은 피해 직전과 피해 처리 직후 같은 명시적 사건에만 연결한다. 처리 순서는 “대상 확정 → 피해 직전 대응 → 피해·보호막·체력 반영 → 전투불능 판정 → 생존자의 피해 직후 효과”로 제안한다. 같은 사건의 대응이 여러 개면 명령 화면의 순서를 사용한다.

방어를 예약하고 피격 시 발동하는 것은 행동 하나다. 예약을 별도 행동으로 세지 않는다. 첫 시제품의 기본 방어는 표적 변경 없이 자기 자신을 보호한다. 도발·대상 변경은 최소 버전에 넣지 않는다.

P03. 정보와 순서의 일관성

첫 보스는 라운드마다 주요 행동 하나를 예고한다. 행동명, 대상, 기본 피해, 방해 가능 여부와 임계치, 실행 뒤 약점 발생 여부를 보여준다. 대상은 의도 공개 시 확정하고 중간에 임의 재추첨하지 않는다.

약점은 원인이 된 보스 행동이 실제로 완료된 경우에만 열린다. 공격 준비를 끊으면 해당 공격·피격 대응·그 공격에 딸린 약점도 사라진다. 실행 전에 이 결과를 미리 표시한다.

핵심 구현 기준: 전·중·후는 애니메이션 재생 시간 비율이 아니라 게임 규칙상의 구간이다. 연출을 배속하거나 생략해도 전투 결과는 같아야 한다.

04. 파티 릴레이: 효과의 전달

이 장 전체는 P 제안 규칙이다. 연계는 행동을 추가하지 않고 기존 행동의 성격을 바꾼다.

P04. 효과 생성 → 변환 → 소비

스킬은 기본 효과와 조건부 연계 효과를 가진다. 입력이 없어도 유효한 대상이 있다면 기본 효과는 작동한다. 앞선 스킬이 만든 충격·번개·표식 같은 “연계 효과”를 다음 스킬이 변환하거나 소모한다. 연계 효과는 캐릭터의 스킬 자원과 구분한다.

제약첫 시제품의 처리
연결 방향실행 순서상 앞에서 뒤로만 연결한다. 선행→대응→후행을 거슬러 연결하거나 순환시키지 않는다.
입출력 수행동 하나당 연계 입력 최대 1개, 출력 최대 1개로 제한한다. 별개의 짧은 연계 여러 개는 허용한다.
소비와 예약출력 하나는 수신 행동 하나만 예약한다. 같은 효과를 두 행동이 중복 사용하지 못한다. 변환도 소비로 처리한다.
존속생성된 연계 효과는 해당 라운드 안에서만 유효하다. 쓰지 않은 효과는 종료 시 사라진다.
유형과 대상스킬이 요구하는 유형과 효과의 대상 범위를 확인한다. 특정 적에게 남긴 표식은 다른 적에게 옮겨 쓸 수 없다.
추가 행동 금지연계 발동은 선택한 행동의 일부다. 연계 길이만으로 추가 턴·무한 반격·일괄 피해 배율을 부여하지 않는다.

P05. 편집 중 검증과 실행 중 실패를 구분

순환, 미래 효과 참조, 유형 불일치, 중복 소비처럼 이미 확실한 오류는 실행을 막고 수정 위치를 표시한다. “기사가 실제로 공격을 받아야 충격이 생성된다” 같은 조건부 연결은 허용하되 조건과 불발 시 결과를 보여준다.

실행 중 입력이 생성되지 않았다면 소비자는 기본 행동을 한다. 출력 발생 여부는 그 스킬의 기본/강화 결과 정의를 따른다. 후속 스킬이 임의로 직전 강화 상태를 상속하지 않는다. 매 단계마다 실제 생성된 효과만 사용한다.

길이가 아니라 용도를 선택하게 한다

충격을 공격 강화로 넘길 수도 있고 치유 강화로 소모할 수도 있다. “4인 연계 + 1인 회복”과 “2인 연계 두 개 + 독립 행동”을 모두 지원한다. 특정 캐릭터 조합이 없다고 다른 캐릭터의 기본 스킬이 무의미해져서는 안 된다.

연출용 연결선과 실제 소비 기록을 분리하지 않는다. 화면의 연결이 어떤 효과를 예약했고, 실제로 무엇이 생성·소비되었는지 전투 로그로 추적할 수 있어야 한다.

05. 자원·예외 처리와 선택의 비용

이 장 전체는 P 제안 규칙이다. 숫자는 첫 비교 실험용 임시값이며 출시 밸런스가 아니다.

P06. 스킬 자원: 임시 집중력

각 캐릭터는 집중력 최대 3, 전투 시작 시 3을 가진다. 첫 라운드를 제외한 라운드 시작마다 1을 회복하고 상한을 넘지 않는다. 일반 공격·기본 방어는 0, 강화/회복 계열은 기본 1, 준비 방해는 기본 2를 비교 출발점으로 삼는다. 캐릭터별 비용은 데이터로 조정한다.

입력이 없어 기본 행동으로 내려가도 선택한 스킬의 기본 비용은 동일하다. 행동이 실제로 시작될 때 비용과 연계 입력을 소비한다. 행동 취소·불발에는 집중력을 쓰지 않지만, 그 캐릭터의 행동 기회는 소진된다. 자원·기본 효과·강화 효과를 함께 미리 보여준다.

P07. 방어와 준비 방해의 차이

준비 방해는 선행 구간에서만 보스에게 방해 수치를 누적한다. 임계치에 도달하면 예고 공격을 취소한다. 방해 스킬은 입력 없는 독립 행동으로도 작동한다. 방해 성공은 이번 피해를 피하지만 집중력을 많이 사용하고, 피격 에너지와 공격 후 약점도 얻지 못한다.

받아내기는 피해를 줄이는 대신 남은 피해를 감수하고 자원을 보존하거나 연계 기회를 얻는다. 모든 행동을 선행 공격에 몰아넣거나 매번 방해만 하는 선택이 우세한지는 테스트로 확인한다. 두 방식이 균형 잡혔다고 선결론을 내리지 않는다.

P08. 실패·취소·전투 종료

상황처리 제안
피격 대응의 원인 없음예약 행동은 불발한다. 비용·출력은 없고 기본 공격으로 바꾸거나 다른 구간에 옮기지 않는다.
행동 전 사망·행동 불가그 행동은 취소한다. 집중력과 입력 효과를 소비하지 않는다. 후속 행동은 입력 유무에 따라 기본 효과로 진행한다.
대상 사망·대상 부재해당 행동만 취소한다. 임의 재조준하지 않는다. 첫 시제품에서는 실행 중 대체 명령을 묻지 않는다.
출력 생성자 사망출력 생성 전에 사망하면 출력이 없다. 이미 생성된 효과는 유형·대상 조건이 유효하면 라운드 끝까지 유지한다.
피해와 보호막피해 감소 → 보호막 차감 → 체력 차감 순으로 계산한다. 상한·반올림은 공통 계산 규칙으로 고정한다.
전투 승리·패배보스 체력 0이면 승리, 파티 전멸이면 패배한다. 결과 확정 뒤 남은 명령은 취소한다. 동시 전멸이 가능한 구현이면 무승부 후 재도전을 제안한다.

시제품 패배에는 영구 손실이 없다. 재도전 시 초기 체력·자원·보스 상태로 되돌린다. 영구 사망, 저장·메타 성장, 전리품 경제는 이번 범위 밖이다.

06. 임시 파티와 합동 작전 예시

D01 승인 시 5인으로 검증한다. 직업명·성별·외형·세계관은 확정하지 않는다.

임시 역할3개 스킬 방향핵심 역할
A 수호일반 공격 / 충격 방어 / 준비 방해피해를 줄이고 충격을 생성한다. 필요하면 방해 작전에 참여한다.
B 변환일반 마법 / 번개 부여 / 약한 방해충격을 번개 강화로 변환한다. 입력이 없어도 기본 강화나 독립 공격을 한다.
C 사격일반 사격 / 관통 사격 / 견제 사격번개 강화로 공격하고 동일 적에게 전하를 남긴다. 기본 공격도 독립적으로 작동한다.
D 마무리일반 참격 / 파열 참격 / 준비 방해전하를 소비해 마무리한다. 짧은 공격이나 방해에도 기여한다.
E 지원일반 공격 / 단일 치유 / 보호독립 회복 또는 충격을 소비한 강화 치유를 담당한다. 고정된 회복 버튼으로 만들지 않는다.

위 15개는 기능 방향이며 최종 수치표가 아니다. 구현 전 스킬별 기본/강화 효과, 구간, 비용, 입력·출력 유형, 발동 조건을 한 데이터 표로 작성한다. 존재하지 않는 입력을 필수로 요구하는 스킬은 첫 시제품에서 제외한다.

작전 예시: 기사를 강타한 뒤 핵이 노출되는 보스

실행 순서선택 행동실제 처리
대응 / 피해 직전A 충격 방어자신에게 오는 피해 일부를 줄인다. 피해 처리 후 생존하고 실제 감소량이 있을 때 충격 1개를 만든다.
후행 1E 단일 치유A를 회복한다. 이 예시에서는 충격을 소비하지 않는 독립 행동이다.
후행 2B 번개 부여충격을 소비해 C에게 강화된 번개를 만든다. 충격이 없으면 기본 번개 강화만 만든다.
후행 3C 관통 사격번개를 소비해 노출된 핵을 공격한다. 강화 조건을 만족하면 같은 대상에 전하를 남긴다.
후행 4D 파열 참격동일 대상의 전하를 소비해 추가 효과를 낸다. 전하가 없으면 기본 참격을 실행한다.

같은 파티, 다른 자원 배분

안전이 우선이면 A의 충격을 E의 치유 강화로 보내고 B·C·D는 기본 효과 또는 짧은 연계를 사용한다. 큰 공격 전에 자원이 충분하면 A와 D가 준비 방해에 투자한다. 방해 성공 시 기존 피격 연계와 약점이 사라지는 것을 계획 화면에서 확인한다.

검증할 차이: 긴 공격 연계, 짧은 연계와 회복, 준비 방해가 서로 다른 상황에서 선택되는가? 이 예시 하나를 모든 보스의 정답 콤보로 고정하지 않는다.

07. 첫 보스와 시험 시나리오

하나의 보스·하나의 전투 공간에서 결정의 차이를 검증한다.

P09. 보스의 임시 정체성

임시 보스는 “공격 뒤 핵이 드러나는 거체”로만 정의한다. 이름·종족·스토리·정식 모델은 미정이다. 외형은 블록아웃을 사용하고, 핵 노출은 아이콘과 간단한 표시로 먼저 구현한다.

패턴예고 내용검증 목적
T01 단일 강타지정 캐릭터를 공격한다. 방해 가능. 공격 완료 후 후행 구간 동안 약점이 열린다.방어→충격→변환→마무리와 준비 방해를 비교한다.
T02 광역 압박생존 파티원을 공격한다. 방해 가능. T01과 달리 공격 후 약점은 열리지 않는다.긴 공격 연계 대신 회복·보호에 행동과 자원을 나눌 이유가 있는지 확인한다.

첫 시제품은 두 패턴을 고정 순서로 반복한다. 의도 선택 AI·확률 패턴·숨겨진 분기는 넣지 않는다. 광역 피해는 하나의 사건으로 처리하며, 즉시 전투불능 판정을 적용한 뒤 생존자의 후속 효과를 계산한다.

시험 A: 자원이 충분한 상태

동일한 초기 상태에서 “선행 방해로 피해 회피”와 “공격을 받아낸 뒤 긴 릴레이”를 각각 실행한다. 라운드 후 체력, 남은 집중력, 보스 피해, 다음 패턴 대응 가능성을 비교한다. 승리 여부 하나만으로 우열을 정하지 않는다.

시험 B: 체력 또는 자원이 부족한 상태

체력이 낮거나 방해 자원이 부족한 시작 상태를 별도 저장된 테스트 설정으로 제공한다. 충격을 치유에 사용하거나 짧은 연계로 나누는 편이 유리한 상황이 실제로 생기는지 확인한다. 특정 행동을 강제로 누르게 하기 위해 다른 선택지를 임의로 금지하지 않는다.

수치 설정과 확대 조건

보스 체력·기본 피해·방해 임계치·약점 보정·회복량은 임시 데이터로 작성하고 버전 기록을 남긴다. 초기 수치에서 한 전략이 압도하면 콘텐츠를 늘리는 대신 원인을 찾고 조정한다. 목표는 “규칙이 서로 다른 선택을 만드는가”를 보는 것이다.

시험 A/B에서 선택의 차이가 확인된 뒤에만 역이용 패턴, 여러 적, 연속 공격 사이 개입을 다음 범위로 제안한다. 이들은 이번 구현 완료 조건에 넣지 않는다.

첫 시제품은 정식 출시 분량도, 출시 가능한 데모도 아니다. 보스 수와 플레이 시간을 먼저 늘리지 말고 핵심 전투의 작동·이해·재도전 의사를 확인한다.

미리보기와 편의 기능의 단계

최소 버전은 행동 가능 여부와 연계 조건, 생성·소비·불발 예상, 라운드 종료 상태를 텍스트로 보여준다. 전체 실행을 순수 규칙 계산으로 미리 확인하고, 실제 실행도 동일 규칙을 사용한다. 조건부 효과를 보장된 성공처럼 표시하지 않는다.

반복 명령 입력이 과하면 이전 작전 불러오기와 일부 수정 기능을 다음 단계로 추가한다. 이전 작전을 불러온 뒤에는 현재 대상·자원·조건을 다시 검증한다. 자동으로 실행하지 않는다. 드래그 연출·화려한 컷인·합체 필살기 영상은 나중에 만든다.

총괄에게 제안하는 논리 분리

전투 상태·규칙 계산, 명령 편집·검증, 실행 결과 로그, UI·연출 재생을 분리한다. 이는 책임 구분 제안이며 특정 Unreal 프레임워크 채택 지시가 아니다. C++·Blueprint·데이터 형식의 구체적 분담은 기존 프로젝트 구조를 확인한 뒤 총괄이 설계한다.

스킬 데이터에는 기본 효과, 허용 구간, 비용, 입력/출력 유형, 발동 조건, 기본 행동으로의 전환 규칙을 둔다. 실행 로그에는 행동 ID, 캐릭터, 구간·순서, 대상, 비용, 생성·소비 효과 ID, 실패 이유, 상태 변화를 남긴다.

보이지 않는 규칙은 만들지 않는다. 플레이어에게 설명할 수 없는 임의 재조준·자동 순서 변경·숨은 보정으로 오류를 덮지 않는다. 표식은 색상만이 아니라 이름·아이콘·상태 텍스트로도 구분한다.

ID시험통과 기준
QA01결정성·실행 순서같은 상태와 명령의 로그가 일치한다. 연출 재생 속도는 결과를 바꾸지 않는다.

QA06다양한 작전긴 연계+독립 치유와 짧은 연계 여러 개를 입력·실행할 수 있다. 입력 없는 스킬도 정상 작동한다.

QA08초기화·연속 플레이즉시 재도전과 연속 전투에서 이전 효과·표식·피해·명령 상태가 누적되지 않는다.
QA09사용자 이해·선택사용자가 예고와 연계 불발 이유를 설명할 수 있다. 시험 A/B에서 다른 작전을 시도할 이유가 있는지 기록한다.
QA10실행 환경코드·에셋 연결·에디터 실행·패키징·패키지 실행을 별도로 확인한다. 수행하지 않은 단계는 미실행이다.

라운드 계획에 걸린 시간, 명령 수정 횟수, 오류 이유, 선택한 전략, 남은 체력·집중력, 보스 피해, 사용하지 않는 스킬, 연계 길이, 패배 원인, 재도전 의사를 기록한다. 초기 수치 목표나 판매 가능성을 검증 결과 없이 단정하지 않는다.

위험 신호와 대응

항상 같은 5인 연계만 쓰면 효과의 소비 경쟁과 짧은 연계의 가치를 조정한다. 항상 선행 공격 또는 준비 방해만 쓰면 피해·자원·약점의 보상 관계를 검토한다. 입력이 복잡하면 새로운 시스템 대신 표시·순서 편집을 단순화한다. 기본 행동 전환이 실패를 완전히 무의미하게 만들면 강화 폭과 비용을 재검토한다.

11. 총괄 전달문과 승인 경계

아래 전달문은 파일과 함께 사용할 수 있다. 기존 운영 지침을 대체하지 않는다.

첨부한 TURN_BASED_RPG_GDD_v0.1.md를 신규 턴제 게임의 전투 프로토타입 기획 검토본으로 읽어줘. 핵심 방향은 4~5인 파티, 보스 공략, 합동 작전과 파티 릴레이의 결합이야. 공격 역이용은 개별 패턴 기믹으로 취급해.

먼저 실제 Unreal 프로젝트·엔진 버전·브랜치/worktree·미커밋 변경·기존 규칙과 운영 세션을 확인해. 웹 대화가 자동으로 전달됐다고 가정하지 말고 실제 수신 문서의 버전을 기준으로 작업해. 다른 웹·챗봇 프로젝트에 이 기획을 적용하지 마.

합의된 방향, 기본안, P 제안 규칙, D 미정 사항을 분리해. 제안과 예시는 사용자 확정 결정으로 승격하지 마. 문서의 모순·누락과 구현 위험을 검토하고, 보완안에는 게임 경험·작업 범위·검증에 미치는 영향을 적어줘.

첫 회신은 최소 작업 분해안, 의존성, 담당 수정 범위, 완료 조건, 검증 계획, 구현 전에 승인할 규칙과 수치표 초안으로 해줘. 프로젝트를 새로 만들거나 시스템 구현을 시작하는 대신 먼저 이 검토를 마쳐줘. 승인 후에는 해당 범위의 시제품을 작은 기능 단위로 진행해.

기존 총괄·구현자 1명·독립 리뷰·아트·레벨디자인 체계와 권한을 유지해. 모델·세션·MCP·훅·전역 설정을 바꾸거나 문서 전체를 AGENTS.md/개발 세션.md에 중복 복사하지 마. 구매·외부 배포·파괴적 변경·미승인 머지는 별도 승인 없이 실행하지 마.
