TURNFEEL-1 설계 초안: 차례 표시 1단계(규칙 불변) — ②-B, 2026-09-28

  • 상태: 사용자 결정 전 준비 초안. 코드 편집은 하지 않았다. 배정되면 이 초안으로 시작한다.
  • 기준: ct-p1-ui fed4b8f, 총괄 기획안 COMBAT_TurnFeel_Proposal_v0.1.md 1단계(차례 배너·실행 중 순서 띠·테두리 색)
  • 범위: UI만 바꾼다. 규칙·계약·사건·카메라·조명은 바꾸지 않는다. 카메라 무빙은 ②-A·⑥, 실제 조명·후처리는 ⑤ 몫이다.

0. 근거(지금 구조)

  • 전술 실행 한 라운드의 비트와 사건 순서(주 폴더 (내부 경로) 표시 로그 확인):
  1. Header(ROUND_START·INTENT)
  2. Plan·PlanShown(계획 화면)
  3. Move
  4. Phase(PHASE pre, 아군 선행 행동 ACTION_START)
  5. ReactPrep(대응 카메라)
  6. Attack(PHASE response, ATTACK_START … ATTACK_END)
  7. ArmReturn·DecisionPrep
  8. Phase(PHASE post, 아군 후행 행동)
  9. RoundEnd
  • 차례 경계는 이미 사건으로 보인다: 선행·후행 구간 = 아군, 대응 구간(보스 공격) = 적, 계획 화면 = 작전
  • 실행 턴 순서 모델(UI/BattleUIModel.cpp ApplyBannerAndOrder)은 PLAN·ACTION_START·PHASE·ATTACK_START로 칸 상태(planned·current·done·canceled)를 이미 바꾼다.
  • 그런데 전술 실행 중에는 최소 HUD(UI/BattleUIController.h IsMinimalHud)가 턴 순서를 숨긴다.
  • 행동 이름 배너(R5)는 아군 행동에만 뜨고, 대응 구간에서는 비운다.

1. 기능

기능내용
가. 차례 배너차례가 바뀔 때 화면 가운데에 '아군 차례'·'적 차례'를 짧게 띄운다(0.9초, 나타남 0.15초·사라짐 0.25초). 아군 = 파티 색 계열, 적 = 보스 붉은색(BossHpFill). 구간에 할 일이 없으면(선행·후행 칸 없음) 그 차례는 건너뛴다
나. 실행 중 순서 띠전술 실행 비트에 얇은 가로 띠로 이번 라운드 칸을 보인다(인물 = 팀 색 표식 + 명령 이름, 보스 = 붉은 칸 + 공격 이름). 지금 칸은 테두리 강조, 끝난 칸은 흐리게, 취소는 줄 긋기. 계획 화면이 열리면 숨긴다(오른쪽 턴 순서 열이 대신한다)
다. 테두리 색차례 동안 화면 가장자리에 얇은 색 테두리(비네트)를 둔다. 적 = 붉은색, 아군 = 푸른색, 알파 약 0.2, 바뀔 때 0.3초 전환. 계획 화면·결과 창·일시정지 동안은 없다
  • 차례 판정(모델): EBattleUITurnSide { None, Plan, Ally, Enemy }와 바뀐 횟수(배너 시작용)
  • PHASE pre / post: 그 구간 칸이 있으면 Ally
  • PHASE response 또는 ATTACK_START: Enemy
  • ROUND_END·승패: None
  • 계획 화면 열림: Plan(컨트롤러가 준다)
  • 관찰 줄(③ 도구와 시험용, 더하기만): ui show … widget=turn field=side value=ally|enemy|plan|none

시험확인

  • red: 차례 판정 끄기, 배너 시간 무시, 띠 숨김 유지(IsMinimalHud), 테두리 색 뒤바꿈 → 짝지은 시험만 실패 → green → 전체

4. 배치 후보(겹침은 레이아웃 시험으로 확정)

  • 배너: 가운데 ±320 × 300~372(짧은 자막처럼 전장 가운데 위). 카메라 전환(ReactPrep 0.6초)과 겹쳐도 판독에 지장이 없게 반투명 띠를 쓴다.
  • 순서 띠
  • 1안: 가운데 ±360 × 836~892(튜토리얼 줄 772~828과 박자 줄 900~1020 사이)
  • 2안: 기존 오른쪽 열(C5)을 실행 중에도 작게
  • 1안을 권한다(눈이 박자 줄 가까이에 있다).
  • 행동 이름 배너(R5, 왼쪽 위)는 그대로 둔다. 차례 배너와 시간이 겹치면 차례 배너를 먼저 끝낸다(0.9초).
