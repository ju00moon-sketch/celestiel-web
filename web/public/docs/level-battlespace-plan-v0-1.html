2. 좌표계

  • 원점 (0, 0, 0)은 전투 바닥 위의 기준점이다. +X는 파티에서 보스 쪽, +Y는 파티가 보스를 바라볼 때 오른쪽, +Z는 위쪽이다(Unreal 기본 축).
  • 인물·보스 좌표는 발 위치다. 액터 원점이 캡슐 중심이면 Z에 캡슐 반높이(임시 90)를 더한다.
  • 회전은 Unreal Rotator 순서(Pitch, Yaw, Roll)이며 Roll은 모두 0이다. Yaw 0은 +X 방향이다.

3. 파티 5인 자리

3.1 배열 형태

보스 중심 (600, 0)을 중심으로 한 반지름 900cm 원호 위에 5명을 300cm 간격(원호 각 19.1°)으로 놓는다.

  • 원호를 고른 이유: 5명의 보스까지 거리가 같아 앞줄·뒷줄 같은 규칙 의미가 생기지 않는다. 앞뒤 두 줄 배치는 전열·후열 규칙이 있는 것처럼 보이므로 쓰지 않는다.
  • 300cm 간격을 고른 이유: 220cm 간격과 비교하면 기본 카메라에서 인물 크기는 거의 같다(최소 110px → 105px). 대신 화면상 인물 사이 틈이 약 50px에서 최소 61px(A–B, 나머지는 107px 이상)로 넓어져, 머리 위 이름표·아이콘·표적 표시가 덜 겹친다. 이름표 폭이 60px을 넘으면 A·B 사이는 위아래로 엇갈리게 둔다(② UI).
  • 좌우 순서: 기본 카메라 화면에서 왼쪽부터 A→E로 보이게 놓는다. 하단 파티 정보 패널도 같은 순서다(Q2 확정).
  • 방향: 각 인물은 핵 중심 (500, 0)을 바라본다.

6. 강조 카메라

GDD 02장 기본안대로 중요한 행동에만 쓴다. 모든 강조 카메라는 결과에 영향을 주지 않는 연출이며, 배속·생략해도 전투 결과가 같아야 한다(QA01). 컷 전환·재생 로직은 ②(M2-3)가 만들고, ⑥은 카메라 액터 배치와 값을 맡는다.

  • 인물 기준 상대값으로도 쓸 수 있다. ②가 카메라를 인물에 붙이는 방식을 택하면 이 규칙을 그대로 옮긴다.
  • 릴레이 전용 카메라(연결 순간 컷, 연쇄 연출)는 만들지 않는다(C04). 연계가 이어지는 경우에도 각 행동의 일반 규칙을 따른다.

7. UI 영역 가림 검토

계산 방식: 인물은 반지름 40·높이 180 원기둥, 보스는 ART-02 경계 상자(월드 X 490~710, Y −200~200, Z 0~600), 핵은 반지름 40 구(중심 (500, 0, 350))로 보고, 위 카메라 값으로 1920×1080 화면에 투영했다. 안전 영역은 세로 162~648px, 가로 0~1920px다. 필수 대상이 모두 이 영역 안에 있으면 통과로 본다.

가림 확인:

  • 필수 대상끼리 가리는 경우는 없다. 기본 화면에서 핵과 5명은 겹치지 않고, 강조 컷의 주인공과 핵 사이에 다른 인물이 끼지 않는다.
  • CAM_Default에서 D의 머리(507px)가 보스 발끝(508px)과 약 1px 겹친다. 보스 하체이므로 판독에는 영향이 없다.
  • 기본 화면의 핵은 39px로 작다. 노출 상태는 핵 크기만이 아니라 ⑤·②의 표시(아이콘·글자)로도 알린다(GDD 08장).
  • CAM_Boss에서 A·B가 보스 하체 앞에 겹친다. 핵과 보스 윗몸은 가리지 않는다.
  • 여유: 기본 화면에서 5명 머리 위부터 상단 UI까지 300px 이상 남아 이름표·아이콘을 둘 공간이 있다. 인물 사이 화면 틈은 A–B 61px, B–C 107px, C–D 129px, D–E 118px다. 가장 아래 인물(D)의 발끝은 하단 UI 경계에서 26px 위다.
  • 필수가 아닌 대상은 영역 밖으로 나간다. CAM_Party에서는 보스가 오른쪽 끝에 걸리고 핵이 상단 UI 영역에 있다. CAM_Act에서는 보스 머리가 상단 UI 영역에 걸린다. 모두 그 컷의 전달 목적과는 무관하다.

검토 한계:

  • 보스·핵은 ART-02의 실제 경계 상자로 계산했지만, 실제 윤곽은 상자보다 안쪽이라 화면에서는 이 표보다 조금 작게 보인다. Blender +X가 Unreal +X로 들어오는지는 ⑤의 임포트에서 확인해야 하므로, 외부 3D 생성 도구를 넣은 뒤 맵에서 다시 확인한다.
  • 16:9 외 화면비는 범위 밖이다(Q6).

채움광(SkyLight)그림자 쪽이 검게 뭉개지지 않을 만큼 밝게. 인물 얼굴(+X 방향)은 채움광으로 읽혀야 한다
하늘SkyAtmosphere는 쓰지 않는다(파란 하늘이 회색 배경 규칙과 어긋남). 배경은 회색 단색(안쪽을 보는 큰 구체나 높이 안개 색)으로 처리한다
노출자동 노출을 고정한다(최소·최대 EV100을 같은 값으로, 값은 맵에서 정함). 카메라가 바뀌어도 밝기가 출렁이지 않게 한다
그림자 확인보스 머리·팔의 그림자가 핵을 덮으면 해당 부분의 그림자 드리우기를 끄거나 ⑤와 핵 재질(자체 발광)로 해결한다. 맵에서 확인 항목으로 둔다
효과광보스 의도·연계를 색 조명으로 표현하지 않는다(릴레이 표현 보류, 색만으로 구분하지 않는 GDD 08장 원칙)

9. 블록아웃 재질 규칙

대상규칙
바닥 판무채색 중간 회색(선형 약 0.14, sRGB 약 #6A6A6A), 거칠기 0.9
전투 원판바닥보다 약간 밝은 회색(선형 약 0.22, sRGB 약 #818181). 선·칸·눈금 무늬를 넣지 않는다
먼 배경어두운 회색(선형 약 0.05, sRGB 약 #3F3F3F). 보스 윤곽이 배경과 구분되게 한다
보스 몸채도 없는 밝은 회색 계열로 바닥·배경과 명도 차이를 둔다(재질 제작은 ⑤ M2-2)
핵역할 색을 쓰지 않고 보스 몸과 명도·발광으로 구분한다. 노출 상태는 색만이 아니라 아이콘·표시로도 구분한다(GDD 08장, ⑤·②)
인물역할 색은 인물에만 쓴다(⑤ M2-2). 바닥·배경·보스·자리 표시에는 역할 색을 쓰지 않는다
자리 표시게임 화면에 자리 원·칸을 그리지 않는다. 격자 전투로 오해할 수 있기 때문이다. 배치 확인용 표시는 에디터에서만 보이게 둔다
격자 재질엔진의 격자 무늬 재질은 에디터 치수 확인에만 쓰고, 게임 화면에는 남기지 않는다
